# 分形递归工作流 Skill

## 原理

基于何恺明的 Fractal Generative Models (TMLR 2025)。

原始论文的核心思想：**一个原子生成模块通过递归调用自身来构建更大尺度的生成模型** ——
生成256×256图像时不是用单一大模型，而是用4级递归的分形架构，每级处理
不同粒度的子任务。全局patch(16×16)→局部patch(4×4)→像素→RGB通道。

在Hermes中，这意味着：**一个skill通过递归调用自身来处理不同粒度的子问题**，
而不是写一个扁平的步骤列表。

## 何时使用

| 场景 | 说明 |
|------|------|
| 树形目录分析 | 逐层深入子目录，每层调用相同的分析逻辑 |
| 嵌套数据结构 | JSON/YAML/XML 的逐层解析 |
| 批量文件处理 | 目录→子目录→文件的递归处理 |
| 多层级调研 | 问题→子问题→子子问题的递归分解 |
| 代码库分析 | 仓库→模块→文件→函数的逐层审查 |

## 工作流

### 基础模式

```
Level N: 处理当前粒度的问题
  → 如果可以再分解: 递归到 Level N-1 处理子问题
  → 如果不可再分解: 直接处理（原子操作）
  → 合并所有子结果返回
```

### 步骤

#### 1. 判断粒度
当前任务是否可以继续分解？判断标准：
- 存在独立的子目录/子模块
- 问题可拆分为不重叠的子问题
- 数据有嵌套结构

#### 2. 原子操作或分解
- **原子操作**: 对当前单元执行标准处理流程（读文件、搜索、分析）
- **分解**: 识别子单元，对每个子单元递归调用此skill

#### 3. 结果合成
收集所有子结果，按结构化格式合并返回。

## 使用方式

### 自动触发
当检测到"遍历"、"递归"、"逐层"、"所有子目录"等关键词时自动激活。

### 手动调用
```
/run fractal-recursive
目标: 分析 src/ 下的所有Python模块质量
最大深度: 3
```

## 示例

### 示例：递归代码库分析

```
目标: 分析 /opt/hermes/agent 下的Python文件

Level 1: agent/ 目录 → 发现3个子目录
  ├─ Level 2: agent/run_agent.py → 原子操作（分析单文件）
  ├─ Level 2: agent/prompt_builder.py → 原子操作
  └─ Level 2: agent/context_engine.py → 原子操作

合成: 合并3个文件的分析报告
```

### 示例：递归问题分解

```
目标: 研究Transformer效率优化方法

Level 1: 整体 → 分解为3个子问题
  ├─ Level 2: 架构改进 → 分解为Attention/FFN/位置编码
  ├─ Level 2: 训练优化 → 分解为蒸馏/量化/剪枝
  └─ Level 2: 推理加速 → 分解为KV缓存/并行解码/稀疏

合成: 按主题组织的研究报告
```
