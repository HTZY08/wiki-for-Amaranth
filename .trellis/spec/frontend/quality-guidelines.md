# Quality Guidelines

> Code and content quality standards for the wiki project.

---

## Overview

This project is a **content wiki** built with Starlight/Astro. Quality is measured primarily by content accuracy, consistency, and discoverability.

---

## Content Standards

### Frontmatter (Required)

Every `.md` content file MUST have valid YAML frontmatter:

```yaml
---
title: Page Title Here
description: Concise one-liner describing the page
---
```

- `title` is **required**
- `description` is **required** (used for search snippets)
- Additional frontmatter may be added per Starlight docs schema

### Writing Style

- **Chinese** (zh-cn) is the primary language
- Technical terms may use English where appropriate (e.g., "Hermes Agent", "Starlight")
- Keep each page focused on one topic
- Use `##` headings for sections, `###` for subsections
- Avoid extremely long pages — split into sub-pages when exceeding ~500 lines

### Links

- Use **relative links** for internal pages: `../../hermes/basic-config/`
- Use **full URLs** for external references
- All links must be valid (check before committing)

### Code Blocks

- Specify language tag on all fenced code blocks
- Shell commands use `bash` tag
- Config files use their format tag (e.g., `yaml`, `toml`, `json`)

---

## Code Quality (Astro/Starlight)

### astro.config.mjs

- All sidebar navigation is defined here — keep in sync with actual `src/content/docs/` structure
- New content categories must be added to `sidebar[]`

### custom.css

- Only Starlight CSS variable overrides — no global style leakage
- Use `@media (prefers-color-scheme: dark)` for dark mode
- Keep font stack consistent (Inter + Noto Sans SC + JetBrains Mono)

---

## Automation Standards

### Cron-Generated Content

Files under `ai-daily/` are auto-generated by the daily cron job:
- File naming: `YYYY-MM-DD.md`
- Content format defined in the cron job prompt
- Do NOT manually edit these files (changes will be overwritten)
- Always verify successful write before reporting completion

### Build Check

Always run before committing:
```bash
npm run build
```

The site must build without errors. Warnings are acceptable but should be tracked.

---

## Forbidden Patterns

1. **Broken links** — never commit with dead internal links
2. **Missing frontmatter** — every .md file needs title + description
3. **Uncommitted dist/ changes** — dist/ is gitignored, don't commit it
4. **Overwriting auto-generated files** — ai-daily/ files belong to the cron job
