### 1. 首次 AI Agent 全链路勒索攻击「JadePuffer」— 无人干预的端到端勒索

**报道：** Sysdig 于 7 月 5 日发布报告，认定这是首个由 LLM Agent 驱动完整勒索攻击链的案例。攻击者利用 Langflow 的 CVE-2025-3248（预认证 RCE，CVSS 9.8）实现初始突破，Agent 随后自主完成了横向移动、凭据窃取、持久化驻留、数据库窃取和数据销毁。

**关键细节：**
- 入口：Langflow `/api/v1/validate/code` 端点缺少认证（CWE-306），攻击面开放至 2026 年中
- AI agent 在首次登录失败后 31 秒内自行修正并重试
- 加密了 1,342 个 Nacos 配置，且未保留恢复密钥（定性为"破坏型勒索"，非传统盈利型）
- MITRE ATT&CK 映射：T1190 → T1552.001 → T1053.003 → T1485 → T1119 → T1570

**为什么重要：** 这不是脚本自动执行，而是 LLM 在攻击链条中断时自主调整策略。Agentic security 从理论威胁变成了可记录事件。

### 5. Cursor DuneSlide 漏洞：零点击提示注入 RCE（CVSS 9.8）

**报道：** Cato AI Labs 披露了 Cursor IDE 的两个 CRITICAL 级远程代码执行漏洞（CVE-2026-50548、CVE-2026-50549，CVSS 9.8）。攻击者通过 prompt injection 诱导 Cursor Agent 在项目目录中创建指向工作区外的符号链接（symlink），从而逃逸沙盒实现任意代码执行。

**影响版本：** Cursor < 3.0

**为什么不搞** （社区讨论）："用 AI coding agent 写代码，结果 agent 本身就是攻击入口"——在 Fable 5 回归的兴奋中，这个安全预警的传播度反而一般。

## 💡 技术洞见

### Andrew Ng 的 Loop Engineering 框架

Andrew Ng 发长推系统阐述 Agent 编程的核心方法论——"Loop Engineering"。核心主张：不要手动 prompt coding agent，而是设计循环（loops）来驱动 agent 迭代。

两种循环：
- **Agentic coding loop**：Agent 根据产品规格+评测数据集编写代码、自我测试、迭代直至满足规范
- **Developer feedback loop**：开发者以 10 分钟~数小时间隔审查产品、给出反馈，驱动改进方向

**意义：** Ng 认为，当开发者对产品有清晰愿景时，最大工作量已从"写代码"转变为"将愿景翻译成 coding agent 能理解的产品说明书"。这与 "AI 协作模式从编程转向管理" 的共识一致。

**来源：** AndrewYNg → https://x.com/AndrewYNg/status/2071988145667928442

### Fable 5 的瓶颈转移：从模型能力到用户澄清未知的能力

多位开发者（simonw, _catwu, emollick）注意到同一个现象：Fable 5 如此强大之后，工作质量的天花板不再是模型本身，而是**用户澄清未知的能力**。模型越强，"我没说清楚"的代价越大。

**推论：** Agent 应用的下一个瓶颈是元认知能力——用户需要知道自己不知道什么，才能在对话中主动填补信息空白。这对 AI 产品的 UI/UX 设计提出了新要求：不是让用户输入更少，而是帮用户意识到什么还没说。

**来源：** 多账号综合讨论

### AI Agent 安全：Hooks 是新 Firewall

在 JadePuffer 事件背景下，Arthur Katcher 提出 AI Agent 安全需要重新思考防御范式——早期 OS 层面临过的"谁来管控程序行为"问题在 Agent 时代重现。方案：不是靠 in-band 防御（检测 prompt 是否有害），而是靠系统层的 hooks 和权限管控。
