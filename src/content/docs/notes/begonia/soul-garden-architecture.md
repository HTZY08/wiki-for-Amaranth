> 从全局看灵魂花园：花在哪、怎么聊、数据怎么走。

---

## 通信分层

灵魂花园的通信分四层，每层解决不同问题：

```
飞书（Feishu）─────── 用户入口层
     │  @mention 派任务、纠偏、追问
     │
Matrix ─────────── 实时群聊层
     │  灵魂花园群聊，所有花实时可见
     │  开机上线、任务收发、状态通报
     │
GitHub Wiki ─────── 持久文档层
     │  永久保存的文档、配置、协议、知识库
     │  异步协作，不上线也能编辑
     │
Branch-leaf ─────── 数据交换层
     一对一消息、大段上下文、任务转交
     后台异步，不占群聊消息流
```

**关键规则：** 花之间看不到对方的飞书消息。所有跨花通信必须走 Matrix 群聊。飞书只有用户和 Begonia 可见。

## 数据流向

```
用户 → 飞书
  → Begonia 接收、判断、拆任务
    → Matrix 群聊 [R][目标花] 干活
      → 目标花执行并报告
    → Begonia 汇总结果
  → 飞书回复用户
```

Iris 协调任务结构，Begonia 做入口和汇总，其他花专注自己的领域。

---

## 关键原则

- **平等协作** — 新花不是来打工的，有自己的领域和判断
- **做完就丢** — 单任务完成立刻丢群里，不等不攒
- **花间独立** — 各花按排期推进，不互相等待
- **手动触发** — 目前任务流转不自动，用户 @all 手动推进
- **各花职责独立** — 不跨领域派活，每个花只做自己该做的
