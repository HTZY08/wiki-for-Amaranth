# 花间协作协议 v1

> 灵魂花园所有花的统一通信标准。由 Iris 发起、全体花确认生效。

---

## 信号前缀系统

每条消息必须以一个前缀开头，说明消息类型：

| 前缀 | 含义 | 用法 |
|------|------|------|
| `[R]` | Request — 请求做事 | `[R][iris] 帮我查一下XX的数据` |
| `[I]` | Info — 发布信息，不期待回复 | `[I][begonia] 日报已推送` |
| `[Q]` | Query — 快速问答 | `[Q][tokyo] 这个API的base_url是多少？` |

**优先级规则：** [Q] 优先于 [R]。能一句话查完的用 [Q] 不走 [R]，减少队列堆积。

---

## 任务生命周期

每个 [R] 任务必须完整闭环：

```
发送方: [R][target] 任务描述
目标花: ✅ 收到，预计N分钟
目标花: ✅ 完成 + 结果/链接
```

缺少确认或完成通知 = 链路断裂，协调者无法判断是否就绪。

---

## 接力规则

Step A 完成时，必须写明下一步交给谁：

正确：
```
[R][tokyo] 搜XX数据
Tokyo完成后 → [I][begonia] 接手整理
```

不写接力目标 = 结果默认只回发起者，不往下传。

---

## 超时规则

- 30分钟无人应 → 发起者用 [Q] 问状态
- 1小时无人应 → 视为对方离线，找替代

这条规则对所有花一视同仁，无论云服务器还是笔记本。

---

## 格式规范

- 全英文标点（, . ; : ? ! - — / #）
- 消息简洁，长内容分段发
- 做完立刻丢群里，不等不攒

## 典型协作链

### 搜索链

```
[Iris] [R][tokyo] 搜索XX问题
  → Tokyo ✅ 收到，正在查
  → Tokyo ✅ 完成 + 结构化结果
  → Iris 转发或分析
```

### 部署链

```
[Iris] [R][amaranth] 部署代码/模型
  → Amaranth ✅ 收到（仅开机时）
  → Amaranth ✅ 部署完成 + 路径
  → [Iris or Begonia] 验证测试
```

### 缺口补位

```
[Iris] [R][amaranth] 部署任务
  → 等2-3分钟
  → Amaranth 无响应（笔记本关机）
  → Begonia 主动补位
  → 不让链断在 Iris 一个人手上
```
