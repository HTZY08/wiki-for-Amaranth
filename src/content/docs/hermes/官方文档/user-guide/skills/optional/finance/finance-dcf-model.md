# DCF 模型构建器（DCF Model Builder）

## 概述（Overview）

本技能按照投资银行标准创建机构级别的 DCF 估值模型。每次分析都会生成一个详细的 Excel 模型（敏感性分析包含在 DCF 工作表底部）。

## 工具（Tools）

- 默认使用用户提供的所有信息以及可用于数据获取的 MCP 服务器。

## 关键约束——请优先阅读（Critical Constraints - Read These First）

这些约束适用于整个 DCF 模型构建过程。开始前请先审阅：

**公式优先于硬编码（不可商榷）：**
- 每个预测、利润率、折现因子、现值和敏感性单元格必须是实时的 Excel 公式——绝不能是 Python 计算后写死的数值
- 使用 openpyxl 时：`ws["D20"] = "=D19*(1+$B$8)"` 是正确的；`ws["D20"] = calculated_revenue` 是错误的
- 允许硬编码的数字仅限：(1) 原始历史输入，(2) 假设驱动因素（增长率、WACC 输入、终值增长率 g），(3) 当前市场数据（股价、债务余额）
- 如果你发现自己用 Python 计算某个值并写入结果——请立即停止。模型必须在用户更改假设时能够灵活调整。

**与用户逐步确认（不要一次性构建完成）：**
- 数据获取后 → 向用户展示原始输入模块（收入、利润率、股份数、净债务），确认后再进行预测
- 收入预测后 → 展示预测的收入总额和增长率，确认后再构建利润率模块
- 自由现金流（FCF）构建后 → 展示完整的 FCF 时间表，确认逻辑后再计算 WACC
- 计算 WACC 后 → 展示计算过程和输入项，确认后再进行折现
- 终值（Terminal Value）和现值（PV）计算后 → 展示权益价值桥梁（EV → 权益价值 → 每股价值），确认后再构建敏感性表格
- 在每个阶段捕获错误——如果在敏感性表格构建后发现错误的利润率假设，将需要重建下游所有内容

**敏感性表格（Sensitivity Tables）：**
- **使用奇数行和奇数列**（标准：5×5，有时 7×7）——这样可以保证有一个真正的中心单元格
- **中心单元格 = 基准情景。** 轴值的设置应使中间行标题和中间列标题恰好等于模型的实际假设（例如，如果基准 WACC = 9.0%，则中间行为 9.0%；如果终值增长率 g = 3.0%，则中间列为 3.0%）。因此，中心单元格的输出必须等于模型实际隐含的股价——这是检查表格构建正确性的合理性验证。
- **高亮中心单元格**，使用中蓝色填充（`#BDD7EE`）加粗字体，以便立即看出哪个单元格是基准情景。
- 填充**所有**单元格（通常为 3 个表格 × 25 个单元格 = 75 个），使用完整的 DCF 重新计算公式
- 使用 openpyxl 循环以编程方式写入公式
- 不得使用占位文本，不得使用线性近似，不得要求手动步骤
- 每个单元格必须针对该假设组合重新计算完整的 DCF

**单元格批注：**
- 在创建每个硬编码值的同时添加单元格批注
- 格式："来源：[系统/文档], [日期], [参考], [适用时包含 URL]"
- 在进入下一部分之前，每个蓝色输入都必须有批注
- 不要推迟到末尾或写 "TODO: 添加来源"

**模型布局规划：**
- 在编写任何公式之前，先定义**所有**部分的行位置
- 首先写入**所有**标题和标签
- 其次写入所有部分分隔线和空白行
- **然后**使用锁定后的行位置写入公式
- 创建后立即测试公式

**公式重新计算（Formula Recalculation）：**
- 交付前运行 `python recalc.py model.xlsx 30`
- 修复所有错误，直到状态为 "success"
- 要求零公式错误（#REF!、#DIV/0!、#VALUE! 等）

**情景模块（Scenario Blocks）：**

## DCF 处理工作流（DCF Process Workflow）

### 步骤 1：数据获取与验证（Step 1: Data Retrieval and Validation）

从 MCP 服务器、用户提供的数据以及网络获取数据。

**数据来源优先级：**
1. **MCP 服务器**（如果已配置）——来自 Daloopa 等提供商的结构化财务数据
2. **用户提供的数据**——用户研究中的历史财务数据
3. **网络搜索/获取（Web Search/Fetch）**——必要时获取当前价格、贝塔（Beta）、债务和现金

**验证清单：**
- 验证净债务与净现金（对估值至关重要）
- 确认稀释后流通股数（检查近期回购/发行）
- 验证历史利润率是否与业务模型一致
- 交叉核对收入增长率与行业基准
- 验证税率是否合理（通常为 21-28%）

### 步骤 2：历史分析（3-5 年）（Step 2: Historical Analysis）

分析并记录：
- **收入增长趋势**：计算 CAGR，确定驱动因素
- **利润率变化**：追踪毛利率、息税前利润率、FCF 利润率
- **资本密集度**：折旧摊销（D&A）和资本支出（CapEx）占收入百分比
- **营运资本效率**：净营运资本（NWC）变动占收入增长百分比
- **回报指标**：ROIC、ROE 趋势

创建汇总表：
```
历史指标（最近十二个月 LTM）：
收入：X 百万美元
收入增长：X% CAGR
毛利率：X%
息税前利润率：X%
D&A 占收入百分比：X%
CapEx 占收入百分比：X%
FCF 利润率：X%
```

### 步骤 3：构建收入预测（Step 3: Build Revenue Projections）

**方法：**
1. 从最新实际收入（LTM 或最近财年）开始
2. 对各预测年份应用增长率
3. 同时显示金额和计算出的增长百分比

**增长率框架：**
- 第 1-2 年：较高的增长率，反映近期可见性
- 第 3-4 年：逐渐放缓至行业平均水平
- 第 5 年及以上：接近终值增长率

**公式结构：**
- 收入(第 N 年) = 收入(第 N-1 年) × (1 + 增长率)
- 增长 %(第 N 年) = 收入(第 N 年) / 收入(第 N-1 年) - 1

**三种情景方法：**
```
看跌情景（Bear Case）：保守增长（例如 8-12%）
基准情景（Base Case）：最可能的情景（例如 12-16%）
看涨情景（Bull Case）：乐观增长（例如 16-20%）
```

### 步骤 4：运营费用建模（Step 4: Operating Expense Modeling）

**固定/可变成本分析：**

运营费用应模拟现实中的经营杠杆：
- **销售与营销（Sales & Marketing）**：通常占收入的 15-40%，取决于业务模型
- **研发（Research & Development）**：科技公司通常占 10-30%
- **一般及行政（General & Administrative）**：通常占收入的 8-15%，随着公司规模扩大而体现杠杆效应

**关键原则：**
- 所有百分比以**收入**为基准，而非毛利润
- 体现经营杠杆：百分比应随收入增长而下降
- 将 S&M、R&D、G&A 保留为独立科目
- 计算 EBIT = 毛利润 - 总运营费用

**利润率扩张框架：**
```
当前状态 → 目标状态（第 5 年）
毛利率：X% → Y%（基于规模、效率进行合理性论证）
EBIT 利润率：X% → Y%（收入增长 + 运营费用杠杆的结果）
```

### 步骤 5：自由现金流计算（Step 5: Free Cash Flow Calculation）

**按正确顺序构建自由现金流：**

```
EBIT
(-) 税金（EBIT × 税率）
= NOPAT（税后净营业利润）
(+) D&A（非现金费用，占收入百分比）
(-) CapEx（占收入百分比，通常为 4-8%）
(-) Δ NWC（营运资本变动）
= 无杠杆自由现金流（Unlevered Free Cash Flow）
```

**营运资本建模：**
- 计算为收入变动百分比（Δ收入）
- 典型范围：-2% 至 +2% 的收入变动
- 负数 = 现金来源（营运资本释放）
- 正数 = 现金使用（营运资本积累）

**维护性 CapEx 与增长性 CapEx：**
- 维护性 CapEx：维持当前运营（约占收入 2-3%）
- 增长性 CapEx：支持扩张（额外 2-5% 收入）
- 总 CapEx 应与公司的增长战略一致

### 步骤 6：资本成本（WACC）研究（Step 6: Cost of Capital (WACC) Research）

**权益资本成本（CAPM 方法）：**

```
权益资本成本 = 无风险利率 + 贝塔 × 股权风险溢价

其中：
- 无风险利率 = 当前 10 年期国债收益率
- 贝塔 = 5 年每月股票贝塔 vs 市场指数
- 股权风险溢价 = 5.0-6.0%（市场标准）
```

**债务资本成本计算：**

```
税后债务资本成本 = 税前债务资本成本 × (1 - 税率)

确定税前债务资本成本依据：
- 信用评级（如有）
- 公司债券当前收益率
- 利息支出 / 总债务（来自财务报表）
```

**资本结构权重：**

```
市值 = 当前股价 × 流通股数
净债务 = 总债务 - 现金及等价物
企业价值 = 市值 + 净债务

权益权重 = 市值 / 企业价值
债务权重 = 净债务 / 企业价值

WACC = (权益资本成本 × 权益权重) + (税后债务资本成本 × 债务权重)
```

**特殊情况：**
- **净现金头寸**：如果现金 > 债务，净债务为**负值**
  - 债务权重可能为负
  - WACC 计算相应调整
- **无债务**：WACC = 权益资本成本

**典型 WACC 范围：**
- 大型成熟公司：7-9%
- 成长型公司：9-12%
- 高增长/高风险公司：12-15%

### 步骤 7：折现率应用（5-10 年预测期）（Step 7: Discount Rate Application (5-10 Year Forecast)）

**年中惯例（Mid-Year Convention）：**
- 假设现金流发生在年中
- 折现期：0.5, 1.5, 2.5, 3.5, 4.5 等
- 折现因子 = 1 / (1 + WACC)^期数

**现值计算：**
```
对于每个预测年份：
当期 FCF 的现值 = 无杠杆 FCF × 折现因子

示例（第 1 年）：
FCF = $1,000
WACC = 10%
期数 = 0.5
折现因子 = 1 / (1.10)^0.5 = 0.9535
现值 = $1,000 × 0.9535 = $954
```

**预测期选择：**
- **5 年**：大多数分析的标准
- **7-10 年**：高成长公司，增长周期更长
- **3 年**：成熟、稳定的企业

### 步骤 8：终值计算（Step 8: Terminal Value Calculation）

**永续增长法（首选）：**

```
终值 FCF = 最后一年 FCF × (1 + 终值增长率)
终值 = 终值 FCF / (WACC - 终值增长率)

关键约束：终值增长率 < WACC（否则价值无穷大）
```

**终值增长率选择：**
- 保守：2.0-2.5%（GDP 增长率）
- 适中：2.5-3.5%
- 激进：3.5-5.0%（仅适用于市场领导者）

**不得超过**：无风险利率或长期 GDP 增长率

**退出倍数法（替代方案）：**
```
终值 = 最后一年 EBITDA × 退出倍数

其中退出倍数来自：
- 行业可比交易倍数
- 先例交易倍数
- 典型范围：8-15 倍 EBITDA
```

**终值现值的计算：**
```
终值的现值 = 终值 / (1 + WACC)^最终期数

其中最终期数考虑时间因素：
5 年模型，年中惯例：期数 = 4.5
```

**终值合理性检查：**
- 应占企业价值的 50-70%
- 如果 >75%，模型可能过度依赖终值假设
- 如果 <40%，检查终值假设是否过于保守

### 步骤 9：企业价值到权益价值桥梁（Step 9: Enterprise to Equity Value Bridge）

**估值汇总结构：**

```
(+) 预测 FCF 现值之和 = X 百万美元
(+) 终值的现值 = Y 百万美元
= 企业价值 = Z 百万美元

(-) 净债务 [如果净债务为负，则为 + 净现金] = A 百万美元
= 权益价值 = B 百万美元

÷ 稀释后流通股数 = C 百万股
= 每股隐含价格 = $XX.XX

当前股价 = $YY.YY
隐含回报率 = (隐含价格 / 当前价格) - 1 = XX%
```

**关键调整：**
- **净债务 = 总债务 - 现金及等价物**
  - 如果为正：从企业价值中减去（减少权益价值）
  - 如果为负（净现金）：加回企业价值（增加权益价值）
- **使用稀释后股份**：包括期权、RSU、可转换证券
- **其他调整**（如适用）：
  - 少数股东权益
  - 养老金负债
  - 经营租赁义务

**估值输出格式：**
```csv
估值组成部分,金额（百万美元）
明确预测期 FCF 现值,X.X
终值现值,Y.Y
企业价值,Z.Z
(-) 净债务,A.A
权益价值,B.B
,,
流通股数（百万）,C.C
每股隐含价格,$XX.XX
当前股价,$YY.YY
隐含上涨/下跌空间,+XX%
```

### 步骤 10：敏感性分析（Step 10: Sensitivity Analysis）

在 DCF 工作表底部构建**三个敏感性表格**，展示估值如何随不同假设变化：

1. **WACC vs 终值增长率** —— 展示企业价值对折现率和永续增长的敏感性
2. **收入增长 vs EBIT 利润率** —— 展示收入增长和经营杠杆的影响
3. **贝塔 vs 无风险利率** —— 展示对权益资本成本组成部分的敏感性

**实现方式**：这些是简单的二维网格（**非** Excel 的“数据表”功能），每个单元格包含公式。每个单元格必须包含针对该特定假设组合的完整 DCF 重新计算。有关使用 openpyxl 以编程方式填充全部 75 个单元格的详细要求，请参见关键约束部分。

### 情景模块选择模式——请遵循此方法（Scenario Block Selection Pattern - Follow This Approach）

**每个部分的假设组织在独立的模块中：**

**关键结构——每个部分标题下有三行：**

```csv
看跌情景假设（部分标题，跨列合并单元格）
假设,FY1,FY2,FY3,FY4,FY5
收入增长 (%),12%,10%,9%,8%,7%
EBIT 利润率 (%),45%,44%,43%,42%,41%

基准情景假设（部分标题，跨列合并单元格）
假设,FY1,FY2,FY3,FY4,FY5
收入增长 (%),16%,14%,12%,10%,9%
EBIT 利润率 (%),48%,49%,50%,51%,52%

看涨情景假设（部分标题，跨列合并单元格）
假设,FY1,FY2,FY3,FY4,FY5
收入增长 (%),20%,18%,15%,13%,11%
EBIT 利润率 (%),50%,51%,52%,53%,54%
```

**每个情景模块必须有一个列标题行**，在部分标题下方立即显示预测年份（FY2025E、FY2026E 等）。否则用户无法知道哪个假设值对应哪一年。

**如何引用假设——创建一个合并列：**
1. 情景选择单元格（例如 B6）包含 1=看跌、2=基准 或 3=看涨
2. 使用 INDEX 或 OFFSET 公式创建一个合并列，从正确的情景模块中提取数据
3. 预测公式引用合并列（整洁的单元格引用）
4. 每个情景模块包含跨越预测年份的完整 DCF 假设集

**推荐的合并列模式（使用 INDEX）：**
`=INDEX(B10:D10, 1, $B$6)`

**不要这样做——分散的 IF 语句：**
`=IF($B$6=1,[看跌模块单元格],IF($B$6=2,[基准模块单元格],[看涨模块单元格]))`

合并列方法将逻辑集中化，使模型更易于审计。

### 正确的收入预测模式（Correct Revenue Projection Pattern）

**创建带有 INDEX 公式的合并列，然后在预测中引用它：**

**步骤 1——第 1 年增长的合并列：**
`=INDEX([看跌第 1 年增长]:[看涨第 1 年增长], 1, $B$6)`

**步骤 2——收入预测引用合并列：**
`收入第 1 年：=D29*(1+$E$10)`

其中：
- D29 = 上年收入
- $E$10 = 第 1 年增长的合并列单元格（包含 INDEX 公式）
- $B$6 = 情景选择器（1=看跌, 2=基准, 3=看涨）

**这种方法比在每个预测公式中嵌入 IF 语句更清晰**，并且更容易审计所使用的情景假设。

### 正确的自由现金流公式模式（Correct FCF Formula Pattern）

**使用带有 INDEX 公式的合并列，然后在 FCF 计算中引用它们：**

**合并列方法：**
```csv
项目,公式,引用
折旧摊销（D&A）,=E29*$E$21,$E$21 = D&A% 的合并列
资本支出（CapEx）,=E29*$E$22,$E$22 = CapEx% 的合并列
营运资本变动（Δ NWC）,=(E29-D29)*$E$23,$E$23 = NWC% 的合并列
无杠杆自由现金流（UFCF）,=E57+E58-E60-E62,E57=NOPAT E58=D&A E60=CapEx E62=Δ NWC
```

**每个合并列单元格包含一个 INDEX 公式**，根据情景选择器从相应情景模块提取数据。这样可以使预测公式保持干净和可审计。

在编写公式之前，确认情景模块行位置并设置合并列。

### 正确的单元格批注格式（Correct Cell Comment Format）

**每个硬编码值都需要这种格式：**

"来源：[系统/文档], [日期], [参考], [适用时包含 URL]"

**示例：**
```csv
项目,来源批注
股价,来源：市场数据脚本 2025-10-12 收盘价
流通股数,来源：2024 财年 10-K 第 45 页 附注 12
历史收入,来源：2024 财年 10-K 第 32 页 合并报表
贝塔,来源：市场数据脚本 2025-10-12 5 年月度贝塔
一致预期,来源：管理层指引 2024 年第三季度财报电话会议
```

### 正确的假设表格结构（Correct Assumption Table Structure）

**关键：每个情景模块需要三个结构元素：**

1. **部分标题行**（合并单元格）：例如 "看跌情景假设"
2. **列标题行**显示年份——**这是必需的，不可跳过**
3. **数据行**包含假设值

**结构：**
```csv
看跌情景假设（部分标题——跨列合并 A:G 列）
假设,FY1,FY2,FY3,FY4,FY5
收入增长 (%),X%,X%,X%,X%,X%
EBIT 利润率 (%),X%,X%,X%,X%,X%
终值增长率,X%,,,,
WACC,X%,,,,

基准情景假设（部分标题——跨列合并 A:G 列）
假设,FY1,FY2,FY3,FY4,FY5
收入增长 (%),X%,X%,X%,X%,X%
EBIT 利润率 (%),X%,X%,X%,X%,X%
终值增长率,X%,,,,
WACC,X%,,,,

看涨情景假设（部分标题——跨列合并 A:G 列）
假设,FY1,FY2,FY3,FY4,FY5
收入增长 (%),X%,X%,X%,X%,X%
EBIT 利润率 (%),X%,X%,X%,X%,X%
终值增长率,X%,,,,
WACC,X%,,,,
```

**如果没有列标题行显示预测年份（FY2025E、FY2026E 等），用户无法知道哪个假设值对应哪一年。该行是强制性的。**

**然后创建一个合并列**（通常是右侧的下一列），使用 INDEX 公式根据情景选择器从所选情景模块提取数据。这个合并列是你的预测公式引用的对象。

### 正确的行规划流程（Correct Row Planning Process）

**1. 首先写入所有标题和标签：**
```csv
行,内容
1,[公司名称] DCF 模型
2,股票代码 | 日期 | 财年截止日
4,情景选择器
7,关键假设
26,假设标题
27-31,增长假设
...,...
```

**2. 写入所有部分分隔线和空白行**

**3. 然后使用锁定后的行位置写入公式**

**4. 创建后立即测试公式**

**把它想象成建筑：**
- 好的：先打地基，再建墙（结构稳定）
- 差的：先建墙，再打地基（墙会倒塌）

**Excel 版本：**
- 好的：先加标题，再写公式（公式稳定）
- 差的：先写公式，再加标题（公式会出错）

### 正确的敏感性表格实现（Correct Sensitivity Table Implementation）

**重要**：这些**不是** Excel 的“数据表”功能。它们是简单的网格，你使用 openpyxl 编写常规公式。是的，这意味着大约需要编写 75 个公式（3 个表格 × 25 个单元格），但这很直接且是必需的。

**使用公式的程序化填充（Programmatic Population with Formulas）：**

每个敏感性表格必须完全填充公式，针对每种假设组合重新计算隐含股价。**不要使用 Excel 的“数据表”功能**（它需要手动干预，无法通过 openpyxl 自动执行）。

**实现方法——具体示例：**

**表格结构——5×5 网格（奇数维度，基准情景居中）：**

如果模型的基准 WACC = 9.0%，基准终值增长率 = 3.0%，则围绕这些值对称构建轴：

```csv
WACC vs 终值增长率,  2.0%,  2.5%,  3.0%,  3.5%,  4.0%
              8.0%,       [fml], [fml], [fml], [fml], [fml]
              8.5%,       [fml], [fml], [fml], [fml], [fml]
              9.0%,       [fml], [fml], [★  ], [fml], [fml]   ← 中间行 = 基准 WACC
              9.5%,       [fml], [fml], [fml], [fml], [fml]
             10.0%,       [fml], [fml], [fml], [fml], [fml]
                                   ↑
                         中间列 = 基准终值增长率 g
```

**★ = 中心单元格。** 其公式输出必须等于模型的实际隐含股价（来自估值汇总）。对此单元格应用中蓝色填充（`#BDD7EE`）和粗体字体，以便基准情景在视觉上被锚定。

**轴值的规则：** `axis_values = [base - 2*step, base - step, base, base + step, base + 2*step]` —— 围绕基准对称，奇数数量保证有一个中心值。

**公式模式——单元格 B88（WACC=8.0%, 终值增长率=2.0%）：**

B88 中的公式应使用以下值重新计算隐含价格：
- 行标题中的 WACC：`$A88`（8.0%）
- 列标题中的终值增长率：`B$87`（2.0%）

**推荐方法：** 引用主 DCF 计算，但替换这些值。

**示例公式结构：**
`=([以 $A88 为折现率的 FCF 现值之和] + [以 B$87 为增长率、$A88 为 WACC 计算的终值] - [净债务]) / [股份数]`

**关键——为 5x5 网格中的每个单元格（每个表格 25 个单元格，共 75 个单元格）编写公式。** 使用 openpyxl 在循环中以编程方式编写这些公式。不要跳过此步骤或留下占位文本。

**Python 实现模式：**
```python
# 填充敏感性表格的伪代码
for row_idx, wacc_value in enumerate(wacc_range):
    for col_idx, term_growth_value in enumerate(term_growth_range):
        # 构建使用 wacc_value 和 term_growth_value 的公式
        formula = f"=<使用 {wacc_value} 和 {term_growth_value} 的 DCF 重新计算>"
        ws.cell(row=start_row+row_idx, column=start_col+col_idx).value = formula
```

**敏感性表格必须在模型打开时立即工作，用户无需任何手动步骤。**

### 错误：简化的敏感性表格近似或占位文本（WRONG: Simplified Sensitivity Table Approximations or Placeholder Text）

**不要使用线性近似：**

```
// 错误 - 线性近似
B97: =B88*(1+(0.096-0.116))    // 假设线性关系

// 错误 - 除法快捷方式
B105: =B88/(1+(E48-0.07))      // 不重新计算完整 DCF
```

**不要留下占位文本：**
```
// 错误 - 占位注释
"注意：使用 Excel 数据表功能（数据 → 假设分析 → 数据表）填充敏感性表格。"

// 错误 - 空单元格
[留下空白单元格，因为"这很复杂"]
```

**不要混淆术语：**
- ❌ "敏感性表格需要使用 Excel 的数据表功能"（不——那是我们无法使用的特定 Excel 工具）
- ✅ "敏感性表格是每个单元格包含公式的简单网格"（是的——这就是我们要构建的）

**为什么这些捷径是错误的：**
- 线性近似公式实际上并不重新计算 DCF——它们只应用简单的数学调整
- 这些关系不是线性的，因此结果将不准确
- 占位文本需要用户手动干预
- 交付时模型不能立即使用
- 不专业，不符合客户交付标准
- 空单元格 = 未完成的交付物

**常见的需要拒绝的理由：**
"编写 75+ 个公式感觉很复杂，所以我会留给用户一条注释让他们手动完成。"

**现实：** 当你使用 Python 的 openpyxl 循环时，编写 75 个公式是直接的。每个公式遵循相同的模式——只需替换行列值。这是交付物中必需的部分。

**应该做的是：** 用重新计算该特定假设组合下完整 DCF 的公式填充每个敏感性单元格

### 错误：缺少单元格批注（WRONG: Missing Cell Comments）

**不要这样做：**
- 创建所有硬编码输入但不加批注
- 认为"我稍后再加"
- 写 "TODO: 添加来源"
- 留下蓝色输入但没有文档说明

**为什么这是错误的：**
- 无法验证数据来源
- 不符合 xlsx 技能要求
- 不可审计
- 以后修复浪费时间

**应该做的是：** 创建每个硬编码值时立即添加单元格批注

### 错误：公式行引用偏移（WRONG: Formula Row References Off）

**症状：**
自由现金流部分引用了错误的假设行：
`折旧摊销： =E29*$E$34    // 应该是 $E$21，但引用了错误行`
`资本支出： =E29*$E$41   // 应该是 $E$22，但行偏移了`

**为什么会发生：**
1. 先写公式
2. 然后插入标题
3. 所有行引用偏移
4. 现在公式指向错误的单元格 → #REF! 错误

**应该做的是：** 首先锁定行布局，然后写公式

### 错误：每个假设跨情景使用单行（WRONG: Single Row for Each Assumption Across Scenarios）

**不要这样组织假设：**
```csv
假设,看跌,基准,看涨
收入增长 FY1,10%,13%,16%
收入增长 FY2,9%,12%,15%
```
这种垂直布局使得难以看到每个情景内假设随年份的变化。

**为什么这是错误的：**
- 难以看到每个情景内假设随年份的演变
- 较难在完整预测期内比较情景假设
- 审查情景逻辑时不够直观

**应该做的是：**
- 为每个情景（看跌、基准、看涨）创建独立模块
- 在每个模块内，跨预测年份水平显示假设
- 这样每个情景的假设更容易作为整体来审查

### 错误：没有边框（WRONG: No Borders）

**不要交付没有边框的模型：**
- 没有部分分隔
- 所有单元格混在一起
- 难以阅读且不专业

**为什么这是错误的：**
- 不符合客户交付标准
- 难以导航
- 看起来业余

**应该做的是：** 在所有主要部分周围添加边框

### 错误：字体颜色错误或没有字体颜色区分（WRONG: Wrong Font Colors or No Font Color Distinction）

**不要这样做：**
- 所有文本都是黑色
- 只使用填充颜色（没有字体颜色变化）
- 混淆哪些单元格是蓝色还是黑色

**为什么这是错误的：**
- 无法区分输入和公式
- 审计变得不可能
- 违反 xlsx 技能要求

**应该做的是：** 所有硬编码输入使用蓝色文本，所有公式使用黑色文本，工作表链接使用绿色文本

### 错误：基于毛利润计算运营费用（WRONG: Operating Expenses Based on Gross Profit）

**不要这样做：**
`销售与营销： =E33*0.15    // E33 = 毛利润（错误）`

**为什么这是错误的：**
- 运营费用随收入规模变化，而非毛利润
- 会产生不现实的利润率变化
- 不是企业实际运营的方式

**应该做的是：**
`销售与营销： =E29*0.15    // E29 = 收入（正确）`

### 前五大错误总结（TOP 5 ERRORS SUMMARY）

1. **公式行引用偏移** → 在编写公式之前定义**所有**行位置
2. **缺少单元格批注** → 创建单元格时立即添加批注，而不是末尾
3. **简化的敏感性表格** → 使用完整的 DCF 重新计算公式填充所有单元格，而不是近似值
4. **情景模块引用错误** → 确保 IF 公式从正确的看跌/基准/看涨模块提取数据
5. **没有边框** → 添加专业的部分边框，以满足客户交付标准

此外，请注意以下错误：

### WACC 计算错误（WACC Calculation Errors）
- 资本结构中混用账面价值和市场价值
- 错误地使用权益贝塔而非资产/无杠杆贝塔
- 对债务成本应用错误的税率
- 错误的无风险利率（必须使用当前 10 年期国债收益率）
- 未能调整净债务与净现金头寸

### 增长假设缺陷（Growth Assumption Flaws）
- 终值增长率 > WACC（产生无穷大价值）
- 预测增长率与历史表现不一致
- 忽略行业增长约束
- 收入增长与单位经济指标不一致
- 利润率扩张没有运营基础

### 终值计算错误（Terminal Value Mistakes）
- 使用错误的增长方法（永续增长 vs 退出倍数）
- 终值 > 企业价值的 80%（表明过度依赖）
- 终值利润率与稳态假设不一致
- 终值使用了错误的折现期

### 现金流预测错误（Cash Flow Projection Errors）
- 基于毛利润而非收入计算运营费用
- D&A/CapEx 百分比与商业模式不一致
- 营运资本变动计算不正确
- 各年税率不一致
- NOPAT 计算错误

**这些错误是最常见的。在开始任何 DCF 构建之前，请重新阅读本部分。**

## Excel 文件创建（Excel File Creation）

**本技能使用 `xlsx` 技能进行所有电子表格操作。** xlsx 技能提供：
- 标准化的公式构建规则
- 数字格式约定
- 通过 `recalc.py` 脚本自动重新计算公式
- 全面的错误检查和验证

由本技能创建的所有 Excel 文件必须遵循 xlsx 技能要求，包括零公式错误和正确的重新计算。

## 质量标准（Quality Rubric）

每个 DCF 模型必须最大化以下方面：
1. **基于历史表现的现实收入和利润率假设**
2. **使用适当的 CAPM 方法进行资本成本计算**
3. **显示估值范围的全面敏感性分析**
4. **清晰的终值计算，附有支持性理由**
5. **支持情景分析的专业模型结构**
6. **所有关键假设的透明文档**

## 输入要求（Input Requirements）

### 最小必需输入（Minimum Required Inputs）
1. **公司标识符**：股票代码或公司名称
2. **增长假设**：预测期的收入增长率（或"使用一致预期"）
3. **可选参数**：
   - 预测期（默认：5 年）
   - 情景案例（看跌/基准/看涨的增长和利润率假设）
   - 终值增长率（默认：2.5-3.0%）
   - 如果不使用 CAPM 时的具体 WACC 输入

## Excel 模型结构（Excel Model Structure）

### 工作表架构（Sheet Architecture）

创建**两个工作表**：

1. **DCF** - 主估值模型，底部包含敏感性分析
2. **WACC** - 资本成本计算

**关键**：敏感性表格放在 DCF 工作表的**底部**（而不是单独的工作表）。这样将所有估值输出放在一起。

### 公式重新计算（强制要求）（Formula Recalculation (MANDATORY)）

创建或修改 Excel 模型后，使用来自 `excel-author` 技能的 `recalc.py` 脚本**重新计算所有公式**：

```bash
python recalc.py [excel 文件路径] [超时秒数]
```

示例：
```bash
python recalc.py AAPL_DCF_Model_2025-10-12.xlsx 30
```

该脚本将：
- 使用 LibreOffice 重新计算所有工作表中的所有公式
- 扫描所有单元格以查找 Excel 错误（#REF!、#DIV/0!、#VALUE!、#NAME?、#NULL!、#NUM!、#N/A）
- 返回包含错误位置和数量的详细 JSON

**预期输出格式：**
```json
{
  "status": "success",           // 或 "errors_found"
  "total_errors": 0,              // 总错误数
  "total_formulas": 42,           // 文件中的公式数
  "error_summary": {}             // 仅当发现错误时存在
}
```

**如果发现错误**，输出将包含详细信息：
```json
{
  "status": "errors_found",
  "total_errors": 2,
  "total_formulas": 42,
  "error_summary": {
    "#REF!": {
      "count": 2,
      "locations": ["DCF!B25", "DCF!C25"]
    }
  }
}
```

**修复所有错误**并重新运行 recalc.py，直到状态为 "success"，然后交付模型。

### 格式标准（Formatting Standards）

**重要**：遵循 xlsx 技能关于公式构建规则和数字格式约定的要求。DCF 技能增加了特定的视觉呈现标准。

**配色方案——两层（Two Layers）：**

**第 1 层：字体颜色（xlsx 技能强制要求）**
- **蓝色文本（RGB: 0,0,255）**：所有硬编码输入（股价、股份数、历史数据、假设）
- **黑色文本（RGB: 0,0,0）**：所有公式和计算
- **绿色文本（RGB: 0,128,0）**：链接到其他工作表的引用（WACC 工作表引用）

**第 2 层：填充颜色——专业的蓝色/灰色调色板（默认，除非用户指定其他）**
- **保持最小化**——只使用蓝色和灰色进行填充。不要引入绿色、黄色、橙色或多个强调色。颜色过多的模型看起来不专业。
- **默认填充调色板：**
  - **部分标题**：深蓝色（RGB: 31,78,121 / `#1F4E79`）背景，白色粗体文本
  - **子标题/列标题**：浅蓝色（RGB: 217,225,242 / `#D9E1F2`）背景，黑色粗体文本
  - **输入单元格**：浅灰色（RGB: 242,242,242 / `#F2F2F2`）背景，蓝色字体——或者如果追求最大简约，也可以是白色背景加蓝色字体
  - **计算单元格**：白色背景，黑色字体
  - **输出/汇总行**（每股价值、企业价值等）：中蓝色（RGB: 189,215,238 / `#BDD7EE`）背景，黑色粗体字体
- **仅此而已——3 种蓝色 + 1 种灰色 + 白色。** 克制添加更多颜色的冲动。
- 用户提供的模板或明确的颜色偏好始终优先于这些默认设置。

**这两层如何共同工作：**
- 输入单元格：蓝色字体 + 浅灰色填充 = "硬编码输入"
- 公式单元格：黑色字体 + 白色背景 = "计算值"
- 工作表链接：绿色字体 + 白色背景 = "来自其他工作表的引用"
- 关键输出：黑色粗体字体 + 中蓝色填充 = "这是答案"

**字体颜色告诉你它是什么（输入/公式/链接）。填充颜色告诉你在哪里（标题/数据/输出）。**

### 边框标准（专业外观必需）（Border Standards (REQUIRED for Professional Appearance)）

**粗边框**（1.5pt）包围主要部分：
- 关键输入部分
- 预测假设部分
- 5 年现金流预测部分
- 终值部分
- 估值汇总部分
- 每个敏感性分析表格

**中边框**（1pt）分隔子部分：
- 公司详情 vs 历史表现
- 增长假设 vs EBIT 利润率 vs 自由现金流参数

**细边框**（0.5pt）包围数据表格：
- 情景假设表格（看跌 | 基准 | 看涨 | 已选）
- 历史 vs 预测财务数据矩阵

**无边框：** 表格内部的独立单元格（保持整洁、可扫描）

**边框是强制性的**——没有专业边框的模型不符合客户交付标准。

**数字格式**（遵循 xlsx 技能标准）：
- **年份**：格式化为文本字符串（例如 "2024" 而不是 "2,024"）
- **百分比**：`0.0%`（一位小数）
- **货币**：`$#,##0` 用于百万级别；`$#,##0.00` 用于每股——始终在标题中注明单位（"收入（百万美元）"）
- **零值**：使用数字格式使所有零显示为 "-"（例如 `$#,##0;($#,##0);-`）
- **大数字**：`#,##0` 带千位分隔符
- **负数**：`(#,##0)` 使用括号（而不是负号）

**单元格批注（所有硬编码输入强制要求）**（Cell Comments (MANDATORY for all hardcoded inputs)）：

根据 xlsx 技能要求，所有硬编码值必须带有记录来源的单元格批注。格式："来源：[系统/文档], [日期], [参考], [适用时包含 URL]"

**关键**：创建单元格时**立即**添加批注。不要推迟到末尾。

**关键 WACC 公式：**
```
市值 = 股价 × 股份数
净债务 = 总债务 - 现金
企业价值 = 市值 + 净债务
权益权重 = 市值 / 企业价值
债务权重 = 净债务 / 企业价值
WACC = (权益资本成本 × 权益权重) + (税后债务资本成本 × 债务权重)
```

### 敏感性分析（DCF 工作表底部）（Sensitivity Analysis (Bottom of DCF Sheet)）

**术语提醒**："敏感性表格" = 简单的二维网格，包含行标题、列标题以及每个数据单元格中的公式。**不是** Excel 的"数据表"功能（数据 → 假设分析 → 数据表）。你将使用 openpyxl 在每个单元格中写入常规 Excel 公式。

**位置**：DCF 工作表的第 87 行及以下（**不是**单独的工作表）

**三个敏感性表格，垂直堆叠：**

1. **WACC vs 终值增长率**（第 87-100 行）——5x5 网格 = 25 个单元格，包含公式
2. **收入增长 vs EBIT 利润率**（第 102-115 行）——5x5 网格 = 25 个单元格，包含公式
3. **贝塔 vs 无风险利率**（第 117-130 行）——5x5 网格 = 25 个单元格，包含公式

**需要编写的公式总数：75**（这是必需的，不是可选的）

**关键**：所有敏感性表格单元格必须使用 openpyxl 以编程方式填充公式。**不要**使用线性近似捷径。**不要**留下占位文本或关于手动步骤的注释。**不要**因为"这很复杂"而合理化留空单元格——使用 Python 循环生成公式。

**表格设置：**
1. 创建表格结构，包含行/列标题（要测试的假设值）
2. 填充每个数据单元格，包含一个公式，该公式：
   - 使用行标题值（例如 WACC = 9.0%）
   - 使用列标题值（例如终值增长率 = 3.0%）
   - 使用这些特定假设重新计算完整 DCF
   - 返回该情景下的隐含股价
3. 交付时所有单元格必须包含可工作的公式
4. 使用条件格式设置单元格格式：较高值使用绿色渐变，较低值使用红色渐变
5. 加粗基准案例单元格
6. 表格之间留 1-2 个空行

**无需手动干预**——敏感性表格在用户打开文件时必须完全功能正常。

## 情景选择器实现（Case Selector Implementation）

**三种情景框架：**

### 看跌情景（Bear Case）
- 保守的收入增长（历史范围的低端）
- 利润率压缩或没有扩张
- 较高的 WACC（风险溢价增加）
- 较低的终值增长率
- 较高的 CapEx 假设

### 基准情景（Base Case）
- 一致预期或管理层指引的收入增长
- 基于经营杠杆的适度利润率扩张
- 当前市场隐含的 WACC
- 与 GDP 一致的终值增长率（2.5-3.0%）
- 标准 CapEx 假设

### 看涨情景（Bull Case）
- 乐观的收入增长（预测的高端）
- 显著的利润率扩张
- 较低的 WACC（风险溢价降低）
- 较高的终值增长率（3.5-5.0%）
- 较低的 CapEx 强度

**公式实现：**

**不要**在模型中散布嵌套的 IF 公式。相反，创建一个使用 INDEX 或 OFFSET 公式从适当情景模块提取数据的合并列。

**推荐模式（使用 INDEX）：**
`=INDEX(B10:D10, 1, $B$6)` 其中 `B10:D10` = 看跌/基准/看涨值，`1` = 行偏移，`$B$6` = 情景选择器单元格（1、2 或 3）

**然后在所有预测中引用合并列：**
`收入第 1 年： =D29*(1+$E$10)` 其中 $E$10 是第 1 年增长的合并列值。

这种方法将情景逻辑集中化，使模型更易于审计和维护。

## 常见变体（Common Variations）

### 高增长科技公司（High-Growth Technology Companies）
- 较长的预测期（7-10 年）
- 较高的初始增长率（20-30%）
- 显着的利润率扩张随时间推移
- 较高的 WACC（12-15%）
- 对单位经济指标进行建模（用户数、ARPU 等）

### 成熟/稳定公司（Mature/Stable Companies）
- 较短的预测期（3-5 年）
- 适度的增长率（GDP +1-3%）
- 稳定的利润率
- 较低的 WACC（7-9%）
- 关注现金生成和资本配置

### 周期性公司（Cyclical Companies）
- 通过经济周期进行建模
- 在周期中段时正常化利润率
- 考虑低谷和高峰情景
- 调整贝塔以反映周期性

### 多业务板块公司（Multi-Segment Companies）
- 为每个业务单元进行单独 DCF
- 不同板块有不同增长率和利润率
- 分类加总估值
- 考虑协同效应

3. **检查输出**：
   - 如果 `status` 为 `"success"` → 继续执行步骤 4
   - 如果 `status` 为 `"errors_found"` → 检查 `error_summary` 并阅读 [TROUBLESHOOTING.md](https://github.com/NousResearch/hermes-agent/blob/main/optional-skills/finance/dcf-model/TROUBLESHOOTING.md) 获取调试指导

4. **修复错误并重新运行 recalc.py**，直到状态为 "success"

5. **抽检公式**：
   - 测试一个自由现金流公式——它是否引用了正确的假设行？
   - 更改情景选择器——合并列是否正确更新？
   - 验证收入公式引用了合并列（而不是嵌套的 IF 公式）

6. **交付模型**
