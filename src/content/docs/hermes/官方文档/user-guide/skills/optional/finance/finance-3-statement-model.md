# 三报表财务模型模板完成

完成并填充已集成的财务模型模板，确保利润表、资产负债表和现金流量表之间具有正确的链接。

## ⚠️ 关键原则 — 在填充任何模板前请阅读

**公式优先于硬编码（不可协商）：**
- 每个预测单元格、滚动计算、链接和小计都**必须**是Excel公式 — 不得使用预先计算的值
- 使用Python/openpyxl时：写入公式字符串（`ws["D15"] = "=D14*(1+Assumptions!$B$5)"`），**不是**计算结果（`ws["D15"] = 12500`）
- **唯一**可以包含硬编码数字的单元格是：(1) 历史实际数据，(2) 假设表中的假设驱动因素
- 如果你发现自己用Python计算了一个值并将其写入单元格 — 请停止。改为写入公式。
- 原因：模型必须在场景切换或假设变化时保持灵活性。硬编码会静默破坏所有下游完整性检查。

**与用户逐步骤验证：**
1. **映射模板后** → 向用户展示你已识别的标签页/部分，并在触摸任何单元格前确认
2. **填充历史数据后** → 向用户展示历史数据块，并确认值/期间与源数据匹配
3. **构建利润表预测后** → 运行小计检查，向用户展示预测的利润表，确认后再进入资产负债表
4. **构建资产负债表后** → 向用户展示每个期间的资产负债表检查（资产=负债+权益），确认后再进入现金流量表
5. **构建现金流量表后** → 向用户展示现金勾稽（CF期末现金 = BS现金），确认后再完成最终检查
6. **不要一次性完成整个模型的端到端填充** — 在每个报表处停下，展示工作，及早发现错误

## 格式 — 专业的蓝/灰调色板（除非模板或用户另有指定）

**保持颜色最少。** 仅使用蓝色和灰色作为单元格填充。不要引入绿色、黄色、橙色或多种强调色 — 一个干净的模型使用克制配色。

| 元素 | 填充 | 字体 |
|---|---|---|
| 章节标题（IS / BS / CF 标题） | 深蓝 `#1F4E79` | 白色加粗 |
| 列标题（FY2024A, FY2025E 等） | 浅蓝 `#D9E1F2` | 黑色加粗 |
| 输入单元格（历史数据、假设驱动因素） | 浅灰 `#F2F2F2` 或白色 | 蓝色 `#0000FF` |
| 公式单元格 | 白色 | 黑色 |
| 跨标签页链接 | 白色 | 绿色 `#008000` |
| 检查行 / 关键总计 | 中蓝 `#BDD7EE` | 黑色加粗 |

**总共3种蓝色 + 1种灰色 + 白色。** 如果模板有自己的配色方案，则遵循模板。

字体颜色表示单元格的*性质*（输入/公式/链接）。填充颜色表示单元格的*位置*（标题/数据/检查）。

## 信用指标

**注意：仅当用户提示或模板明确要求时才执行以下信用分析。如果没有提示，请跳过此部分。**

在资产负债表标签页上计算并显示信用/杠杆指标，以评估财务健康状况、债务容量和契约合规性。

### 包含的核心信用指标

| 指标 | 公式 | 衡量内容 |
|--------|---------|------------------|
| 总债务 / EBITDA | 总债务 / LTM EBITDA | 杠杆倍数 |
| 净债务 / EBITDA | (总债务 - 现金) / LTM EBITDA | 扣除现金后的杠杆 |
| 利息覆盖倍数 | EBITDA / 利息费用 | 偿还债务的能力 |
| 债务 / 总资本 | 总债务 / (总债务 + 权益) | 资本结构 |
| 债务 / 权益 | 总债务 / 总权益 | 财务杠杆 |
| 流动比率 | 流动资产 / 流动负债 | 短期流动性 |
| 速动比率 | (流动资产 - 存货) / 流动负债 | 即时流动性 |

### 信用指标层级检查

验证乐观情景显示最强的信用状况：
- 杠杆率：乐观 < 基准 < 悲观（越低越好）
- 覆盖倍数：乐观 > 基准 > 悲观（越高越好）
- 流动性：乐观 > 基准 > 悲观（越高越好）

### 契约合规性跟踪

如果已知债务契约，添加明确的合规性检查，将实际指标与契约阈值进行比较。

| 情景 | 描述 |

## 完成模型模板

本节提供完成任何三报表财务模型模板的一般指南，同时保留现有公式并确保数据完整性。

### 步骤1：分析模板结构

在输入任何数据之前，请彻底审查模板以了解其架构：

**识别输入与公式单元格**
- 寻找区分输入单元格与公式单元格的视觉提示（字体颜色、单元格阴影）
- 常见约定：蓝色字体 = 输入，黑色字体 = 公式，绿色字体 = 链接到其他工作表
- 使用Excel的追踪引用/追踪从属（公式→追踪引用）来理解单元格关系
- 检查可能控制关键输入的命名区域（公式→名称管理器）

**映射模板流程**
- 确定哪些标签页馈送到其他标签页（例如假设→利润表→资产负债表→现金流量表）
- 注意任何辅助计划表及其与主要报表的链接
- 在填充之前记录模板的具体科目和结构

### 步骤2：填充数据而不破坏公式

**数据输入黄金法则**

| 规则 | 描述 |
|------|-------------|
| 仅编辑输入单元格 | 除非有意替换公式，否则切勿覆盖包含公式的单元格 |
| 保留单元格引用 | 复制数据时，使用粘贴数值（Ctrl+Shift+V）以避免使用源格式覆盖公式 |
| 匹配模板单位 | 在输入数据前确认模板使用千、百万还是实际值 |
| 尊重符号约定 | 遵循模板现有的符号约定（例如费用为正或负） |
| 检查循环引用 | 如果模板使用迭代计算，确保已启用迭代计算 |

**安全数据输入流程**
1. 确定专门用于输入的单元格（通常高亮或标记）
2. 首先输入历史数据，然后验证公式在这些期间是否正确计算
3. 输入馈送预测计算的假设驱动因素
4. 检查计算输出，确认公式按预期工作
5. 如果必须修改公式单元格，在更改前记录原始公式

**处理预建公式**
- 如果公式引用尚未填充的单元格，预计会出现临时错误（#REF!, #DIV/0!），直到所有输入完成
- 当公式产生意外结果时，追踪引用以识别缺失或不正确的输入
- 切勿在未检查所有标签页的公式依赖关系的情况下删除行/列

### 步骤3：验证公式

**公式完整性检查**

在依赖模板输出之前，验证公式是否正常运行：

| 检查类型 | 方法 |
|------------|--------|
| 追踪引用 | 选择一个公式单元格 → 公式 → 追踪引用以验证它是否正确引用了输入 |
| 追踪从属 | 验证关键输入是否流向预期的输出单元格 |
| 公式求值 | 使用公式 → 公式求值以逐步执行复杂计算 |
| 检查硬编码 | 预测公式应引用假设，而不是包含硬编码值 |
| 用已知值测试 | 输入简单的测试值以验证公式产生预期结果 |
| 跨标签页一致性 | 确保相同的公式逻辑应用于所有预测期间 |

**需注意的常见公式问题**
- 混合绝对/相对引用导致跨期间复制时结果错误
- 断开的指向外部文件或已删除区域的链接（#REF!错误）
- 在早期期间收入上升之前的除零错误（#DIV/0!错误）
- 循环引用警告（对于利息计算可能是故意的）
- 跨预测列公式不一致（使用Ctrl+\查找差异）

**验证跨标签页链接**
- 确认出现在多个标签页上的值是链接的（而非重复）
- 验证计划表总计与主要报表上的对应科目一致
- 检查所有标签页上的期间标签是否对齐

### 步骤4：按工作表进行质量检查

填充模板后，对每个工作表执行以下验证检查：

**利润表质量检查**
- 历史期间收入数据与源数据匹配
- 所有费用科目加起来等于报告的总计
- 小计（毛利润、EBIT、税前利润、净利润）计算正确
- 税费计算逻辑适当（正确处理亏损）
- 预测驱动因素引用假设标签页（无硬编码）
- 期间对比变化方向合理

**资产负债表质量检查**
- 每个期间资产 = 负债 + 权益（主要检查）
- 现金余额与现金流量表期末现金匹配
- 营运资本账户与辅助计划表一致（如适用）
- 留存收益滚动正确：期初留存收益 + 净利润 - 股息 +/- 调整 = 期末留存收益
- 债务余额与债务计划表一致（如适用）
- 所有资产负债表科目符号正确（资产为正，大多数负债为正）

**现金流量表质量检查**
- 经营活动现金流顶部的净利润与利润表净利润匹配
- 非现金加回（折旧摊销、股权激励等）与其来源计划表/报表一致
- 营运资本变动符号正确（资产增加 = 现金使用 = 负数）
- 资本支出与PP&E计划表或固定资产滚动一致
- 融资活动与资产负债表上的债务和权益账户变动一致
- 期末现金与资产负债表现金匹配
- 期初现金等于前一期的期末现金

**辅助计划表质量检查**
- 期初余额等于前一期期末余额
- 滚动逻辑完整（期初 + 增加 - 减少 = 期末）
- 计划表总计与主要报表科目一致
- 计算中使用的假设与假设标签页匹配

### 步骤5：跨报表完整性检查

验证单个工作表后，确认三张报表正确集成：

| 检查 | 公式 | 预期结果 |
|-------|---------|-----------------|
| 资产负债表平衡 | 资产 - 负债 - 权益 | = 0 |
| 现金勾稽 | CF期末现金 - BS现金 | = 0 |
| 净利润链接 | IS净利润 - CF起始净利润 | = 0 |
| 留存收益 | 前期留存收益 + 净利润 - 股息 - BS期末留存收益 | = 0（根据需要调整股权激励/其他项目） |

### 步骤6：最终审查

在认为模型完成之前：
- 遍历所有情景（如适用）以验证检查在每个情景下通过
- 检查所有#REF!, #DIV/0!, #VALUE!和#NAME?错误并解决或记录
- 确认所有输入单元格已填充（搜索占位符值）
- 验证所有标签页的单位一致
- 在进行任何额外修改之前保存一个干净的版本

| 现金勾稽 | CF期末现金 - BS现金 | = 0 |
| 现金月度 vs 年度 | 期末现金（月度）- 期末现金（年度） | = 0 |
| 净利润链接 | IS净利润 - CF起始净利润 | = 0 |
| 留存收益 | 前期留存收益 + 净利润 + 股权激励 - 股息 - BS期末留存收益 | = 0 |
| 股权融资 | Δ普通股/APIC（BS）- 股权发行（CFF） | = 0 |
| 第0年权益 | 筹集的权益（第0年）- 期初权益资本（第1年） | = 0 |

### 符号约定参考

| 报表 | 科目 | 符号约定 |
|-----------|------|-----------------|
| CFO | 折旧摊销、股权激励 | 正数（加回） |
| CFO | Δ应收账款（增加） | 负数（现金使用） |
| CFO | Δ应付账款（增加） | 正数（现金来源） |
| CFI | 资本支出 | 负数 |
| CFF | 债务发行 | 正数 |
| CFF | 债务偿还 | 负数 |
| CFF | 股息 | 负数 |

### 循环引用处理

利息费用产生循环：利息 → 净利润 → 现金 → 债务余额 → 利息

在Excel中启用迭代计算：文件 → 选项 → 公式 → 启用迭代计算。设置最大迭代次数为100，最大变化为0.001。在假设标签页中添加断路器切换。

### 检查类别

**第1节：货币一致性**
- 识别并在假设标签页中记录货币
- 所有标签页使用一致的货币符号和单位
- 单位行与模型货币匹配

**第2节：资产负债表完整性**
- 资产 = 负债 + 权益（每个期间）
- 公式：资产 - 负债 - 权益（必须 = 0）

**第3节：现金流量表完整性**
- 现金与BS勾稽（CF期末现金 = BS现金）
- 现金月度 vs 年度：期末现金（月度）= 期末现金（年度）
- 净利润与IS勾稽（CF净利润 = IS净利润）
- 折旧摊销与计划表勾稽
- 股权激励与IS勾稽
- Δ应收账款、Δ存货、Δ应付账款与营运资本计划表勾稽
- 资本支出与折旧摊销计划表勾稽

**第4节：留存收益**
- 留存收益滚动检查：前期留存收益 + 净利润 + 股权激励 - 股息 = 期末留存收益
- 显示分解以便调试

**第5节：营运资本**
- 应收账款、存货、应付账款与BS勾稽
- DSO、DIO、DPO合理性检查（若超出正常范围则标记）

**第6节：债务计划表**
- 总债务与BS勾稽（流动 + 长期债务）
- 利息计算与IS勾稽

**第6b节：股权融资**
- 股权发行收益与BS普通股/APIC增加勾稽
- 股权带来的现金增加 = 权益账户增加（必须平衡）
- 股权筹集勾稽：Δ普通股/APIC（BS）= 股权发行（CFF）（必须 = 0）
- 第0年权益勾稽：筹集的权益（第0年）= 期初权益资本（第1年）

**第6c节：NOL计划表**
- 期初NOL（第1年/设立）= 0（新业务从零NOL开始）
- 仅当税前利润 < 0时NOL增加（亏损必须实现才能产生NOL）
- DTA与BS勾稽（NOL计划表DTA = BS递延所得税资产）
- NOL使用 ≤ 税前利润的80%（2017年后联邦限制）
- NOL余额非负（不能使用超过可用部分）
- 仅当税前利润 < 0时产生NOL
- 应纳税所得额 ≤ 0时税费 = 0

**第7节：情景层级**
- 绝对指标：乐观 > 基准 > 悲观（净利润、EBITDA、自由现金流）
- 利润率：乐观 > 基准 > 悲观（毛利率%、EBITDA%、净利润率%）
- 信用指标：乐观 < 基准 < 悲观（对于杠杆率，反向）

**第8节：公式完整性**
- COGS、S&M、G&A、R&D、股权激励由收入%驱动（无硬编码）
- 跨预测年公式一致
- 无#REF!、#DIV/0!、#VALUE!错误

**第9节：信用指标阈值**
- 根据契约阈值将指标标记为绿色/黄色/红色
- 任何红色标志的摘要

### 主检查公式

将所有部分状态汇总到单个主检查中：
- 如果所有部分通过 → "✓ ALL CHECKS PASS"
- 如果任何部分失败 → "✗ ERRORS DETECTED - REVIEW BELOW"

### 快速调试工作流

当主状态显示错误时：
1. 滚动到红色高亮部分
2. 确定哪个检查类别失败
3. 导航到源标签页进行调查
4. 修复根本问题
5. 返回到检查标签页验证已解决
