# 委派与并行工作

Hermes 可以生成独立的子代理（child agent），让它们并行处理任务。每个子代理拥有自己的对话上下文、终端会话和工具集。只有最终摘要返回给你——中间的工具调用结果永远不会进入你的上下文窗口。

## 何时使用委派

适合委派的场景：

- **推理密集型子任务**（调试、代码审查、研究综合）
- **会往你的上下文中塞满中间数据的任务**
- **并行独立工作流**（同时研究 A 和 B）
- **需要新上下文的任务**——你希望代理在没有偏见的情况下处理问题

应使用其他方案的情况：

- 单次工具调用 → 直接使用工具即可
- 机械化的多步操作 → 使用 `execute_code`
- 需要用户交互的任务 → 子代理不能使用 `clarify`
- 快速文件编辑 → 直接编辑
- 需持久运行的长时任务 → `cronjob` 或 `terminal(background=True)`

## 模式：并行研究

同时研究三个主题，取回结构化摘要。

## 模式：代码审查

将安全审查委托给一个全新上下文的子代理。

## 模式：比较方案

对同一个问题并行评估多种解决方案。

## 模式：多文件重构

将大型重构任务拆分给多个并行子代理。

## 模式：先收集后分析

用 `execute_code` 完成机械化的数据收集，然后将推理密集的分析工作委托出去。

## 继承的工具访问权限

子代理继承父代理已启用的工具集。

## 约束

- 默认最多 3 个并行任务
- 独立的终端会话
- 无对话历史记录
- 默认最多 50 次迭代
- 不持久（进程结束后不会保留）

## 提示

**目标要具体。** "修复 bug" 过于模糊。 "修复 api/handlers.py 第 47 行的 TypeError，其中 process_request() 从 parse_body() 接收到 None" 能让子代理（subagent）有足够的操作依据。

**包含文件路径。** 子代理不知道你的项目结构。始终包含相关文件的绝对路径、项目根目录以及测试命令。

**利用委派实现上下文隔离。** 有时你需要一个全新的视角。委派迫使你清晰地阐述问题，而子代理在不会受你对话中积累的假设影响的情况下处理问题。

**检查结果。** 子代理的摘要只是摘要。如果子代理说"已修复 bug 且测试通过"，请通过自行运行测试或查看差异（diff）来验证。
