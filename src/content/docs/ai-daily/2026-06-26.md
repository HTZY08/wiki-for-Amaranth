## 📌 今日值得关注

### 1. OpenAI 发布首款自研推理芯片 Jalapeño，推理成本直降 50%
**发生了什么**：6 月 24 日，OpenAI 联合 Broadcom 发布自研推理芯片 Jalapeño。该芯片为大型语言模型推理专用 ASIC，采用 reticle-sized 设计，配备 8 组高带宽内存堆栈，9 个月内完成从设计到流片。计划年底前在 OpenAI 数据中心大规模部署。
**为什么重要**：这是 OpenAI 从"买 GPU"到"自研芯片"的战略转折——直接切入 AI 基础设施最深层的成本结构。推理成本降低 50% 意味着 API 价格有巨大下降空间，也意味着 OpenAI 对 NVIDIA 的依赖将逐步降低。
**跟我有什么关系**：如果 OpenAI 将成本优势传导到 API 定价，GPT-5.5 系列的使用成本可能在未来 6-12 个月内腰斩。对于高频调用 API 的工程和研究，这是直接利好。但注意——这个芯片 OpenAI 不会对外出售，只用于自家服务。
*来源：https://techcrunch.com/2026/06/24/openai-unveils-its-first-custom-chip-built-by-broadcom/*

### 2. Google DeepMind 在 Gemini 3.5 Flash 中加入原生 Computer Use 能力
**发生了什么**：6 月 24 日，Google DeepMind 宣布 Computer Use 成为 Gemini 3.5 Flash 的内置工具。开发者可以直接用模型操控浏览器、操作桌面应用，不再需要额外框架。
**为什么重要**：Computer Use 从"独立功能"变成"模型原生能力"，是 agent 能力的架构级简化。对比 Claude 的 computer use 需要单独配置，Google 直接整合进模型调用栈，开发者体验大幅提升。
**跟我有什么关系**：如果你在做 agent 类应用（网页自动化、跨应用操作），Gemini 3.5 Flash 现在可能是集成成本最低的选项。API 调用方式不变，只需在 tool 声明中启用 computer_use。
*来源：https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-3-5/ + https://deepmind.google/models/gemini-3.5-flash*

### 3. OpenAI 退休 GPT-5.2 全线模型，GPT-4.5 本周日退出 ChatGPT
**发生了什么**：OpenAI 6 月 12 日从 ChatGPT 撤下 GPT-5.2 全线（Instant/Thinking/Pro），比原定 8 月退休计划提前两个月。紧接着宣布 GPT-4.5 将于 6 月 27 日退出 ChatGPT，o3 将在 8 月 26 日退出。GPT-5.5 Instant 同时进行可读性升级并将移除 Canvas 功能。
**为什么重要**：OpenAI 在加速模型迭代的同时也在加速"杀老型号"——GPT-5.2 用户被迫迁移到 GPT-5.5。配合 Canvas 移除，产品方向从"多工具界面"回归到"对话内即完成"（inline writing/coding）。这是产品哲学的往回走——少界面、少切换、少开销。
**跟我有什么关系**：还在用 GPT-5.2 的话，对话已经在后台被迁移到 GPT-5.5。GPT-4.5 用户只剩明天（6/27）最后一天。长期来看，GPT-5.x 系列成为唯一可选。如果依赖 o3 的某些特定行为，需要在 8 月前完成迁移验证。
*来源：https://help.openai.com/en/articles/6825453-chatgpt-release-notes + https://aiweekly.co/node/2972*

### 4. Sakana Fugu：日本首个"多模型编排"服务对标 Fable 5
**发生了什么**：东京 Sakana AI 6 月 22 日发布 Sakana Fugu（及 Fugu Ultra），一个编排模型——它不自己推理，而是将任务动态路由到多个前沿 LLM 的池子中，综合结果后输出。定价 Fugu Ultra $5/M 输入、$30/M 输出，全面兼容 OpenAI API 格式。
**为什么重要**：Sakana 是"日本 AI 国家队"级别的存在。Fugu 走的不是"训练更大的模型"路线，而是"把多个模型组合成一个更强的系统"——和 OpenRouter Fusion 思路一致，但 Sakana 自己控制路由逻辑和模型池。在多个基准测试中接近或超越 Claude Fable 5。
**跟我有什么关系**：日本首次有了一个可直接 API 调用的"前沿级"AI 服务。如果你需要高推理质量但被 Anthropic 的地缘政治限制所困扰（Fable 5 下线），Fugu 是一个值得试的替代路线。支持自定义模型组合。
*来源：https://the-decoder.com/sakana-ais-fugu-orchestrates-multiple-llms-to-match-anthropics-fable-and-mythos-benchmarks/*

### 5. GLM 5.2：开源权重模型首次在编码任务上接近闭源前沿
**发生了什么**：中国 Z.ai 发布 GLM 5.2（6 月 13 日面向编码用户，6 月 16 日全面开放），开源权重。在 Terminal-Bench 2.1 上得分 81.0（对比 GLM-5.1 的 63.5），成为最强开源编码模型。Hugging Face 上可直接下载权重。
**为什么重要**：这是继 DeepSeek R1 之后，开源模型能力最大的一次跳跃。GLM 5.2 在编码 agent 场景下首次能与 Claude Opus 4.7/GPT-5.5 正面竞争，且模型权重可自行部署。意味着"用本地模型做 agent"从玩具级变成了可用的工程选项。
**跟我有什么关系**：如果你用 Cursor/Claude Code 等 coding agent，GLM 5.2 已经可以作为后端模型接入。成本极低（自部署只需 GPU 费用），数据不出本地的优势在合规场景下价值巨大。Cursor 社区已经在请求支持。
*来源：https://huggingface.co/blog/zai-org/glm-52-blog + https://simonwillison.net/2026/jun/17/glm-52/*

### 6. Vercel 开源 agent 框架 eve：把 agent 当做目录
**发生了什么**：Vercel 6 月 17 日发布 eve，Apache-2.0 开源 TypeScript agent 框架。核心理念：每个 agent 就是一个文件目录，目录里有 prompt、tools、config、状态文件。npm 包名 eve。
**为什么重要**：这是 agent 开发的一次"范式简化"——从写代码配置 agent，变成用文件系统定义 agent。目录即 agent 的设计天然可版本控制、可分享、可组合。对比 LangChain 的抽象层叠，eve 的设计哲学更接近 Unix 哲学。
**跟我有什么关系**：如果你在 Vercel 生态中构建 agent 应用，eve 是开箱即用的选择。不依赖 Vercel 也可以用。对比 OpenClaw/Hermes Agent，eve 更适合需要自定义流程的生产级场景。
*来源：https://thenewstack.io/vercel-launches-eve-an-open-source-framework-that-treats-agents-as-directories/*

### 7. Google DeepMind 人才持续流失：Shazeer → OpenAI、Jumper → Anthropic
**发生了什么**：一周内 Google 失去两位核心研究员——Transformer 论文合著者 Noam Shazeer 加入 OpenAI（距 Google 花 27 亿从 Character.ai 挖回仅 18 个月），AlphaFold 之父 John Jumper 加入 Anthropic。
**为什么重要**：这不是普通离职——Shazeer 手握 Transformer 架构的核心 IP 理解，Jumper 是诺贝尔奖级结构生物学+AI 的顶尖人物。两人同时流向竞争对手，对 Google 的模型竞争力是实质性打击。
**跟我有什么关系**：Anthropic 拿到 Jumper 可能加速生物/AI 交叉方向（药物发现、蛋白质设计）。OpenAI 拿到 Shazeer 强化预训练架构能力。关注这两个团队后续的技术产出方向。
*来源：https://techcrunch.com/2026/06/24/ai-researchers-continue-to-leave-google-for-its-rivals/*

## 💡 技术洞见

1. **芯片层面的垂直整合正在重塑 AI 成本结构**。OpenAI 自研芯片、Google 的 TPU 持续迭代、Microsoft 的 Maia 芯片——三大模型公司都在建自己的"模型-芯片"闭环。Jalapeño 的 50% 成本降幅不是一个优化增量，而是架构级变化：当推理芯片为模型量身定制，NV GPU 的通用优势在推理场景下会被逐步侵蚀。

2. **"多模型编排"成为新的范式，而非单一模型竞赛**。Sakana Fugu、OpenRouter Fusion 都在做同一件事——不追求一个模型打天下，而是把多个模型组合成更强的系统。这个方向的深层逻辑是：单一模型的能力天花板可能比我们想象的低，但组合系统没有天花板。

3. **开源模型首次在 agent 场景下成为严肃选项**。GLM 5.2 在编码 agent 基准上接近闭源前沿。核心价值不在"能力超过 GPT-5.5"，而在"你可以自己部署"。当 GLM 5.2 + 本地 GPU 能跑出和 API 调用近似的 agent 效果，数据合规和成本控制就不再是 trade-off 了。

4. **Agent 框架正在向"文件系统即架构"的方向收敛**。从 steipete 的 OpenClaw（文件配置 agent）到 Vercel eve（目录即 agent），核心思路一致：agent 定义应该比代码更轻量，比 JSON 配置更结构化。这是 agent 工程从"写代码"到"编排组件"的演化。
