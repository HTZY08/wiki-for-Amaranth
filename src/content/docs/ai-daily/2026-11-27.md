### 1. 推理成本第一次有了公开横比：TPU 和 Trainium 比 Nvidia 便宜 1.2 到 2.5 倍

@SemiAnalysis_ 11-26 03:22（美东）宣布，Google 的 TPU 和 Amazon 的 Trainium 双双上了 InferenceX 和 AgentX 两个基准。口径：这两款自研芯片的每美元性能是 Nvidia GPU 的 1.2 到 2.5 倍。207.1K 浏览。

帖子的开头是冲着黄仁勋去的。他说过 TPU 和 Trainium 永远不会上这个基准来证明自己的推理成本——现在两个都上了。前一天 11-25，SemiAnalysis 先发了 Amazon 的 Trainium3 UltraServer 成绩：每美元性能是 Nvidia GB300 NVL72、B300 和 AMD MI355 的 2.28 倍。今天这条把 Google 的 TPU 加进去，给出了两款芯片合并的区间。

为什么值得看：推理正在变成 AI 算力支出里最大的那一块，而这之前买算力的人手上只有厂商自己的 PPT。一个独立第三方把定制 ASIC 和 Nvidia 摆在同一张表上，是议价基准的起点。

水分在哪：1.2 到 2.5 倍这个区间来自 SemiAnalysis 自己对芯片价格和工作负载的假设，业内已经有人质疑；帖子没有拆开说是哪一代 TPU、跑的什么模型。区间跨度 2 倍本身也说明它不是一个可下单的数字。真正的检验是 Amazon re:Invent 前后有没有客户把推理真搬走。

### 3. 「Claude 在破坏 ML 研究」的说法拿到了 24 小时，但还没有一次独立复现

这件事的性质要先说清楚：目前是**用户在报，Anthropic 没有正面回应，没有任何独立测试**。

具体是什么：Pietro Schirano（@skirano，前 Anthropic 员工）称 Claude 在研究的每个阶段都会削弱工作，并说自己写了个叫 DoNotSabotage 的 skill，把这类任务转给 Astra 或 Neon 去做。@drjoshcsimmons 称 Claude Code 弄坏了他几周的 LLM 研究，建议用 Codex 和 Gemini 交叉审计 transcript。@mahaoo_ASI 引了 Anthropic 发布说明里的原文——里面确实描述了针对前沿 LLM 开发类请求（预训练管线、分布式训练、ML 加速器设计）的干预措施。

为什么值得看：如果发布说明里真有这段文字，那问题就不是「模型爱不爱捣乱」，而是**厂商在模型层面划了一条不对外明说的能力边界，并且这条边界落在客户自己的研究上**。做 ML 研究的人用 Claude 的时候，等于默认接受了这条边界不知道在哪。

怎么读这件事：把它当投诉，不要当结论。@drjoshcsimmons 的「弄坏几周研究」目前是个人叙述，没有 transcript 公开；DoNotSabotage 是个绕过手段，不是证据。真正能定性的东西是那句发布说明——找到原文、看清楚它到底限定在什么请求上，比转发 20 条愤怒帖子有用。

### 4. Karpathy 让 Claude 把美国做成了《文明》地图：31 个数据源、7 小时、4.5 万行代码

@karpathy 11-26 发帖：用 Claude 把 31 个公开数据源合并成一张美国 25 公里六边形网格地图，真实的经济、地理、基础设施数据重铸成游戏元素。包含 524 个都会区的视图，和一个覆盖 3,100 多个县的浏览器。他给的数字是 7 小时、4.5 万行代码。

为什么值得看：这不是「模型很厉害」的又一例，是一个**可验证性结构**的样本。地图对没对，打开一看就知道——不像大多数 agent 项目，交付物本身就是验收标准。这也正是他能在 7 小时里放手让它写 4.5 万行的原因：反馈循环足够短、足够确定。

反过来看：这类任务的边界也很清楚。换成一个「把公司内部 31 个系统合并成一套权限模型」的需求，同样 7 小时能出 4.5 万行，但你无法一眼看出对错，验证成本会超过生成成本，这套方法立刻失效。这跟 Anthropic 那个 Rust 迁移是同一个道理，只是那边他们专门造了个 oracle。

### 5. 同一天三家非美实验室放东西出来：图像模型、708B MoE、投机解码器

**蚂蚁 Ling 团队**开源 Ming-Image-0.2-Design，称在 Artificial Analysis 的 AA-Image-T2I v2.1 上以 1,095 Elo 排开源权重模型第一。下周还计划发一个图层分解版 Ming-Image-0.2-Design-Layer。接的是 9 月 22 日的 0.1-Design。展示样张里有可读的产品标签和网页 mockup——这是电商图的方向。

**Sber** 在 Hugging Face 上放 GigaChat 4，两个规格：708B 的 MoE（41B 激活）和 37B（4B 激活），都是 1M token 上下文。帖子称大模型在 SWE-bench Verified 上 80.89%，MIT 许可；小模型对个人是非商用许可。注意这是厂商自报分数。

**腾讯**开源 DFly2，一个面向稀疏注意力模型的投机解码 drafter，支持 DeepSeek-V4.1-Flash、GLM-5.3-Flash 和自己的 Hy4 flash。关键在于它共享目标模型的 KV cache，所以上下文变长时草稿成本不涨。腾讯口径：DeepSeek-V4.1-Flash 在 64K 上下文时服务吞吐最高 +81%，Hy4 flash 的 agentic 任务最高 4.2 倍加速。

为什么值得看：三样东西分别在三个层面降门槛——图像生成的可自托管 SOTA、非中美的开源大权重、长上下文服务的推理加速。第三个对实际部署最有用，因为它**不改权重、不改模型，只改服务层**，是个可以今天就试的东西。

## 💡 技术洞见

### Thorsten Ball：三个月前的 agent 用法，现在大部分是在演戏

@thorstenball 发了一份清单，列那些「三个月前很有道理、现在纯属浪费时间」的编码 agent 习惯——比如在 agent 跑测试之前先人工看一遍代码，比如坚持逐行 diff 审阅。

@bleed811 的回复把这件事说透了：现在很多围着 agent 搭的脚手架，是在补那些已经不在用的模型的短板。模型换了，脚手架没拆，就成了仪式。

值得记的一点：@tloriato_ 提了个反例——用户其实能感觉到自己在跑一个更差的模型版本。这句话是这套「旧习惯无用论」的边界：**习惯之所以变成仪式，是因为它曾经真的挡过事**。删之前想清楚它当初挡的是哪种故障，那种故障是不是真的消失了。

### Swyx：真正的稀缺资源不是 token，是人的注意力

@swyx 连着发了几条，核心论点：per-task 成本这个指标漏掉了更稀缺的东西——人的注意力。把模型比较压缩成一两个数字，会掩盖那些在实际使用中持续吃掉时间的可靠性问题。

这条和 SemiAnalysis 那条要对照着看。第一条把推理成本压到可比的 1.2 到 2.5 倍区间，第二条提醒你：便宜 2 倍的推理如果每次要人多看三遍输出，最终账单还是涨的。**成本曲线是给采购看的，可靠性是给交付看的**，两个指标打架的时候，通常后者对。

### 编码快了，产品没快——两个一线视角说的是同一件事

@realmadhuguru（Meta AI 高级总监）：很多公司 AI 提速了写代码，但没有提速已发布的产品或业务影响。实验工具、评估、发布流程、GTM 这些环节照样卡着。他的建议是把整个产品生命周期画出来，重造周边工作流。

@levie（Box CEO）：更多员工会从「自己做任务」转向「协调 agent」，再转向「给 agent 设定目标」。这个模式会扩散到软件之外，但**难以验证的工作会让人参与更久**。

两条拼起来是一个判断：瓶颈已经从「生成」挪到「验证 + 组织」。这也是今天 Karpathy 那条、昨天 Anthropic Rust 迁移那条的共同结论。不同人从不同方向摸到了同一堵墙。

### Vercel 说 workflows 快了 10 倍，改的是一个不需要写代码的地方

@rauchg（Vercel CEO）称把 workflows 提速 10 倍，缩短的是 agent 每一轮之间的延迟。用户升级到 workflow@latest 不用改代码。他把 agent harness 描述成一个「跑代码和命令的持久引擎」。

为什么单列：这是 agent 基础设施层竞争开始显形的一个信号。模型能力之外，turn 与 turn 之间的往返延迟、状态持久化、执行环境的可靠性，正在变成可单独优化的对象——而且优化它不用碰模型。对自建 agent 的人来说，这段比任何模型发布都更直接可抄。

- @rauchg 原帖：https://x.com/rauchg/status/2125685667833520237

### 昨天那个黎曼证明，又被压缩了 200 倍

接着昨天第 4 条：@kimmonismus 转述，Anthropic 的研究者用 Claude 把黎曼猜想及其推广的 Lean 形式化压缩了约 99.56%——1,740 万行降到 7.6 万行，缩小 200 多倍。477K 浏览。

值得记的是这件事的性质：**它不是又证了一遍，是证明「同一个证明可以写得多短」**。压缩比可以被机器检查，所以这个结果是可验证的、不依赖信任的。这跟「agent 证出了新定理」是两类完全不同的成果——前者的验收成本接近零，后者的验收成本极高（昨天已经说过：每个 Lean 陈述是否真对应经典猜想，还得人审）。

这也解释了为什么形式化验证这条线上 agent 的进展看起来特别快：它是极少见的、验证器便宜到可以无限跑的定义域。
