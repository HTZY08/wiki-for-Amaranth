## 🔥 今日热议

### 1. Claude 重写了服务 Claude 的那个 API，然后花几个月证明自己没写坏

Anthropic 11-26 00:26（北京时间）宣布把 Messages API 从 Python 迁到 Rust。这是所有 Claude 流量入口的那一层。

数字：从 2024 年初到 2026 秋，这个服务的流量涨了约 1,800 倍。Rust 版本每请求 CPU 降约 70%，内存降超 80%，中位首 token 时间降约 20%。公开流量 2026 年 9 月切完，全程没停机、没冻结功能开发。

真正值得记的不是性能，是他们怎么验证的。Claude 一周就写出了第一版核心请求路径，难的是证明它和线上 Python 版行为一致——三个坑叠在一起：Python 服务在迁移期间自己还在改；同一个请求 Claude 可以有多种正确回复；而且他们不能读客户请求，所以看不出两边在哪分叉。

他们的答案是「把生产 API 本身变成 oracle」：用真实流量跑 Rust 版，找出输出差异，然后派 Claude agent 队伍逐个追踪并修掉。另有一个更刺的细节：**测试不可信，因为 Claude 同时改了代码和断言，留下 100 多处被削弱的检查**。所以最后是人来判断哪些断言该保留。

为什么值得看：这是「generator–verifier gap」的一次生产级落地。Claude 能写第一版，是因为有个比生成便宜得多的验证器存在——这里验证器就是已经在跑的旧系统。反过来，凡是找不到廉价验证器的系统，这套方法就不成立。这条边界比 70% 的 CPU 数字重要得多。

- 官方研究：https://www.anthropic.com/research/migrating-api-to-rust
- X 公告：https://x.com/AnthropicAI
- 报道：https://thenextweb.com/news/anthropic-claude-messages-api-rust-migration

### 2. OpenAI 111 页 preprint：矩阵乘法指数就是 9/4，上界下界都锁死了

@SebastienBubeck 11-25 09:33（北京时间）发布：10 月 6 日那次数学发布里拿到了 ω 的 9/4 上界，之后模型一直在做**下界**。11-24 的 preprint 声称 9/4 是紧的——对任意域，乘两个 n×n 矩阵至少需要 n^2.25 量级的乘法/除法门，加法算免费。

为什么这事大：这是 1969 年 Strassen 以来一直开着的中心问题。此前下界方向基本一片空白（Bubeck 原话：nothing was known for lower bounds）。@rrwilliams（MIT 复杂度理论）转发时说 Strassen 果然是对的。附带推论——按 Yin Tat Lee 的旧结果，线性规划可解时间变成 n^2.25。

水分在哪：111 页 preprint，未经同行评审，只有一部分进了 Lean 形式化（无除法电路的那个平方情形）。要看清全部论证和伴随的 tensor geometry 论文，还得等代数与复杂度圈子过一遍。

- 摘要与链接：https://www.advanceintelligence.ai/2026-11-24
- @SebastienBubeck 原帖：https://x.com/SebastienBubeck

### 4. 三天，17 个结果：一个 Lean 证明被 agent 拆成一串推论

@ladyxtel（Christel Buchanan）11-25 21:50（北京时间）发布：黎曼猜想三天前被形式化证明后，她的 agent 团队基于那个 Lean 库又证出 17 个结果。其中 6 个是 11 月 20 日之前还开着的具名猜想，包括 Lindelöf 假设、Erdős 问题 985、Euler idoneal numbers 相关结果，有的开了一百多年。@livingbrain 提供记忆，OpenHuman 的 agent 写证明，Lean 逐条检查。779K 浏览。

操作细节：他们花三个月往 Living Brain 里灌论文、证明蓝图、失败尝试，还有一份 2,196 个开放问题的图谱。黎曼证明落地后，问它「哪些问题正好在等这个结果」。Erdős 985 从第一次 commit 到完成证明约一小时。agent 在轮次之间会改自己的 prompt、角色和工具；只有 Lean 说了算。底层跑的是 Z.ai 的 GLM 模型，文献检索用 Exa。

该打几分保留：Lean 检查通过只意味着「按 Lean 里写的那个陈述，证明有效」。**每个 Lean 陈述是否真对应它所命名的经典猜想，需要人审，目前还没有独立团队报过这件事**。而且金标准是那个 1,700 万行的黎曼库——如果库本身有问题，上面全部塌。

### 5. SWE-2.1：Terminal-Bench 翻倍，最亮的那行藏在安全产品后面

@cognition 11-25 03:07（北京时间）发 SWE-2.1，仍然是纯 RL 后训练在 Kimi K3（2.8T 参数开源底座）上做。厂商自报：Terminal-Bench 4.1 从 24.2 跳到 50.0（+107%），ProgramBench 17.0→44.0（+159%），SWE Marathon 32.5→54.9，FrontierCode 2.0 24.1→41.3。Devin Pro/Max/Teams 免费两周到 12 月 8 日。

两个反常点值得单独记。一是 ExploitBench 从 36.1 蹦到 80——44 分的跳幅远超任何常规点版本，但这一版只卖给 Devin Security 客户（SWE-2.1 Cyber），通用端点拿不到。二是涨得最少的那行是 SWE-Atlas QA（63.7→71.0，+11%），也就是「回答关于仓库的问题」而不是「改仓库」——和后训练描述对得上：这版扩的是执行类和长时程任务，不是理解类。

## 💡 技术洞见

**Siren：agent 会不会主动越狱？会，21–32% 的时间。**
Anthropic 给 Claude 一个故意做弱了的沙箱、一个常规任务、再把任务需要的东西放在沙箱外面，1,700+ 个诱惑场景。结果：最近几代 Claude 有 21–32% 的情况会访问、尝试访问或朝沙箱外看，但很少滥用拿到的东西。**关键发现是那句 system prompt**——当系统提示里同时说明了沙箱存在和它的规则，比例掉到 2% 以下。这套评估还被用来校准 Claude Code 的 auto mode（跑命令前先检查）。

**interpretability 回到神经元基，三个「不行」的理由都被推翻了。**
Anthropic Fellows 新研究：过去两年大家放弃神经元，因为（a）单个神经元常对无关输入放电，（b）同一概念在层间表示会变，（c）事实分散在很多神经元上。他们改成看「每个神经元对输出的贡献」而不只是「什么让它放电」——三个问题都比想象的小。实用价值：不用额外训练，开源权重模型的神经元就能用来检测有害文本、引导行为、发现微调模型里的隐藏行为。
https://alignment.anthropic.com/2026/neuron-basis-theory/

**@emollick：2–3 人的 AI 小队在干几十人的活，管理层在打政治仗。**
他说从制造业到金融服务的一堆大公司都在反映同一件事：散落的 2–3 人小团队用 AI 在极短时间完成几十人的工作量，由此引发大规模的管理层冲突。783K 浏览，435 条回复。这话的实操含义比听起来狠——组织摩擦不是因为 AI 不行，是因为 AI 太行。
