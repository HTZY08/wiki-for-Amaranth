# 🔥 今日焦点

## 1. Anthropic 砍掉 Claude Code 80% 系统提示词——Fable 5 模型"不想要那么多指令"

**核心事实**：Anthropic 技术员工 Tariq Shihipar 透露，Claude Code 的系统提示词被削减了约 80%。原因很反直觉：Fable 5（Mythos 类）模型"想要更小的系统提示词"，示例反而会"约束它，因为它比我们给的示例更有想象力"。Anthropic 不再使用"do not do this"式的硬规则，而是通过上下文来引导模型行为。

**为什么重要**：这是 LLM 提示工程领域的一个范式转变。长期以来，系统提示词的设计思路是"写得越详细越安全"——OpenAI 的 GPT 系列、早期 Claude 模型都遵循这一逻辑，系统提示词动辄数万字符（Claude Fable 5 在 Claude.ai 上的完整提示词泄露显示高达 120K 字符）。Fable 5 的表现说明：更强的模型不一定需要更多指令，相反，过度规则化反而削弱了模型的判断力和创造力。这对 Agent 系统设计有直接启示——Skill 文件、CLAUDE.md、插件配置等都应当从"约束性规范"转向"上下文性指引"。

**讨论**：Simon Willison 在其博客中详细记录了 Fable 5 的使用体验，认为模型在低 effort 模式下表现出的主动性和代码质量远超此前版本。Reddit r/ClaudeAI 社区对此反应复杂——一方面认可模型能力提升，另一方面抱怨 Anthropic 的访问限制策略（Fable 5 免费到 7 月 7 日，之后转为 usage credit）。

**来源**：the-decoder.com / Simon Willison's blog

## 2. Kimi K2.7 Code 登陆 GitHub Copilot——首个开放权重模型进入 Copilot 模型选择器

**核心事实**：Moonshot AI 的 Kimi K2.7 Code（开放权重模型）正式在 GitHub Copilot 中可用，支持 VS Code（1.127+）、Visual Studio（17.14.6+）、Copilot CLI、JetBrains、Xcode 等全平台。这是 GitHub Copilot 首次提供开放权重模型作为可选项。模型由 GitHub 托管在 Microsoft Azure 上，按 provider list pricing 计费。先面向 Copilot Pro/Pro+/Max 用户灰度，后续扩展到 Business/Enterprise。

**为什么重要**：之前 Copilot 的模型选项仅限于 OpenAI 和 Anthropic 的闭源模型。Kimi K2.7 的接入意味着：①开放权重模型在编码场景已具备竞争力，足以进入主流商业工具；②GitHub/微软在模型策略上开始"多模型并行"，不再单一依赖 OpenAI；③对于关注数据隐私和成本的企业，开放权重模型提供了新的选择维度。

**链接**：https://github.blog/changelog/2026-07-01-kimi-k2-7-is-now-available-in-github-copilot/
