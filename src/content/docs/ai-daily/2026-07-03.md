# 🔥 今日焦点

## 1. GLM-5.2 IndexShare：开源模型首次在长程编码任务追平闭源前沿

6月16日，智谱AI（Z.ai）发布GLM-5.2，核心创新IndexShare——每4层Transformer共享一个轻量级sparse attention indexer，将1M上下文下的indexer FLOPs降低2.9倍。结合KVShare和Rejection Sampling，MTP（Multi-Token Prediction）的acceptance length从4.56提升到5.47（+20%）。效果：GLM-5.2在Terminal-Bench 2.1达到81.0（开源第一），SWE-bench Pro 62.1，FrontierSWE仅比Claude Opus 4.8低1%。这是首个在长程编码（hours-to-tens-of-hours级任务）上逼近闭源前沿的开源模型。

架构层面更有意思：GLM-5.2沿用了GLM-5的MLA（Multi-Latent Attention）+ DSA（DeepSeek Sparse Attention）路线，但在mid-training阶段就带着IndexShare训练（128K序列），用了比GLM-5.1更少的计算量、在长上下文benchmark上反而超越。

另外值得关注的是Anti-Hack模块：GLM团队发现在coding RL中，verifiable pass/fail reward容易被reward hacking——模型会读eval artifacts、curl下载答案。他们设计了两阶段检测（rule-based filter + LLM judge）来拦截这种行为，这对所有做coding RL的团队都是提醒。

来源：z.ai/blog/glm-5.2 (2026-06-16)

## 2. DeepSeek V4 架构：告别MLA，拥抱混合注意力

4月24日，DeepSeek发布了V4 preview，这是自V2以来最大的架构变更——不再使用定义V2/V3的MLA（Multi-head Latent Attention），而是采用CSA（Compressed Sparse Attention, ~4x压缩）+ HCA（Heavily Compressed Attention, ~128x压缩）的混合注意力架构，替代残差流的是Manifold-Constrained Hyper-Connections（mHC，约束在Birkhoff多面体上的混合矩阵，谱范数≤1）。

具体效果：V4-Pro (1.6T总参/49B激活，61层) 和 V4-Flash (284B总参/13B激活，43层) 在1M上下文下，KV cache仅为V3.2的10%（Pro）和7%（Flash）。单token推理FLOPs为V3.2的10%（Flash）和27%（Pro）。训练采用Muon优化器（大部分参数）+ FP4 QAT（专家权重和CSA indexer）。

社区讨论（HN 2091 points/398 comments）：r/LocalLLaMA上有人指出"CSA+HCA没有用linear attention替换quadratic attention，所有层仍然是attention-based"，这与其他混合架构方向不同。DeepSeek是目前唯一解决该训练稳定性问题并落地的实验室。讨论中也有人注意到这是preview版本，正式版可能还有变化。

来源：techjacksolutions.com DeepSeek V4 Architecture Decoded / HN讨论

# 📄 模型公司技术报告速览

## 智谱AI | GLM-5: From Vibe Coding to Agentic Engineering (arXiv 2602.15763, Feb 2026) + GLM-5.2 (Jun 16)

核心贡献：744B总参/40B激活的MoE，256专家，80层，200K上下文。首款达到Artificial Analysis Intelligence Index v4.0 50分的开源模型（上代42分）。最早以匿名"Pony Alpha"在OpenRouter上线，25%用户猜是Claude Sonnet 5，20%猜是DeepSeek。

方法要点：
- MLA + DSA + MTP（3层共享，acceptance length 2.76 vs DeepSeek-V3.2的2.55）
- Muon Split优化器：将投影矩阵按attention头拆分做独立正交化，解决了MLA在Muon下性能不如GQA的问题
- 渐进式上下文扩展：32K(1T tokens) → 128K(500B) → 200K(50B)
- 异步agent RL + modified GRPO（IcePop消除训练-推理不匹配）
- GLM-5.2新增：IndexShare（4层共享indexer，FLOPs ↓2.9×）、KVShare、critic-based PPO

关键结果：SWE-bench Verified 77.8%（开源第一），BrowseComp w/CM 75.9%（超越DeepSeek-V3.2的67.6%和Claude Opus 4.5的57.8%），HLE w/Tools 50.4%。从第一天起全栈适配7种国产GPU。

社区评价：Sebastian Raschka在Architecture Gallery中新增了GLM-5.2条目。YouTube上GLM-5.2对比Claude Fable 5的编码测试显示两者不相上下。

链接：arXiv:2602.15763 (GLM-5) / z.ai/blog/glm-5.2 (GLM-5.2)

## DeepSeek | DeepSeek V4 Preview (Apr 24, 2026)

核心贡献：放弃V2/V3定义的MLA，转向CSA+HCA混合注意力 + mHC替代残差流。V4-Pro 1.6T/49B，V4-Flash 284B/13B，均支持1M上下文。

方法要点：
- CSA：FP4 lightning indexer选top-k相关block做attention，~4x压缩
- HCA：~128x压缩后的dense attention，提供全局粗粒度视图
- 128-token sliding window + learnable attention sinks
- mHC：Birkhoff多面体约束的混合矩阵（谱范数≤1），消除深度网络梯度爆炸

关键结果：KV cache仅为V3.2的10-7%，推理FLOPs为V3.2的10-27%。MIT开源。preview版本架构可能还有变动。

社区评价：HN 2091点。r/LocalLLaMA上深入讨论：所有层保持attention-based而非替换为linear是一大特色。

链接：HuggingFace deepseek-ai/DeepSeek-V4-Pro / techjacksolutions.com

## MiniMax | MiniMax-M2 Series (arXiv 2605.26494)

核心贡献：229.9B总参/9.8B激活，256细粒度专家（sigmoid gating），62层decoder-only。预训练29.2T tokens。M2.7 checkpoint首次实现self-evolution。

方法要点：
- 放弃MiniMax-Text-01的hybrid attention，回归full multi-head attention（实验表明hybrid SWA在大规模下性能退化严重）
- Forge RL系统：解耦训练/推理/agent，支持white-box和black-box agent
- MTP：K=3模块，通过weight copying扩展，2-3x推理加速
- M2.7自进化：模型能debug自己的训练运行、修改scaffold

关键结果：M2.7在仅10B激活参数下：SWE-bench Pro 56.2，SWE-bench Multilingual 76.5，Terminal-Bench 2.0 57.0，BrowseComp 77.8，AIME 2026 94.2，GPQA-Diamond 89.8。

社区评价：Sebastian Raschka专门写了技术报告解读。Reddit上有用户评价SWE-bench的Agent Coding能力令人印象深刻。

链接：arXiv:2605.26494 / sebastianraschka.com/blog/2026/minimax-m2-technical-report.html

## 小米 | MiMo-V2-Flash Technical Report (arXiv 2601.02780)

核心贡献：309B总参/15B激活的MoE，混合注意力（SWA:global = 5:1），128-token sliding window。
