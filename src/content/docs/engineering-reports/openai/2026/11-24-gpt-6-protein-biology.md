# GPT-6 models demonstrate intrinsic protein-design capabilities

**发布日期：** 2026-11-24
**来源：** https://openai.com/index/gpt-6-models-demonstrate-intrinsic-protein-design-capabilities
**预印本：** *GPT-6 as a Universal Foundation Model for Protein Biology: Beyond Specialized Models*
**工程范式：** 不训练任何生物学模型，把一个通用推理模型 + 代码执行器塞进结构生物学的既有工作流，只接管"骨架生成"和"序列重设计"这两段原本由 RFdiffusion / ProteinMPNN 占据的环节；然后用自有湿实验去量它到底能不能用。

## 设计哲学

这篇的核心不是"AI 会设计蛋白了"，而是**一个能力约束的重新表述**。

约束来自现有流水线的形状：结构化学生物学依赖一堆窄模型——RFdiffusion 做骨架，SolubleMPNN / ProteinMPNN 做序列，ESMFold / Boltz-2 做结构预测与过滤。这套东西的问题不在单项精度，在**接口刚性**：每个模型只接受特定种类的输入和约束，想加一个新条件（"把这三个残基固定住"、"要五段卷曲"、"通过 β-sheet–β-sheet 接触"）就得改软件或重训。协调这些模型本身需要相当的专业知识。

OpenAI 的选择是把接口换成人话 + 代码。模型的输入是自然语言指令（目标蛋白结构、结合位点、结构类别、螺旋/链的数量）加 3D 坐标，输出是它自己写的脚本来探索构象和氨基酸选择。同一个模型靠换 prompt 就能从"预测小分子怎么嵌"切到"设计一个 minibinder"，不需要重训。

**放弃的东西写得很清楚：端到端。** 论文自述其流程仍然依赖 SolubleMPNN 供序列、Boltz-2/OpenDDE/ESMFold2 过滤候选，"因此我们的结果尚不能证明我们的模型可以在零样本、无专用模型辅助的情况下端到端生成 de novo minibinder"。也就是说，它抢的是流水线里的两段，不是整条流水线。把它读成"通用模型取代结构生物学工具链"会读错。

第二个放弃：**放弃"通用 > 专用"的叙事，改用"锯齿状能力前沿"（jagged capability frontier）来表述。** 从序列预测完整三维结构这一项，最好的内部模型 TM-score 均值 0.38，ESMFold2 是 0.93。这个差距被主动放在 Limitations 里，而不是藏在附录。

## 关键架构决策

- **注意力机制**：未披露。文章不含任何架构节。
- **MoE 设计**：未披露。所有涉及模型规模、参数量、训练算力的字段，原文均未公开。
- **训练策略**：未披露。原文只描述方法（自然语言指令 + 通用代码工具 + SMILES 化学表示 + 3D 坐标输入），不描述这些能力是怎么训出来的。
- **推理优化**：原文提到"at each model's highest evaluated compute setting"，即以各模型最高算力档位评测，但未给出推理栈细节。
- **能力来源的举证方式（本文真正的技术贡献）**：用**推理轨迹和生成代码**作为可解释性证据。文章展示模型在给 IL-7Rα 做 minibinder 时先分析目标表面、把五段卷曲排成一个形状、再写代码检查两个蛋白能否贴合。这条逻辑链是判断"这是生物学推理还是查表"的主要依据。
- **去记忆化的设计**：为排除训练集记忆，实验里刻意使用**未公开的骨架**（模型自己先前生成的 PD-L1 / IL-7Rα 形状）要求重新设计序列，并检查新序列与原序列的差异幅度。

## 关键结果

全部数据来自原文，均为 OpenAI 自有评测与自有湿实验。

**湿实验 1 — minibinder 结合（合作方 Onava）**
- 322 个 minibinder × 5 个靶点，35 个（10.9%）检测到结合。
- 分靶点：PD-L1 5 个，IL-7Rα 3 个，TrkA 1 个，VEGF-A 8 个，IL-17A 18 个。
- 原文注明：原始 RFdiffusion 研究报告的命中率更高，但命中率高度依赖上湿实验前的过滤严格程度以及"结合"的定义。

**湿实验 2 — 给定 3D 结构、隐藏原序列后重新设计序列**
- MDM2：88 个设计中 75 个结合（85%）；VEGF-A：42 中 26（62%）；PD-1：59 中 8（14%）。
- 与原序列的差异中位数：VEGF-A 50%，MDM2 43%，PD-1 15%。
- 针对 3 个**未公开**骨架（2 个 PD-L1、1 个 IL-7Rα）：107 个蛋白中 14 个（13.1%）结合。
- 同一个 PD-L1 骨架上，GPT-6.2 给出的两条序列分别与原序列在 90 个氨基酸中的 52 和 58 个位置不同，两条之间也有 44 个位置不同。

**抗体结合环重设计**
- 单域抗体（VHH）对 IL-4Rα：182 个设计中 128 个（70%）结合。
- 5 个治疗性抗体的结合环片段：272 个片段中 179 个（66%）保持对 PD-1 / PD-L1 的结合。

**计算评测（对照专用模型）**
- MotifBench motif scaffolding，30 个挑战：最新内部模型 43.7%，RFdiffusion 27.8%。
- CATH fold design，200 个任务：18.9%，Proteina 17.1%。
- 小分子对接 PoseBusters：GPT-6.2 93%，最新内部模型 96%，DiffDock-L 50%。
- Scarpino 数据集（预先告知成键的两个原子，179 个结构）：GPT-6.2 92%，内部模型 97%，DiffDock 60%。
- 抗体—靶点 DockQ 均值（隐藏全部侧链）：GPT-5.6 ≈0.05 → GPT-6 0.28 → GPT-6.2 0.57 → 最新内部模型 0.81。
- 突变效应排序（稳定性，265 组，rank correlation）：0.41 → 0.52 → 0.57 → 0.66。
- 从序列预测结构（TM-score 均值）：0.16 → 0.26 → 0.38；ESMFold2 0.93。

原文点出的两个解读陷阱：序列从结构反推的高分可能部分来自记忆（这些结构是模型自己生成的，残留了生成过程的规律）；湿实验只证明结合，特异性、稳定性、生物活性、安全性与有效性均未测。

## 范式对比

- **对 DeepMind**：同为"通才模型做结构生物学"，但路径相反。AlphaFold / AlphaGenome 走的是训练专用架构 + 专用数据，把精度推到极限；OpenAI 走的是不训练专用模型、靠推理 + 代码调用已有工具，把**可操控性**推到前面。前者比的是 TM-score，后者比的是"能不能用一句话描述一个自然界不存在的约束"。
- **对 Isomorphic / Chai 这类蛋白设计公司**：那些团队的护城河是"自有模型 + 自有湿实验闭环"；OpenAI 的姿势是提供通用能力，湿实验外包给 Onava。它卖的不是蛋白，是可编程性。
- **对 DeepSeek / Qwen 这类价格战玩家**：完全不在一个维度。这条线上没有 token 价格，只有"每个设计—测试循环的成本"。
- **可迁移的范式信号**：把"代码执行"当作科学模型的对外接口。所有能被形式化、能写脚本验证的科学任务，都可以拿通用模型 + 代码工具去顶专用模型的位。这次选蛋白是因为它有干净的可验证终点（结合 / 不结合）。

## 社区评价

HN 讨论的主线是"intrinsic 这个词用得过不过分"。批评方的论点集中在流程事实：de novo 设计本来就是两段式——先用一个模型出骨架，再用 MPNN 填侧链；GPT-6 干的是前一段，而前一段本来就决定了大半成功率。另一条质疑是"如果训练语料里含其他前沿蛋白模型的代码和数据，那这叫不叫 intrinsic 存疑"，主张的判据是"无工具调用的零样本/少样本设计"。文章自己的 Limitations 实际承认了后一条的边界（依赖专用模型供序列与过滤）。

## 可复用的工程经验

1. **用"已公开 vs 未公开"做记忆审计**。想证明模型不是查表，最便宜的办法是给它一个它自己生成、从未公开过的中间产物再要求重算，并量化输出的差异幅度（这里是 90 个位点里差 52–58 个）。这个实验设计比任何 ablation 都便宜。
2. **报命中率必须同时报过滤强度**。原文主动指出自己的 10.9% 不能和 RFdiffusion 的历史数字直接比，因为湿实验前的过滤严格度和"结合"的定义不同。跨论文比命中率而不对齐过滤协议，等于比两个不同的量。
3. **能力领先要按子任务拆，不要按模型拆**。同一个模型在 motif scaffolding 上超过专用模型（43.7% vs 27.8%），在结构预测上落后一大截（TM-score 0.38 vs 0.93）。"这个模型行不行"是个错问题，"哪个子环节可以换掉"才是对的。
4. **接口即产品**。这套方案真正的工程价值不是精度，是把"新约束"的成本从"改软件/重训"降到"改 prompt"。任何流水线里，如果某一段的输入是刚性 schema 且用户经常想加新字段，那一段就是通用模型的机会窗口。
5. **把安全评估架在能力披露之上**。原文在给结果的同时声明同一批能力可被滥用，交回 Preparedness Framework 评估。做双用途能力（生物、化学、网络）的团队，能力发布与风险评估要同批出，不能先发再补。
