# Qwen4-Max：新架构换来的不是分数，是每任务成本

**发布日期：** 2026-11-16（11 月 11 日起为订阅制预览）
**来源：** https://qwen.ai/blog?id=qwen4-max
**工程范式：** 注意力与残差同时重构，用"压缩历史 + 微块级索引 + N-gram 查表"三招换取长序列效率；产出导向的评测（成本/任务、token 消耗）优先于排行榜。

## 设计哲学

Qwen 这次的核心叙事不是"更强"，而是"同样的活更便宜"。官方给的效率数字：Work360 上 token 用量降约 24%（Xhigh）/35%（High），Terminal-Bench 4.0 上降约 48%/49%，Work360 每任务平均成本从 $4.43 降到 $1.67（−62%）。价格同步下调，尤其是缓存输入。

支撑这些数字的是三处架构改动，方向一致：让历史不必逐 token 存。放弃的是"全注意力 + 全量 KV"的简单性，换来的是长序列上的计算与索引双降；代价是架构复杂度上升，且**权重不公开**——本代只有 API。

## 关键架构决策

- **规模**：2.4T backbone 参数，71B 激活/token，另有 **328B N-gram Embedding 参数**；1M 上下文；原生视觉输入。权重未发布。
- **GDN + QSA**：每层 Qwen Sparse Attention 前配 3 层 Gated DeltaNet，把历史压成**定长状态**；QSA 用轻量 indexer 在**微块（micro-block）粒度**选相关上下文，同时降低注意力与索引成本。
- **Gated Residual（GR）**：4 条并行残差分支，用动态读写门控加强跨层信息流与训练稳定性。
- **N-gram Embedding**：在第二层做上下文相关查表，为局部 token 模式提供表示——用极少的算力扩容参数。
- **训练稳定性**：官方称 2.4T 规模训练"loss 平滑下降、全程无 loss spike"，归因于架构与优化改进。
- **Agent 工程**：对外开放 Qwen-Live-Delivery-Plugin，长任务"先交可用初版、再迭代"，让用户中途可纠偏。

## 关键结果

- Work360（26 个一级域、182 个二级、721 个三级细分）：**52.69**，Qwen3.8-Max 为 47.74。
- 内部 Base 评测（Knowledge / Code / QA / STEM）：Qwen4-Max-Base 在五个 checkpoint 中 BPB 最低，各域比 Qwen3.8-Max-Base 低约 **5%–13%**，而激活参数少 **25%**。
- 成本：Work360 每任务 $4.43 → **$1.67**；API 定价 $1.50 / $4.50 每百万输入/输出 token（此价格取自第三方对官方发布的整理，官方博文正文以"大幅下调缓存输入价"表述，具体价目以 QwenCloud 为准）。
- 工程案例（官方展示）：汽车产线场景里，单个工件的编程人工耗时从约 475 分钟降到 24 分钟（约 −95%）；金融研究调用 90 个 MCP 工具做 A 股/港股/美股与债券基金衍生品的交叉核验，产出带可点击溯源链接的 Excel 与可对齐到工作簿的 PPT；Pre-IPO 法务尽调把 198 份格式混乱的工作底稿整理为 14 个目录、86 页报告、60,000+ 字、14 个法律问题。

## 范式对比

同一个"降低长上下文成本"的目标，四条路线：DeepSeek 压 KV 字节（890 B/token）、MiniMax 造稀疏算子（per-token 计算降到 1/20）、Qwen 把历史压成定长状态 + 微块索引、Moonshot 靠后训练而非架构。Qwen 的独特之处是把 **N-gram 查表**作为扩容手段——用近似零算力换参数容量，这在万亿级模型上是很少见的取巧。

另一处差异是交付形态：Qwen4-Max 只给 API，官方承诺"更小的 Qwen4 会开源"。相比之下 Kimi K3.1 Pro、GLM-5.3、Mistral Large 4 都给了权重。

## 社区评价

公开讨论主要围绕"N-gram Embedding 是否等价于把 MoE 的一部分换成查表"以及"1M 上下文的实际有效长度"。这些属于架构推测，官方未回应，wiki 不做结论。

## 可复用的工程经验

1. **把 token 消耗与每任务成本当一等指标公布**。用户真正付的是每任务成本，不是每百万 token 单价。
2. **定长状态 + 微块索引**是可以组合的两层：前者砍存储，后者砍索引开销，别只做一层。
3. **查表扩容**：在算力受限时，N-gram/N-gram 类嵌入是"低成本加容量"的现实选项。
4. **长任务的交付形态要改**：Live Delivery（先交初版再迭代）比"等全部跑完"更能容错，也更适合人机协作。
5. **训练稳定性要能归因**。2.4T 规模无 loss spike 是可复用的工程结论，但必须能说清是架构还是优化器带来的。
