# Qwen-Audio-3.1-ASR Technical Report

**发布日期：** 2026-10-20（arXiv v1，cs.SD）
**来源：** https://arxiv.org/abs/2610.28711
**机构：** Alibaba Token Foundry, Alibaba Group
**工程范式：** 沿用"音频编码器 + adapter + MoE 语言模型解码器"这条既定骨架，不动架构，把扩展全部压在**输出空间**和**训练流水线**上——把转写扩成结构化转写（说话人 + 时间戳），再扩成通用音频理解，最后用多教师在线策略蒸馏把多个专家能力和回一个模型里。

## 设计哲学

约束来自一句话：**产品要的不是转写文本，是"谁在什么时候说了什么，以及这段音频里还发生了什么"。**

原文把要回答的问题拆成三个——说了什么、谁说的和何时说的、转写之外音频还传达了什么都。麦克风阵列、会议记录、访谈这些真实场景里，逐字稿即使字全对也可能错，因为说话人归属和时间关系错了。

大多数工程队伍面对这个需求的解法是级联：ASR → 说话人分离 → 时间戳对齐，三段流水线拼起来。这篇明确反对这个解法，理由是级联把误差叠起来，而且各段看不到彼此的中间表示。它选的路线是**单解码器联合建模**：模型直接输出带说话人标签、时间戳、文本的结构化序列，跨轮次保持说话人标签一致，并能表示重叠语音。

代价也很清楚，写在变体表里：**流式变体不支持说话人分离和通用音频理解**。也就是说这个能力有部署形态上的硬边界——低延迟流式只做转写 + 上下文 + 热词，要做 diarization 就得走非流式的 Flash / Next。这是为了 latency 主动放弃的能力，不是没做到。

另一处放弃：**放弃用专用 diarization 模块保底**。既然结构上让解码器自己出说话人 token，那么 diarization 的质量就完全取决于训练信号怎么设计——这直接决定了后面那套 loss 重加权的必要性（见下）。

## 关键架构决策

- **整体结构**：audio encoder → audio adapter → LLM decoder。另有一条**辅助 CTC 分支**给上下文处理提供初步识别假设（图里省略，正文说明）。
- **解码器初始化**：从 Qwen 的语言模型部分初始化，**不使用其视觉组件**；主干是 **MoE 架构**。选择 MoE 的理由原文写得很直白：保留语言能力与多语言知识，同时把每 token 计算与解码成本压下来，"使其适合包括延迟敏感的流式变体在内的整条产品线"。
- **音频编码器预训练**：两段式——先 **BEST-RQ** 自监督，在大规模无标注语音上训练（语料跨 AI、生物技术、电商、教育、娱乐、金融、出行等领域，原文称"数千万小时"量级）；再做**有监督 AED**（attention-based encoder–decoder）训练。编码器的兼容 Transformer 层**从预训练的 Qwen3 语言模型初始化**（跨模态初始化）；非流式编码器把因果注意力换成双向注意力，声学前端单独初始化。
- **Audio LLM 预训练**：约 **2000 万小时**多语言数据，主体是 ASR 数据和交错文本—音频数据；此阶段**冻结音频编码器**，只更新 adapter 与 LLM 解码器。
- **Cooldown 适应**：约 **100 万小时**更高质量音频—文本数据，用于精调音频—语言对齐，重点是语言与中文方言分布更均衡、转写质量更高、任务与指令混合更广。
- **SFT**：联合更新音频编码器与 adapter，**冻结基础 LLM**，decoder 走 **LoRA**。训练样本是对话格式（用户指令 + 音频 → 助手回复），目标函数是自回归交叉熵。
- **RL**：vLLM 做 rollout（音频编码器与 adapter 把 Mel 特征变成帧级 embedding，与文本 embedding 拼接后由 MoE 解码器采样 G 条候选），按任务与数据源取 reward（ASR reward 评转写与指令条件行为；diarized ASR reward 联合评说话人分离、转写准确率与时间），Megatron-Core 做策略优化（张量 / 流水线 / 专家并行）。
- **多教师在线策略蒸馏（MOPD）**：六个阶段中的最后一环，把多个教师模型的能力消解进单个模型；工具链是 FunVerl，异步执行时用策略版本控制限制学生轨迹的滞后。
- **最关键的一个设计细节——说话人 token 的 loss 重加权**：统计五类 token 的 token 数与未加权 loss 占比后发现，说话人 ID 数字 token 在 loss 中占比极低（因为它太短），于是**只给说话人 ID 数字 token 设交叉熵权重 10**，时间戳、格式、转写、其他监督 token 保持权重 1。原文称这不改目标序列也不改 token 数，只调 loss 相对贡献，就显著改善了 diarization error rate（DER）与 cpWER。
- **推理优化**：流式变体做增量转写，句末再用非流式方式"刷新"一次结果；流式不支持 diarization 与通用音频理解。

## 关键结果

**中英文常规 ASR（与上一代 Qwen-Audio-3.0-ASR 对照）**

| 测试集 | 3.1 | 3.0 |
|---|---|---|
| AISHELL-1（CER） | 1.08% | 1.03% |
| AISHELL-2（CER） | 2.05% | 2.02% |
| FLEURS-zh（CER） | 2.25% | 2.08% |
| LibriSpeech-clean（WER） | 1.23% | 1.19% |
| LibriSpeech-other（WER） | 2.19% | 2.24% |
| FLEURS-en（WER） | 4.17% | 4.72% |

原文自己点明：中文与英文识别性能与上一代"大致可比"，LibriSpeech-other 取得表内最低值，FLEURS-en 是最大改善项。

**说话人分离转写**（AISHELL-4、AliMeeting-test、MLC-SLM、MagicData-RAMC 四个测试集 × DER/WER/cpWER 三个指标）
- 两个 3.1 变体在 12 个数据集—指标组合上**全部取得最低错误率**。
- 两个变体差异最大的是 AliMeeting-test 的 cpWER：Next **12.04%**，Flash **15.78%**，绝对下降 **3.74 个百分点**。
- 两个变体在四个测试集的 DER 与 cpWER 上**都优于级联的 Fun-ASR 基线**；Next 在所有八个指标上优于全部非 Qwen 系统。

**通用音频理解（Qwen-Audio-3.1-ASR-Flash-Next，对比 Gemini-3.1-Pro / Gemini-3.5-Flash / Seed-2.0-Lite）**
- MMAU 准确率 **81.60%**，比 Gemini-3.1-Pro 高 **0.70 个百分点**（后者 80.90%）。
- MMSU **82.24%**，落后最好成绩 **3.06 个百分点**（Gemini-3.1-Pro 85.30%）。
- 专项任务全部第一：CochlScene 76.30、Nonspeech7k 93.20、MELD 58.12、NSynth 66.90、DiDiSpeech 99.67。
- 时间定位（mIoU）：Clotho-Moment 82.20、DESED 66.60。
- 九个基准中取得七个最佳。

## 范式对比

- **对 OpenAI Whisper / 传统 ASR 厂商**：传统路线是声学模型 + 语言模型 + 分离模块拼装，能力边界靠换模块来扩展；Qwen 这条是把所有子任务塞进一个解码器的输出空间，靠**训练信号设计**（权重、教师路由、数据配比）来扩展。好处是消除级联误差，坏处是任何新能力都得回到训练管线里做。
- **对豆包 / 腾讯**：原文的对照表里直接放了 Seed-2.0-Lite 与 Gemini 系列。中文方言和说话人分离这块是国内厂商的主战场，Qwen 的差异化不在 MMAU 这种通识音频理解（那里只赢 0.7 个百分点，且 MMSU 还落后），而在 diarized ASR 的结构化输出和级联基线的对比上。
- **对 Qwen 自家的 Qwen3-Omni**：Omni 走的是更宽的模态统一，这条线走的是单一模态内的深度（转写 → 结构化转写 → 音频理解）。集团内部两条并行路线，说明"统一多模态"和"单模态做到生产级"的取舍还没收敛。
- **对 MiniMax / Kimi 这类带宽竞争**：没有可比性。这是一份语音工程报告，卖的是延迟、错误率、方言覆盖和每 token 成本，不是智能上限。

**产品侧备注（非本报告内容）**：Qwen-Audio-3.1 系列（含 ASR / TTS / Realtime 与两个 Next 变体）在 2026-09-23 的云栖大会上以产品形式发布，国内媒体有报道；本页所有技术数据只取自 arXiv 技术报告，不引用发布会数据。

## 社区评价

中文技术社区对这份报告的主要讨论点有两个。一是"六阶段训练 + MOPD"的复杂度——把多教师蒸馏放在最后收口，说明前面各阶段是分工训练、能力有冲突，靠蒸馏和解；这对想复现的团队门槛很高。二是说话人 token 重加权这个 trick 被反复单独拎出来：它是一个几乎零成本的改动（不动结构、不动数据），换来了 DER/cpWER 的显著改善，被认为是"先做 loss 分析再改模型"的正面案例。批评意见集中在流式变体砍掉 diarization——真实会议场景恰恰最需要流式 + 说话人，这个组合目前没有。

## 可复用的工程经验

1. **先算 loss 占比，再改架构**。说话人 ID token 数量少、在 loss 里占比低，模型自然学不好。给稀有但关键的监督 token 加权（这里 10 倍），比加模块便宜得多。任何序列标注/结构化输出任务都该先做这一步统计。
2. **能不能冻结基础模型，是成本和效果的旋钮**。这份报告里编码器和 adapter 全程可训，LLM 在预训练阶段冻结、SFT 阶段只走 LoRA。这样做既保住语言能力，又把训练成本压到可接受。想给已有大模型加一种新输入模态时，这是最稳的默认姿势。
3. **编码器初始化可以借语言模型**。用预训练 LLM 的兼容 Transformer 层初始化音频编码器，再用 BEST-RQ 做自监督、AED 做有监督。跨模态初始化比从零训编码器少走很多路，前提是层结构对齐。
4. **流式与非流式不要强行统一**。这里的处理是流式给增量结果、句末用非流式"刷新"，并且明确声明流式不具备 diarization 与音频理解。把能力边界写进变体表，比让所有变体都"什么都能干但都一般"更工程。
5. **级联基线必须自己重跑**。报告里把基线分 Panel A（取原文数字）与 Panel B（统一 API 管道重跑），并声明两者不可横比。做对比评测时这条纪律能省掉大量错读。
6. **蒸馏用来收口，不用来替代训练**。MOPD 放在六阶段的最后，作用是把多个教师的能力合并进一个可部署模型，而不是用蒸馏省掉前面五个阶段。
