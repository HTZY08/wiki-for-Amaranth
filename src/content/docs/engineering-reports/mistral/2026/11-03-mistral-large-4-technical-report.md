# Mistral Large 4 技术报告：一次被 perplexity 骗过的架构决策

**发布日期：** 2026-11-03（技术报告提交；权重已于 2026-10-29 开放）
**来源：** https://www.alphaxiv.org/abs/2611.mistral-large-4
**工程范式：** 用**agentic 评测反过来驱动架构决策**——先做省显存的注意力简化，发现 LLM loss 看不出来但长程 agent 任务掉分，于是对已训练模型做"外科手术"改回长上下文，再用稀疏注意力把成本压回去；报告的价值不在分数，而在这条被公开的返工路径。

> 说明：本文分析的是 11 月 3 日提交的**技术报告**，与本目录 `10-06-mistral-large-4-le-chonk.md`（10 月 6 日预览博文）不是同一份材料。两者数字口径不同，正文会标出是哪份来源。

## 设计哲学

报告的摘要只有三段，但结构很能说明这家的取舍：模型规格（52B 激活 / 1T 总参多模态 MoE）→ **可执行环境的自动生产管线**（agent 生成并验证软件工程、网络安全、知识工作的可执行任务）→ 服务侧（稀疏注意力 + 上下文并行 + PD 分离 + 投机解码 + NVFP4 量化）。

也就是说，Mistral 把"数据从哪来"和"怎么便宜地跑起来"放在与模型规格同等的位置。真正的核心结论藏在方法论里：**架构变体在语言建模 loss 上几乎不可区分，但在长程 agent 任务上能差出十几分**（论文 p6 的 Figure 5 右图：perplexity 相近，SWE-bench Verified 分散）。

放弃的是什么？放弃了"用 perplexity 做架构消融"这条行业默认捷径，代价是每换一次架构就得跑一遍昂贵的 agentic 评测。

## 关键架构决策

**第一版：三层省显存叠加（后被部分回退）**

- **Ragged MLA**：每 4 层里有 1 层用全局注意力，其余层用 **512 token 滑动窗口**。
- **Cross-layer attention (CLA)**：让某层直接复用前面全局注意力层的 KV cache。
- **YOCO**：网络后半段的全局注意力层复用前半段的 KV 值。
- 三者叠加把 KV cache 相对全注意力基线**压到 1/16**；YOCO 还允许两阶段预填充，官方在自建基准上测得 1M 上下文下**预填充快 1.7×**（论文 p4）。

**发现的问题：agentic penalty**

早期预训练与后训练评测"影响不大或可接受"，但**监督微调后的长上下文 agent 任务明显弱于预期**（p4）。同样的 perplexity，SWE-bench Verified 分数却散开（p6）——作者把这称为架构选择带来的"agentic penalty"，并指出知识类评测没有出现同样的落差，且更长的训练可以缓解。

**修复：对已训练模型做手术，而不是从头重训**

- 去掉受影响层的滑动窗口限制，让它能看到完整上下文；
- 去掉 CLA 共享，从前面某个长注意力层**复制 KV 产生权重**补回来；
- 小算力规模下也试过连 YOCO 一起去掉；**全尺寸模型选择保留 YOCO**（更大规模下"手术 + midtraining"的对照支持保留，但作者说明该对照无法重跑完整的 phase-2 + midtraining 日程，p7）。
- **最终架构**：无滑动窗口、无 CLA、保留后半段原全局注意力层之间的 YOCO 共享，并加入 **LeRoPE** 与 **SSMax**（p7）。

**第二步稀疏化：引入 DSA 把成本压回去**

- 借鉴 DeepSeek Sparse Attention：轻量 indexer 为每个 query 选 **top-2,048 个 key token**。
- 训练分两段：先冻结主模型、用全注意力跑 **约 15.1B token** 蒸馏注意力分布来热身 indexer；再让 indexer 与主模型在稀疏注意力下联合训练 **198B token**（p8）。
- 原滑动窗口层在指定分组内**共享同一个 indexer** 以降低开销（p9）。
- 作者明确定性：稀疏化是**降长上下文注意力的成本**，并没有证明相对全注意力带来 agent 能力增益。

**可执行任务的数据管线**

agent 把种子扩写成候选可执行任务 → 廉价检查（LLM judge、极性检查）→ 昂贵检查（agentic verifier、reward hacking 检查）→ **难度标定** → 接受。失败任务带反馈回到种子，但**未通过初筛的种子直接丢弃**（p9–p10）。作者也承认 agent 会出错，部分领域需要事后调整与过滤。

**Post-training 与三档推理强度**

- **多教师蒸馏**产出 high / medium / low 三档推理强度，让用户按 token 消耗换性能。
- 权重发布后额外约三周 RL，官方口径是带来更高效的推理与更低推理成本（释放说明，非本报告正文）。

## 关键结果

技术报告口径（摘要 + 正文表格）：

- **FrontierCode 2.0（Cognition）：19.7%**，同一表格中 DeepSeek V4.1-Flash 1017 为 **19.3%**（p19）。
- **Terminal-Bench 4.0：41%**。
- **Artificial Analysis Cyber Index：50.9%**。
- **服务侧（最值得抄的部分）**：校准后的混合精度 **NVFP4 checkpoint 606 GB**，官方称与 FP8 参考在评测上持平，**可在 4 张 GB300 上部署**（p21）。在 50K 输入长度、8 并发条件下，优化后的 decode 上下文并行把 **decode 交互性提升 51%**，投机解码 **DSpark 提升 90%**（相对未投机解码基线，p20–p21）。基线配置是 FP8 + 现成上下文并行、8×GB300。

对照组口径提醒：

- 10 月 6 日预览博文报的 Terminal-Bench 4.0 是 **28.3%**，权重发布后为 **41%**（Mistral 释放说明 + 第三方转述）。跨版本比提升幅度可以，但不要把两个版本的分数混进同一张表。
- **参数口径有两套**：模型卡写 **49B 激活 / 52B 含 embedding 与输出层**，技术报告摘要在标题层写 **52B active**。引用时必须带口径。

## 范式对比

- **对 DeepSeek**：DSA 是 DeepSeek 在 V3.2-Exp 上提出并用 continued training 实现的；Mistral 这里是**先恢复全注意力、再重新引入 DSA**，而且 indexer 先用全注意力蒸馏热身。同一个技术在不同返工路径里的位置完全不同——DeepSeek 用它换长上下文效率，Mistral 用它把"为了 agent 能力付出的显存"再买回来。
- **对 Kimi / GLM**：那两家走"底座冻结、只加后训练"；Mistral 是从零预训练 1T 再返工架构。前者迭代快、上限受基座限制，后者成本高但可以把架构错误改掉。
- **对 Gemini 4 Carbon**：DeepMind 的做法是同底座靠后训练偏置出多个型号（见本 wiki `11-10-gemini-4-carbon.md`）；Mistral 的整份报告本质上是在论证"底座架构选错了，agent 评测才发现"。两条路线对"架构 vs 后训练谁更重要"给出了相反的回答。
- **对 Anthropic/OpenAI**：三家都没公开这种"我们改错了架构又手术修回来"的返工记录。这份报告最大的差异不在技术，在坦白程度。

## 社区评价

αrxiv 页面上唯一有实质内容的公开讨论（评论者 Andrei Parfenov）聚焦在**任务难度标定**：报告用 solver 通过率设难度、再用 RL 轨迹修复坏任务，提问者追问"模型变强后会不会同步更新任务难度，还是只用于修坏题"。作者未在该页公开回应。HN / Reddit 的讨论集中在权重体积与部署硬件门槛（八卡起步、FP8 权重约 1.06 TB），未见针对 agentic penalty 的技术性反驳。

## 可复用的工程经验

1. **架构消融必须用 agentic 评测，别用 perplexity/LM loss**。同一 loss 下 SWE-bench Verified 能散开，这条结论可以直接省掉一次错误的技术选型。
2. **KV 压缩的代价可能延迟出现**。滑动窗口 + 跨层共享在预训练与通用评测上"看不出问题"，是在 SFT 之后的长程任务上才暴露。
3. **"模型手术 + midtraining"是比从头重训便宜的纠错路径**：恢复注意力范围 + 从相邻层复制 KV 产生权重，能把一个训好的模型救回来。
4. **稀疏注意力的 indexer 要先用全注意力蒸馏预热，再联合训练**（15.1B 热身 + 198B 联合），否则稀疏从一开始就限制了注意力分布的学习。
5. **量化换硬件比优化 kernel 更划算**：NVFP4 把 checkpoint 压到 606 GB，直接把机型门槛从 8 卡降到 4 卡，且在自有评测上与 FP8 持平。
6. **报"每天可训 token 数"和"压力档位下的交互性提升"** 这类产能/服务指标，比报卡数更能说明工程水平。
7. **多档推理强度用多教师蒸馏做**，一次训练出三档，比训三个模型或让用户靠 prompt 控制更可控。
