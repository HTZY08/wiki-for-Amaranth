# Mistral Large 4：欧洲算力 + 开放权重 + 拒绝率即特性

**发布日期：** 2026-10-06（公开预览）；权重 2026-10-29 放出
**来源：** https://mistral.ai/news/mistral-large-4
**工程范式：** 不做最大最强，做"能力 + 主权 + 自部署"的组合——用自有欧洲数据中心训练，把安全拒答视为可配置的策略而非硬约束。

## 设计哲学

Mistral 的定位很明确：1T 参数、原生多模态、开放权重，训练在**自有欧洲数据中心的 3,800 张 NVIDIA Grace Blackwell** 上完成，预览服务也跑在同一套基础设施上。官方把"AI 主权"写进标题——重点是"客户能自己跑、自己控策略"。

最能说明其取舍的是网络安全这一节：官方称若干闭源模型（点名 Claude Opus 5.5、GPT-6 Astra）在同一"复现漏洞并修补"的测试上得分接近零，因为**拒答**；而防御方的工作恰恰从"证明漏洞是真的"开始。ML4 选择在这些任务上不拒答，把风险通过开放权重 + 自部署 + 分级合作（给受审伙伴与国家机关更低审核、更宽 cyber 能力的版本）来管理。

代价同样清楚：开放权重意味着能力外溢不可回收；Mistral 的应对是许可分层（Mistral Ecosystem Open-Weight License，商用 model-as-a-service 需另签）。

## 关键架构决策

- **规模**：1T 总参、**52B 激活**（官方博文口径；权重发布后的第三方资料多写 49B 激活、含 embedding/输出层约 52B，两者口径不同，引用时需说明）。1M 上下文，原生多模态。
- **训练**：从零训练，3,800 张 Grace Blackwell，自有欧洲数据中心；训练数据多语种，覆盖 **160+ 种语言**（含全部欧盟官方语言）。
- **RL 工程**：共享可组合接口，把单轮对话、科学问题求解、安全对齐、事实性、长程工具使用放进同一次训练；验证侧用 reward model、单测、LLM judge、静态检查自由组合；runtime 用自动扩缩的 actor 集群并行生成数万条 rollout，训练异步进行；针对长轨迹优化（支持数百万 token 的 rollout 预算与多次 compaction），压低 staleness 与 off-policy 漂移。**3k GPU 规模下单次训练每天约产 330 亿 token，过滤掩码后可训约 160 亿。**
- **与客户环境同构**：官方称模型使用与 Mistral Forge 客户相同的训练/定制/RL 环境——这解释了它为什么强调企业垂直场景。

## 关键结果

（均为官方博文自报，2026-10-06 预览口径）

- 编码：DeepSWE v1.1 **61.7%**，SWE-Atlas-QnA **59.4%**，Terminal-Bench 4.0 **28.3%**；综合 Coding Agent Index **49.8%**，官方称领先 DeepSeek V4 Pro 0813 与 Qwen3.8 Max。
- Agent 工作流：AutomationBench（657 条跨 Gmail/Sheets/Slack/Salesforce 的业务流）**59.9%**，官方称领先 Kimi K3、MiMo-V2.6-Pro、DeepSeek V4 Pro。
- 知识工作：AA-Briefcase **1,393 Elo**，领先 DeepSeek V4 Pro；Harvey 法律 Agent 基准上优于所有开源模型；金融/法律两项经第三方 vals.ai 评测超过 GPT-6 Astra。
- 网络安全：AA Cyber Index 全球前五、非中国开源模型第一；"复现并修补"测试 **82%**（全模型最高）；Cybench **93%**。
- 多模态：Dense 200 视觉定位 **42%** vs GPT-6 Astra **41%**。
- 人工盲评（Surge AI，1–5 分，匿名）：ML4 Preview **3.74**，排第二（Kimi K3 3.59、GLM-5.3 3.60、GLM-5.2 3.40、Claude Opus 5 4.22 第一）。

## 范式对比

在 2026 年的开源阵营里，三家路线互不重叠：GLM-5.3 只做后训练、靠环境；Kimi K3.1 Pro 只做后训练、靠 RL 吞吐；Mistral 则从零预训练一个 1T 模型并且坚持欧洲自建算力。代价是投入巨大（€3B D 轮），收益是"不依赖任何第三方云"的叙事在欧洲政企市场成立。

另一个关键差异是**安全策略的位置**：Anthropic 把护栏做成准入分层，OpenAI 做成运行时监控，Mistral 做成可部署在客户侧的策略配置。三种选择对应三种商业模式，不是单纯的技术差异。

## 社区评价

发布后讨论集中在两处：一是参数口径（1T/52B 与 1.05T/49B 的差异），二是"拒答率低"是否等于"更危险"。官方在博文中把低拒答定位为防御方刚需，社区对此分歧明显，未有共识。

## 可复用的工程经验

1. **安全拒答是一项策略配置，不是模型属性**。对有合法双重用途的场景，可配置的拒绝边界比统一硬拒更有用。
2. **RL 环境与客户环境同构**能直接转化为垂直场景表现——训练栈即产品。
3. **长轨迹 RL 的关键是 staleness 控制**：异步 + compaction + 数百万 token 的 rollout 预算，要一起设计。
4. **报"每天可训 token 数"** 这类产能指标，比报卡数更能说明训练工程水平。
5. **权重开放要配许可分层**：开源权重 + 商用 MaaS 另签，是当前最现实的折中。
