# 拆开视觉编码器：三个被捆绑的设计选择，只有一个真正重要

**发布日期：** 2026-11-13（Meta AI 研究页标注；arXiv 编号 2611.17334）
**来源：** https://arxiv.org/abs/2611.17334 ｜项目页 https://unbundling.github.io ｜研究页 https://ai.meta.com/research/publications/unbundling-multimodal-vision-encoding
**工程范式：** 不发模型，发**可分离的设计空间**——把所有模型从随机初始化开始、用同一份数据与同一套配方重训一遍，在"匹配生命周期算力"的前提下一次只改一个变量，把"用预训练视觉编码器"这个行业默认拆成三个独立假设逐一证伪或证实。

## 设计哲学

业界对多模态模型的视觉编码方式长期有两派：用预训练视觉编码器（SigLIP/MetaCLIP 这类），或干脆去掉编码器（encoder-free，图像 patch 直接线性投影进主干）。争论之所以打不完，是因为已发表模型在数据、架构、训练阶段、算力上全都不一样，比分数比不出任何结论。

这篇论文的贡献是先把问题拆开。视觉编码器其实捆绑了**三个**选择：

- **视觉先验**：来自上游单独预训练（图像识别 / 图文对齐目标）
- **专用容量**：只有视觉 token 会用到的那部分参数
- **融合前放置**：这部分容量放在与文本交互之前

由此得到四种配方：

| 配方 | 视觉先验 | 专用容量 | 融合前放置 |
| --- | --- | --- | --- |
| 预训练编码器 | ✓ | ✓ | ✓ |
| 从零联合训练编码器 | ✗ | ✓ | ✓ |
| Encoder-free | ✗ | ✗ | ✗ |
| In-fusion（融合内） | ✗ | ✓ | ✗ |

控制协议很硬：所有模型**从随机初始化开始自己跑完每个训练阶段**，同一批文本与图文对（图像 224×224），固定生命周期算力预算；评测用 16 个 Cambrian 基准的类别均值（Avg. VQA，指令微调用 Cambrian-7M、448×448）与 12 个语言基准均值（Avg. Text）。这样做的好处是每个配方都为它的全部算力付账——包括别人通常当成"免费"的编码器预训练（论文点名 SigLIP 2 训练用了 400 亿图文样本）。

## 关键架构决策与实验结论

**结论一：视觉先验可省。** 与主干联合从零训练的编码器，和在同一数据上预训练的编码器**打平**。MetaCLIP 在 1.7B 与 4B 主干上**每个算力预算都落后于从零编码器**，4B 最大预算处落后 **1.8 Avg. VQA 分**。更长的编码器预训练（即使不计入预算）能提高 ImageNet 准确率，但**不提高 VQA**。

**结论二：专用容量是必须的。** Encoder-free 在 Avg. VQA 上落后：1.7B 主干落后 **4.1–6.4 分**，4B 主干落后 **2.8–6.8 分**；从 1.7B 到 6.4B 主干，encoder-free 大约需要 **3× 算力**才能追平带编码器的 Avg. VQA。

这个差距**不能**用"编码器多了参数"解释：把编码器那 **0.4B** 参数以加宽、加深、或两者兼有的方式送给 encoder-free 主干，Avg. Text 会涨（文本 token 也用得上），Avg. VQA **最多只动 0.4 分**。换更丰富的 patch embedding 也不行——受 Gemma 4 启发的两层投影得 40.5，线性默认 39.0，编码器 44.4；Inkling 那种四层分层 MLP 只有在把 640×640 图像压到同样 256 个 token 时才追平编码器。

**结论三：这份容量可以搬到融合之内。** 把编码器的 0.4B 参数预算搬进主干、做成**只用视觉 token 的模块**（in-fusion，FFN-only 变体省略视觉专用注意力投影），放在**前 8 层**时可以追平甚至略超从零编码器：**45.0 vs 44.4** Avg. VQA。放置位置极其关键——同样的容量放在别处，表现不比 encoder-free 好。前 8 层的好处在对细节敏感的任务上最明显：OCR 与图表题 **36.0**，encoder-free 为 **25.2**。

与 Mixture-of-Transformers (MoT) 的对照更能说明"位置"比"结构"重要：把 in-fusion 方案加到预训练好的 1.7B 语言模型上，MoT 复制前 8 层得 **48.5**，in-fusion 得 **50.1**；而 MoT 复制**每一层**只有 **43.3**，且用掉 **3.5×** 的视觉专用参数。

**结论四：换到 midtraining 设定仍然成立。** 把自己的 1.7B 纯文本模型从 1T 续训到 **1.33T token 当量**，在等算力下加入各配方：in-fusion **50.1**、从零编码器 **48.6**、encoder-free **39.8**。

**首 token 延迟的额外收益**：在 0.4B 容量下，in-fusion 只增加 **37 ms** 的 TTFT，预训练编码器增加 **64 ms**，而复制所有层的 MoT 增加 **100 ms**。视觉容量放进融合，反而比放在融合之前更快。

## 关键结果汇总

| 配方 | Avg. VQA（1.7B 主干，等算力） | 备注 |
| --- | --- | --- |
| 从零联合训练编码器 | 44.4 | 基准线 |
| In-fusion（视觉专用 FFN 分支，前 8 层） | **45.0** | 略超基准线，TTFT +37 ms |
| Encoder-free | 落后 4.1–6.4 分 | 需约 3× 算力追平 |
| MetaCLIP 预训练编码器 | 落后（4B 预算处 −1.8） | 预训练算力若不计入预算仍不占优 |

在预训练语言模型上续训的对照组：in-fusion 50.1 / 从零编码器 48.6 / encoder-free 39.8 / MoT 前 8 层 48.5 / MoT 全层 43.3。

## 范式对比

这篇论文顺手解释了一个社区争论：为什么有些研究说 encoder-free 与编码器持平甚至更好？作者给了两个方法学原因——（1）那些实验给编码器用了**更低的学习率**，而在本文的复现里这会抹掉编码器的大部分或全部领先；（2）它们用文本/交错/描述数据的**平均验证 loss** 做缩放律拟合，而这个指标对视觉处理设计不敏感：到 1.7B 为止，平均验证 loss 只能把编码器与 encoder-free 分开 **0.05 nats**，而留出集描述 loss 能分开 **0.24 nats**，且与 Avg. VQA 趋势一致。

与同业路线的对照也因此清晰：Kimi K3 是"从零训编码器"（对应本文的 scratch encoder，结论支持）；Gemma 4 与一些 encoder-free 方案在本框架里属于"去掉专用容量"，正是本文认为会掉分的那条；Inkling 的四层分层 MLP 在论文里被归为"仍属视觉专用容量"，只有压缩比足够高时才追平编码器。换言之，各家标榜的"encoder-free"往往并不是真的没有视觉专用参数。

## 可复用的工程经验

1. **做架构选择时，对照组要按"设计选择"拆，而不是按"现成模型"比**。同一批数据、同一配方、同一算力预算下只改一个变量，才谈得上归因。
2. **别把编码器预训练算成免费**。在固定生命周期预算下，单独预训练编码器是**纯亏**：同一份算力直接喂给多模态联合训练更划算。
3. **视觉必须有专属参数**。想省参数去做 encoder-free，代价是约 3× 算力；把编码器的参数量补给主干并不能替代专用容量。
4. **专用容量放前面。** 前 8 层的视觉专用 FFN 分支即可追平融合前编码器；放晚了等于白加。
5. **想省首 token 延迟就把视觉容量搬进融合**（37 ms vs 64 ms），同时注意别用"每层都复制"的 MoT——参数量与延迟都不划算。
6. **选对评测指标比选对模型更重要。** 平均验证 loss 对视觉设计不敏感（0.05 nats），留出集描述 loss 才跟 VQA 一致（0.24 nats）。做多模态消融时，先确认你的 loss 对这个变量有分辨力。
