# MiniMax M3 技术预览 — 稀疏注意力驱动的全栈开源前沿模型

**发布日期：** 2026-07-24
**来源：** https://www.minimax.io/blog/minimax-m3
**工程范式：** 以稀疏注意力架构（MSA）为基石，将超长上下文（1M token）、前沿编码能力和原生多模态合为一体，走先开源后报告的快速迭代路线。

> **说明：** 本文基于 MiniMax 官方技术博客撰写。完整技术报告将在未来 10 天内发布，届时将开源模型权重。

## 设计哲学

MiniMax M3 的核心约束是：**在单一模型中同时解决长上下文、编码/Agent 能力和多模态三个表 stakes 需求**，且必须做开源权重模型。这意味着架构必须在推理效率上做到质的飞跃——不能靠堆算力来弥补长上下文的复杂度爆炸。

面对这一约束，MiniMax 的选择是从最底层——注意力机制——重构。他们没有沿用全注意力（Full Attention）的路径，因为其二次复杂度在 1M token 上下文中不可承受。他们的答案是 **MSA（MiniMax Sparse Attention）**——一种新的稀疏注意力架构，将 1M 上下文的每 token 计算量降到前代模型的 1/20。

**放弃了什么？** 放弃了对全注意力在随机 token 上完美对齐的追求——MSA 在绝大多数能力上匹配全注意力，但承认在某些极端场景可能有微小差距。这是工程上的权衡：保留 99% 的能力，换来 20× 的计算节省。

## 关键架构决策

### 注意力机制：MSA（MiniMax Sparse Attention）

MSA 是 M3 最核心的架构创新。其核心思路是**在注意力计算前增加预过滤阶段**：

- **块级 KV 分区**：相比于 DSA、MoBA 等方法，MSA 能以更细的粒度对 KV 进行分块，实现更高的有效上下文覆盖率
- **KV 外循环 Q 内聚**（"KV outer gather Q"）：以 KV 块作为外层循环，聚合命中该块的查询。每个块只读一次，内存访问连续
- **在 M3 的 head 配置下**，算术强度显著优于常见方法，比开源的 Flash-Sparse-Attention 和 flash-moba 快 4× 以上

**实际效果（1M 上下文）：**
- Prefill 阶段加速：9× 以上
- Decode 阶段加速：15× 以上
- 每 token 计算量：前代模型的 1/20
- 多轮消融实验：MSA 在绝大多数能力上匹配全注意力

### MoE 设计

- M3 延续 MiniMax M2 系列的 MoE 路线，但具体专家数/粒度/路由机制未在博客中披露（等待正式技术报告）
- 从 benchmark 表现推断，激活参数规模应在 M2.7（2.7T 总参数）的基础上优化

### 原生多模态训练

- **从 Step 0 开始混合模态训练**：不同于先训练语言模型再拼接视觉 encoder 的方案，M3 在预训练之初就将多模态数据纳入训练
- 跨模态语义空间自然融合，而非后期对齐
- 交错的（interleaved）多模态数据比合成数据更容易扩展——为此 M3 重新设计了整个文本预训练数据处理流程，生产了大量交错数据

### 训练策略

- Prefill 和 Decode 阶段的详细训练配置未在博客中披露（等待正式技术报告）
- 使用了交互式用户模拟器框架来缩小 benchmark 与生产环境的差距，在训练和评估中模拟真实开发者的协作行为模式（需求细化、方案讨论、反馈纠偏、连续任务切换、复杂项目迭代）

### 推理优化

- MSA 自身提供 15× decode 加速
- MiniMax Code Agent 配套使用 Producer + Verifier 对抗环（adversarial harness loop），支持数天无人干预的持续运行
- 模型支持 Thinking 开关切换，两种模式共享定价

### Post-training

- 交互式用户模拟器不仅用于评估，也用于训练——模拟真实开发者的协作行为，让 Agent 不再被动执行指令，而是主动与用户协作完成任务

## 可复用的工程经验

1. **从架构层面解决上下文扩展问题**：M3 的路线是不在已有全注意力架构上打补丁，而是重新设计注意力机制。当二次复杂度成为瓶颈时，这是根本性的解法。

2. **KV 外循环 Q 内聚的算子优化思路**：以 KV 块为外层循环，每块只读一次、内存连续访问——这个思路在稀疏注意力场景下通用有效，可复用到其他稀疏注意力实现中。

3. **交互式用户模拟器用于训练/评估数据生产**：用模拟器生成更接近真实场景的训练数据，而非仅依赖静态 benchmark——这个思路对于 Agent 能力的提升具有普适性。

4. **原生多模态优于后期拼接**：从 Step 0 开始混合模态训练让语义空间自然融合，避免了后期对齐的性能损失和工程复杂度。

5. **对抗环式 Agent 架构**：Producer + Verifier 的自我纠错框架是可以跨模型复用的 Agent 设计模式，适合需要长期稳定运行的复杂任务。
