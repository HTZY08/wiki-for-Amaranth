## 架构决策

### 为什么不做第二台微信主机？

| 原因 | 说明 |
|:----|:-----|
| 笔记本非 7×24 运行 | 随时关机带走，不适合做常驻服务 |
| 微信网关占用大 | 单实例 ~1.5-2GB 内存，与 GPU 计算抢资源 |
| 管理复杂度 | 双微信实例需要 iLink 双 bot + 双 token 维护 |
| 记忆碎片化 | 两个 hindsight.db 无法自动合并 |

**决策**：云服务器是"大脑"（24h 在线 + 微信 + 记忆），笔记本只做"肌肉"（GPU 计算）。

### 同步方案

| 同步内容 | 方案 | 方向 |
|:--------|:----|:----|
| skills/ | GitHub 私有仓库 `hermes-config` | 双向同步 |
| vault/ | GitHub 私有仓库 | 双向同步 |

## 踩坑记录

### Docker Desktop 下载失败

**症状**：从 docker.com 下载卡住/报错
**根因**：PowerShell 默认仅 TLS 1.0，Docker 要求 TLS 1.2+
**修复**：
```powershell
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
```
**或**：从阿里云镜像站下载（推荐，国内直连更快）

### DeepSeek base_url 错写

**症状**：`hermes chat` 报连接错误
**根因**：base_url 写成了 `https://api.deepseek.com.ai/v1`（多了 `.ai`）
**修复**：改为 `https://api.deepseek.com/v1`

新版 config.yaml 中 DeepSeek 配置：
```yaml
providers:
  deepseek:
    base_url: https://api.deepseek.com/v1
    key_env: DEEPSEEK_API_KEY
```

### Docker 数据迁移

**背景**：WSL2 的 Docker 默认数据在 C 盘，占用系统盘空间。
**新版 Docker Desktop 的变化**：不再暴露 `docker-desktop-data` 作为独立 WSL 发行版，无法用 `wsl --export/--import` 迁移。
**修复**：在 Docker Desktop 设置 → Resources → Advanced → Disk image location，直接设为 D 盘路径。
