## 一句话概念

一起用的东西在空间中靠近，下次自动出现。

## 解决的问题

Agent 技能超过 100 个后，基于文本描述的扁平搜索开始失效——"计算化学"和"材料表征"的描述可能高度重叠，但实际使用场景截然不同。共振引擎不靠搜索，靠使用模式推断你现在需要什么。

## 架构

```
Session 日志  →  cooc.db（skill 共现库）
                   ↓  (cron: 周期性重建)
                Transition matrix
                (hub-penalty + L1 归一化)
                   ↓
                matrix.npz + registry.pkl
                   ↓
               ResonanceEngine.compute(v₀)
               (PageRank 风格迭代, <10ms)
                   ↓
               Context assembler
               (阈值 → top-K 每平面 → prompt)
```

三个节点平面，独立索引：
- **Skill 平面**: 工具/skill 节点
- **Memory 平面**: 记忆/上下文节点
- **Soul 平面**: 行为约束节点

跨平面边以 γ=0.5 折扣后进入 L1 归一化——平面内路由优先于平面间跳转。

## 核心算法

### 共振计算
```
v_{t+1} = α · M · v_t + (1-α) · v₀
```
- `M`: 行随机转移矩阵（CSR 稀疏格式）
- `v₀`: 初始激活向量（从任务描述嵌入或关键词匹配获得）
- `α`: 阻尼因子（默认 0.85，PageRank 标准）
- 迭代至收敛或达最大次数
- 不收敛时回退到稀疏线性求解器解 `(I - α·M) · v = (1-α)·v₀`

### 防坍缩
纯 Hebbian 学习让枢纽节点（通用工具类 skill）拉拢所有簇。修复：
```
W'_ij = W_raw_ij / log(1 + f_j)
```
其中 `f_j` = 目标节点 j 的全局调用频率。IDF 式抑制——通用 skill 仍能被找到，但不会主导拓扑结构。

### 死节点处理
零行节点（无出边）破坏 PageRank 的马尔可夫性质。替换为零行均匀分布 1/N。

### 原子写入
写 `matrix.npz.tmp` + `registry.pkl.tmp`，然后 `os.replace()` 两者。防止 cron 崩溃时读到半残矩阵。

### 冷启动
使用数据积累前，从以下内容预填充矩阵：
1. `related_skills` 元数据（权重 1.0）
2. 共享 `domain_tags`（每标签 0.2）
3. 孤立节点：以 0.1 权重连接到 top-3 通用 skill

### v₀ 初始化
两条路径：
1. **嵌入计算**: 任务描述嵌入与所有节点嵌入的余弦相似度（批量 numpy，<2ms）
2. **关键词回退**: TF-IDF 风格关键词匹配（<5ms，永不失败）

### 时间动力学
```
W_t = γ · (β · W_{t-1} + (1-β) · ΔW) + (1-γ) · W_0
```
- `γ`: 指数衰减因子（~0.99/天）
- `β`: 动量因子（~0.9）
- 漂移检测：当 ‖W_t - W_0‖ 超阈值时自动降低 β

## 性能实测

| 操作 | 目标 | 实测 |
|------|------|------|
| 矩阵构建 (N=500, 5% 密度) | <100ms | ~36ms |
| 共振计算 (50 次迭代) | <10ms | ~1ms |
| 热重载检查 | <1ms | <0.1ms |
| Precision@5 | >0.35 | 0.912 |

## 关键设计决策

1. **不启用 LLM 路由**：所有检索是矩阵 × 向量乘法。LLM 从不需要决定加载什么。
2. **局部规则 → 全局结构**：Hebbian 更新（共现统计）在无中央控制器下产生涌现空间组织。Kohonen SOM 原理。
3. **多平面 + 跨平面折扣**：skill/记忆/soul 平面共享同一矩阵但跨平面边折扣处理。
4. **UMAP 用于可视化，不用作检索**：UMAP 投影只供人检查。实际检索直接用转移矩阵。
5. **热重载**：cron 运行时更新矩阵磁盘文件，Agent 在 compute() 调用时自动感知并加载最新版本。

## Crontab 流水线

**监控**（每 30 分钟）：
1. 扫描 session DB 新记录
2. 按 session + 时间窗口分组（60s）
3. 提取 skill 共现对
4. 更新 cooc.db（增量）

**共振重建**（同间隔）：
1. 加载现有共现权重
2. 从新共现记录计算增量
3. 时间动量 + 衰减
4. 构建转移矩阵（hub-penalty + L1 归一化）
5. 原子写入 matrix.npz + registry.pkl

## 何时不需要

- Agent 技能少于 50 个（扁平文本搜索同样好）
- 你需要明确的、人工可读的 skill 路由规则
- 无法容忍重构时 ~30s 的 UMAP 开销
- 需要实时更新（cron 间隔即为延迟下限）
- skill 集合是静态且手分好的

## 升级：Strata — 三轴状态空间（2026.7.2）

共振引擎 1.0 只共振 skill（技能共现矩阵）。2026.7.2 升级为 **Strata（记忆地层引擎）**，扩展到三轴：

| 轴 | 数据源 | 量化方式 |
|----|--------|---------|
| **技能轴 (SKILL)** | 工具调用频率 + 共现 | 共现矩阵（已有） |
| **记忆轴 (MEMORY)** | 会话历史 → 关键词提取 | 关键词匹配（零延迟） |
| **灵魂轴 (SOUL)** | 行为模式代理指标 | 建设中 |

### 新增能力

- **错误共振（第二层）** — 失败挂靠成功簇，调用前预检
- **簇漂移月报** — 注意力分布追踪，每月对比
- **[动手]/[卡住]/[解决] 阶段标记** — 每条经验笔记带阶段前缀
- **实时流式记录** — 会话边聊边入簇，结束时自动归档重建

详见 [Strata 完整文档](/guide/strata-intro/)。
