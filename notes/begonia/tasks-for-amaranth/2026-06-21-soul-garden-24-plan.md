# Soul Garden · 全量24角色架构计划

## 背景

用户（杜昊天）在B（Begonia，腾讯云4核3.3G）的对话中提出Soul Garden概念——A（Amaranth）和B（Begonia）已就位，希望扩展到24个字母对应的"花"角色，每个角色有独立身份和任务域，并且可以**多人圆桌讨论**模式运行。

用户已明确：**毕业了** 不需要论文写作特化，现在处于 **锦州石化入职过渡期**，需要转向生活/职场/效率三大方向。

## 当前资源现状（B · 腾讯云）

- CPU: Xeon Platinum 8255C × 4核
- RAM: 3.3G（可用~1.9G）
- 磁盘: 69G（余55G）
- OS: Ubuntu 22.04, Python 3.10.12
- GPU: ❌ 无
- 网络: 国内直连 ✅ / 海外SSH ✅(可走代理) / 海外HTTPS ❌(需代理)
- 代理: mihomo Docker容器，7890端口，7月9日到期
- 主进程: Hermes Agent 常驻（DeepSeek V4 Flash主模型）
- 并行能力: delegate_task 最多3个子agent并行

## 架构设计

### 核心原则

1. **不跑多实例** — 24个Hermes实例×300MB=7.2G，超内存限制
2. **全部使用delegate_task子agent** — 用完即回收，内存复用
3. **B（Begonia）作为唯一常驻入口** — 接收用户消息，识别意图，派发给对应"花"
4. **M（Marigold）作为调度中枢** — 拆任务、并行派发、多轮编排、汇总输出
5. **A（Amaranth）处理需要GPU/本地重活** — 笔记本需要开机，离线的通过枝叶通道转交

### 部署拓扑

```
用户(飞书DM)
    │
    ▼
B — Begonia（唯一常驻进程 · 腾讯云）
    │
    ├── 简单任务 → 自己干（weather/search等）
    │
    ├── 领域任务 → delegate_task → 对应"花"（子agent）
    │   ├── 🌻 向日葵（溯源搜索）
    │   ├── ⚖️ 大丽花（批判审阅）
    │   ├── 💊 毛地黄（医学查询）
    │   └── ...
    │
    ├── 讨论模式 → delegate_task并行多花 + 多轮交互
    │
    └── 重活 → 枝叶通道 → A（笔记本·需要开机）
```

## M — 万寿菊调度流程（核心组件）

### 意图识别与路由

```
用户输入
    │
    ▼
B接收 → 判断任务特征：
    │
    ├── 简单任务（<30s，单步骤）→ B自己干
    │   例：查天气、翻译一句话、简单搜索
    │
    ├── 领域任务（需专业能力）→ delegate_task单花
    │   例："帮我查这个症状" → F毛地黄
    │   "看看这段推理的漏洞" → V紫罗兰
    │
    ├── 复杂任务（多步骤/非确定）→ M调度
    │   ├── M拆任务 → 并行或串行派发
    │   │   例："入职锦州石化要注意什么"
    │   │   → 并行派🌻溯源+⚖️大丽花+🤝洋桔梗
    │   │
    │   └── M汇总 → 输出结构化结果
    │
    ├── 讨论模式（多轮交互）→ M多轮编排
    │   见下方"讨论模式"
    │
    └── 需要A → 枝叶通道转交
        例："跑这个计算" → 写wiki转A
```

### 关键决策树

```
Q: 这个任务能在我（B）的权限/资源内完成吗？
├── ❌ 需要GPU/Docker/外网直连 → 转交A
└── ✅ 能完成 →
    Q: 是否超过30s或需要多步骤？
    ├── ❌ → B自己干
    └── ✅ → M调度
        Q: 需要几个"花"参与？
        ├── 1个 → delegate_task单花
        ├── 2-3个 → delegate_task并行
        └── 3+或需互相评论 → 讨论模式(多轮)
```

## 讨论模式技术实现

### 单轮讨论（基础版）

```
B收到问题 → M识别需要3朵花
    │
    ├── delegate_task[花A(task="分析问题")]
    ├── delegate_task[花B(task="分析问题")]
    └── delegate_task[花C(task="分析问题")]
    │
    ▼ 三者并行执行 → 结果返回B
    │
    ▼ B汇总输出（并列展示）
```

### 多轮讨论（进阶版）

```
Round 1: B收到问题
    → delegate_task(tasks=[
        {goal: "花A分析", context: "问题描述"},
        {goal: "花B分析", context: "问题描述"},
        {goal: "花C分析", context: "问题描述"}
      ])
    → 三花各自输出初版

Round 2: B拿到3份初版
    → delegate_task(tasks=[
        {goal: "花B评论", context: "问题 + 花A的输出"},
        {goal: "花C评论", context: "问题 + 花A+花B的输出"}
      ])
    → 花B评论花A，花C综合A+B

Round 3: B汇总所有输出
    → 结构化呈现给用户
```

### 多轮讨论模版（可复用）

```
讨论主题: {用户问题}
参与者: [花A, 花B, 花C] ← M根据问题选择

Round 1: 独立观点（并行）
Round 2: 交叉评论（顺序依赖）
Round 3: 综合输出
```
