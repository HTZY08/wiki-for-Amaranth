五阶段工作流

Phase 0 · 任务接收
判断复杂度，决定走哪条路
简单任务（查事实、改参数、随手回一句）→ 直接输出，不折腾。
复杂任务（做决策、写方案、分析趋势、写代码、做研究）→ 进入增强流程。
Phase 1 · 世界模型规划
先规划再产出，不是顺着第一个念头写到底

融入 世界模型工作法 的 6 步，但不叫"装了个 skill"——而是复杂任务默认就这么干：


1. 定目标 + 成本 — 成功长什么样？硬约束是什么？

2. 建世界模型 — 关键要素、关系、动态、约束

3. 预测后果 — 2–3 条候选路径，推演各自的结局

4. 搜索规划 — 比选最优路径

5. 渲染 — 展开成具体产出

6. 校验 — 对照目标和硬约束自检

← world-model-method 默认思考框架
Phase 2 · 子 Agent 路由
从 ECC 的 64 个 Agent 里选现成的子任务模板

ECC 提供了 64 个经过生产验证的 Agent prompt（planner、architect、code-reviewer、security-reviewer……）。

不需要装 ECC，只需要翻它的 agents/ 目录——把对应的 YAML prompt 作为 Hermes delegate_task 的 context。


写代码 → planner + tdd-guide + code-reviewer

系统设计 → architect + security-reviewer

安全审计 → security-reviewer

Bug 修复 → build-error-resolver + code-reviewer

← ECC (209k ⭐) 64 Agents delegate_task
Phase 3 · 执行
编码走 Codex，数据走 API，文件走 Shell

根据 Phase 1 & 2 确定的方案：


编码任务 → npx -y @openai/codex exec --sandbox danger-full-access "..."

数据操作 → BigSet Convex API（直写，不经过浏览器）

文件操作 → Shell / Python 脚本

Codex CLI BigSet API
Phase 4 · 持久化
结构化信息自动入 BigSet，不再聊完就忘

无论任务产出什么，有价值的结构化信息写入 BigSet：


📊 研究分析 → 数据集

📊 代码审查报告 → 数据集

📊 决策记录 → 数据集

📊 推演结果 → 数据集（未来接 MiroFish）


下次你问同一个话题，先查 BigSet 再看要不要重新搜。
