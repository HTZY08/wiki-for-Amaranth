# MiMo-V2-Flash — 混合注意力 SWA + 多教师蒸馏的极致效率 MoE

**发布日期：** 2026年1月（arXiv 2601.02780）
**来源：** https://arxiv.org/abs/2601.02780
**工程范式：** 混合 SWA-GA 注意力 + MOPD 蒸馏 = 划算的 Agent 模型

## 设计哲学

MiMo-V2-Flash 的核心理念是 **用极致的架构效率换取性能，而非堆参数**。在小模型上也能打大模型——309B 总参数 / 15B 激活参数的 MoE，对标的是 671B/37B 的 DeepSeek-V3.2 和 1043B/32B 的 Kimi-K2。

三个设计原则贯穿始终：

1. **注意力就是成本** —— 长上下文的 KV-cache 是推理的最大瓶颈。用激进的 Sliding Window Attention + 注意汇偏置（attention sink bias）把 KV-cache 砍到接近 1/6，同时通过实验证明更小的窗口（128）比更大的窗口（512）反而更优。
2. **训练信号不浪费** —— Multi-Token Prediction (MTP) 不只是训练目标，训练完还能复用为投机解码的 draft model，分文不加地拿到 2.6× 推理加速，并加速 RL rollout。
3. **知识不需要合并参数** —— 多教师蒸馏（MOPD）不合并模型权重也不生成静态离线数据集，而是在线策略蒸馏：学生从自己的分布采样，从领域专家接收 token 级 KL 散度奖励。这解决了"跷跷板效应"——提升一个能力不会让另一个能力退步。

## 关键架构决策

### 1. 混合注意力：5:1 SWA-GA 交错

- **结构：** 48 层 Transformer，39 层 Sliding Window Attention + 9 层 Global Attention，按 5:1 交错排列（每 5 个 SWA 跟 1 个 GA），仅第一层用 GA 加 dense FFN 稳定早期表征。
- **SWA 窗口：** 128 tokens —— 相比常见 4096 窗口极其激进。实验证明 W=128 在长上下文和推理任务上全面超过 W=512，原因是小窗口强制 SWA 专注局部、GA 处理全局，形成清晰的劳动分工。
- **注意汇偏置（Attention Sink Bias）：** 每个 attention head 在 softmax 分母上加一个可学习的偏置项，让模型在必要时可以"不看"某些 token。没有这个偏置的混合 SWA 会出现明显退化，加上后甚至在推理和长上下文上超越全 GA 基线。
- **KV-cache 节省：** 约 6× 降低（5/6 的层使用 SWA，窗口仅 128，且 SWA 的 KV heads 更少）。

### 2. MoE 配置：大池子、少激活、无共享专家

- 256 个专家，每个 token 激活 8 个（top-8 routing）
- 没有 shared experts —— 架构更简洁，但依赖路由质量
- 激活参数仅 15B（总参数 309B），激活率 ~4.85%
- GQA（Grouped-Query Attention）：SWA 用 64 query heads / 8 KV heads，GA 用 64 / 4
- FP8 混合精度训练：attention output projection 和 embedding/head 保留 BF16，router 用 FP32 保证稳定性

### 3. Multi-Token Prediction (MTP)：训练加速两用

- **训练时：** 预训练阶段只挂 1 个 MTP head（不增加太多开销），后训练时复制为 3 层，联合训练多步预测。MTP loss 权重 Stage 1 为 0.3，Stage 2&3 降为 0.1。
- **推理时：** 复用为 draft model——采用 dense FFN（非 MoE）+ SWA（非 GA）= 极轻量级，每层仅 0.33B 参数。
- **加速效果：** 3 层 MTP 下平均接受长度最高 3.6 tokens（代码生成场景），解码加速最高 2.6×。接受长度与 next-token 交叉熵呈强负相关（R²=0.995），低熵场景（如 WebDev 代码生成）收益最大。
- **RL 加速：** MTP token 级并行度替代 batch 级并行度，让 on-policy 小 batch RL 训练更实用；同时缓解长尾 straggler 导致的 GPU 闲置。

### 4. MOPD 后训练范式：三步走

| 阶段 | 内容 | 目标 |
|------|------|------|
| Stage 1: SFT | 百万级高质量指令数据（通用对话、推理、编码、agent 任务） | 激活基座模型能力，对齐格式 |
| Stage 2: 领域专业化 RL/SFT | 分别训练 agentic（搜索、编码、工具使用）和非 agentic（数学、推理、安全对齐）教师模型 | 各领域达到峰值性能 |
| Stage 3: MOPD 蒸馏 | 学生在线采样 → 教师提供 token 级 KL 散度奖励 + 结果奖励模型（ORM）信号 | 整合专家能力，不牺牲任何一项 |

**关键洞察：** MOPD 使用 reverse KL 散度作为蒸馏损失，结合训练-推理重要性采样和 token 过滤，避免分布漂移。学生不仅能追上最强教师，在部分任务上甚至超越教师（AIME 2025：学生 94.1 vs 最佳教师 93.9）。

### 5. RL 基础设施

- **Rollout Routing Replay (R3)：** MoE 在 rollout 和 training 之间因数值精度产生路由不一致，R3 让训练使用 rollout 时相同的路由专家，消除不一致。
- **Data Scheduler：** 在细粒度序列级别调度而非 micro-batch 级别，结合 partial rollout（长轨迹分段）和 importance sampling，提升 GPU 利用率。
- **Toolbox & Tool Manager：** 基于 Ray 的集中式资源分配器，处理代码 agent 训练中 10,000+ 并发 pod 的容器化环境管理。

## 范式对比

### 与 DeepSeek-V3.2、Kimi-K2 的参数效率对比

|------|:-------------:|:-------------:|:-------:|
| 总参数 | **309B** | 671B | 1043B |
| 激活参数 | **15B** | 37B | 32B |
| 参数比 | **1×** | ~2.2× | ~3.4× |
| 注意力机制 | SWA+GA 混合 (5:1) | 全注意力(MLA) | 全注意力 |
| KV-cache效率 | **~6× 降低** | ~2×（MLA降维） | 基线 |
| SWE-Bench Verified | **73.4%** | ~同级别 | ~同级别 |
| SWE-Bench Multilingual | **71.7%** | - | - |
| 后训练范式 | MOPD（多教师在线蒸馏） | 传统 RL | RL |
| 投机解码 | MTP 原生（2.6×加速） | 独立 draft model | 独立 draft model |
| 开源 | ✅ 权重+3层MTP | ✅ | ✅ |

**核心洞察：**
- MiMo-V2-Flash 用 **15B 激活参数** 达到 DeepSeek-V3.2（37B）和 Kimi-K2（32B）同级别甚至领先的代码 Agent 能力，每激活参数效率高出 2-3 倍。
- SWA 窗口 128 的激进选择是双刃剑：长上下文检索略低于全注意力模型，但在需要噪声鲁棒性的推理任务（GSM-Infinite）上反而更强。
- MOPD 的核心贡献不是蒸馏了一个更强的模型，而是**让一个模型同时拥有多种"面孔"而不冲突**——这是传统 RL 和多阶段训练难以做到的。

## 可复用的工程经验

### 1. 混合注意力设计原则

- **窗口越小不一定越差。** W=128 优于 W=512 的核心原因是强制分工——小窗口使得 SWA 只能看局部，GA 必须承担全局，避免了职责模糊导致的次优解。
- **Attention Sink Bias 是混合注意力的必选项。** 没有 sink bias 的混合 SWA 在多项任务上退化；加上后甚至超越全 GA。这应该是所有混合注意力架构的标配。
- **RoPE base 需要差异化。** SWA 用低 base frequency（10,000）适合局部位置编码，GA 用高 base（640,000 → 5,000,000 扩展后）处理长距离依赖。

### 2. MTP 不仅是训练目标，更是推理加速器

- MTP 的 draft model 设计原则：**用 dense FFN + SWA 代替 MoE + GA**，参数降到最低（0.33B/层），不会成为新瓶颈。
- MTP 加速对 RL 训练的价值甚至大于推理——它让 on-policy 小 batch 训练变得经济，解决了 RL rollout 中的长尾 straggler 问题。
- 接受长度与交叉熵的 R²=0.995 关系说明：**MTP 在确定性强的任务（代码生成）收益最大，在开放生成任务（MMLU-Pro）收益有限。**

### 3. MOPD 的实践要点

- **在线策略蒸馏 > 离线数据蒸馏。** 学生从自己的分布采样而不是从教师的静态数据学习，避免了 exposure bias。
- **KL 散度奖励 + 结果奖励（ORM）双信号** 比单一信号更稳定。MOPD 贡献 token 级细粒度指导，ORM 提供最终结果的明确信号。
- **num-zeros 指标是 MoE SFT 训练的稳定性晴雨表。** 上升 → 负载不均衡，下降 → 过拟合。维持 num-zeros 稳定的关键是 expert bias update rate 和 AdamW ε 的配合。
- **MoE 路由一致性** 在 RL 中至关重要。R3（Rollout Routing Replay）解决数值精度导致的路由不一致，这是 MoE+RL 组合的一个隐蔽陷阱。

### 4. Agentic RL 训练的基础设施

- **代码 agent 训练需要大规模容器化环境。** 作者构建了自动环境搭建流水线（8 种语言，70% 成功率），Kubernetes 集群运行 10,000+ 并发 pod。
- **轻量 agent scaffold：** 仅暴露三个原子工具（bash, str_replace, finish），不做预定义工作流，让 RL 自行发现最佳实践——"少即是多"的 agent 设计哲学。
- **代码 agentic RL 的迁移效果显著。** 在代码任务上做 RL 训练的模型，在数学、编码和通用推理上都有提升——agent 训练培养的是 **可迁移的问题求解能力**。

### 5. 预训练数据策略

- 三个阶段的 progressive curriculum：通用（0-22T）→ 代码+合成推理（22-23T）→ 长上下文扩展（23-27T）。
- 刻意加强长距离依赖数据（长文档、repository-level 代码、PR/issue/commit history）。
- SWE-Bench 上的 Agentless 方法（few-shot）说明：代码 agent 基座模型的能力可以通过训练数据配比得到本质提升，不依赖复杂的 agent 框架。
