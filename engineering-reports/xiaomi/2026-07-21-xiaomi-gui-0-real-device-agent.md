# Xiaomi-GUI-0 — 真实设备驱动的端到端移动 GUI 智能体

**发布日期：** 2026年6月
**来源：** [arXiv:2606.31410](https://arxiv.org/abs/2606.31410)
**工程范式：** 错误驱动数据飞轮 + 渐进式三阶段强化学习——用真实设备上的错误分布替代模拟器中的成功轨迹来训练 GUI 智能体

## 设计哲学

移动 GUI 智能体的核心矛盾是：`模拟器和 benchmark 上的高分数不等于真实手机上的可用性`。真实应用环境中的账号状态、权限对话、支付认证、风控机制不断地重塑执行过程中的状态分布。

Xiaomi-GUI-0 的核心选择是**用真实设备定义训练和评估的基准分布**，彻底放弃以模拟器为主的传统路径：

- **真实设备主导的混合基础设施**：物理手机/平板为主要执行环境，sandbox 提供辅助支持。覆盖近 10 个主流品牌，含智能手机、平板、车载座舱。
- **错误驱动数据飞轮**：传统 flywheel 追求数据规模扩大，这里的目标是围绕**模型的真实错误分布**构建矫正信号。失败轨迹 → 错误定位 → 纠正动作 → 恢复示范，形成闭环。
- **放弃"一次训练终身使用"**：采用 SFT → Step RL → Agentic RL 三阶段渐进式训练，每阶段从上一阶段的策略出发，逐步从密集反馈过渡到稀疏反馈。
- **结构化 CoT 而非自由文本推理**：每个步骤强制输出五标签推理模式（Observation/Reflection/Plan/Decision/Memory），而不是自由形式的 Chain-of-Thought，确保每步语义可观测、可审计。

## 关键架构决策

### 混合基础设施（真实设备 + Sandbox）

系统架构分为三层：

1. **资源层**：数百台物理手机 + 数十台物理平板 + 数百个 sandbox 实例。物理设备覆盖前 100 个高流量商用应用，平板/座舱覆盖 20 个代表性应用。
2. **调度层**：采用 Device-Pull 调度方案（非 push），空闲设备根据当前 readiness 从队列拉任务。适应物理设备频繁的离线/重新登录/风控/冷却状态变化。
3. **执行与采集层**：标准的 observe-decide-act 循环，支持低延迟浏览器控制通道用于人工维护。

### 三阶段训练管线

#### 阶段一：SFT（监督微调）

- 训练数据：1.2M GUI step-level samples (~120K 轨迹) + 4.4M grounding samples
- 4 类数据源：高频任务数据 + 高泛化数据 + Agent 能力增强数据 + 纠错数据
- 训练配置：1 epoch, batch size 256, sequence length 8192, AdamW, lr=1e-5, cosine decay, 10% warmup

**高频任务数据**：针对头部功能的精确标注，覆盖 14 种异常状态（登录过期、验证码、支付认证、权限弹窗等）。异常状态被区分为"需要人工参与"（如验证码→模型停止执行）和"可安全跳过"（如广告→关闭）。

**高泛化数据**：通过五级功能树 + 行为桶（Behavior Buckets）系统化地合成长尾意图查询：
- 行为桶描述用户意图，功能树描述应用功能
- 双轴采样：行为桶主采样保持自然，功能树辅助采样保证长尾覆盖
- 查询经过 LLM 评判（真实性/可完成性/复杂度）→ 自然语言润色 → 功能点回溯标记

**Agent 能力增强数据**：每个轨迹被规范化为五标签结构 CoT——强制每步输出 Observation/Reflection/Plan/Decision/Memory，采用双向一致性约束（前向可推导性 + 标签一致性）防止 LLM 合成推理中的"事后合理化"。

#### 阶段二：Step-level RL（步骤级强化学习）

- 使用 GSPO（Group Sequence Policy Optimization）目标
- Cascade reward：四级级联奖励（规则解析→动作有效性→推理结构→语义一致性），低级失败提前退出
- 训练数据：~0.4M step-level samples (~40K 轨迹)
- 配置：16 responses/prompt, constant lr=1e-6, asymmetric clip (3e-4, 4e-4), batch size 128
- 异步 SGLang rollout

步骤级 RL 专门针对**局部错误**（无效动作、不完整 CoT、推理与动作不一致），这些错误不需要完整轨迹的稀疏信号就能纠正。

#### 阶段三：Agentic RL（智能体级强化学习）

- 在交互式环境中（数百个并行 emulator + 物理设备集群）在线训练
- 使用 GSPO 目标，但以 turn 为单位进行训练（历史窗口固定长度，保持训练序列短）
- 每步奖励从完整轨迹的 return 中派生 group-relative advantage
- 渐进课程采样：维护每个任务的平滑成功率估计，逐步从易任务转向难任务
- 配置：16 responses/prompt, constant lr=1e-6, batch size 32
- 最大 prompt length 8192

智能体级 RL 专门针对**全局行为**（长时间跨页面的状态追踪、跨应用一致性、错误恢复、最终任务完成）。

### 错误驱动数据飞轮

这是最核心的数据工程创新：

**互动标注**：回放失败轨迹 → 定位 first-key-error（第一个关键错误，而非所有错误） → 提供纠正确动作 + 错误原因。GUI 失败通常会级联，早期的错误 tap 会改变后续所有状态分布，所以大部分后续错误都是衍生性的。只标注 first-key-error 既能降低成本又能保持级联信息。

**教师模型评分与接管**：学生模型在集群上执行时，教师模型每步打分（基于截图、历史、动作）。连续低于阈值 → 教师暂时接管（有限步数）→ 从错误状态恢复回正确路径 → 控制权返回学生。整个过程被存档为完整的"偏差→诊断→恢复"片段，提供错误状态中如何矫正的训练信号。

这与传统的 trajectory selection flywheel（保留成功、丢弃失败）完全不同：它不是被动筛选，而是主动围绕模型的当前错误分布生产矫正数据。随着模型改进，容易的错误消失，飞轮自动聚焦于剩余难分类别。

### 评估：RealMobile Benchmark

RealMobile 是与 Xiaomi-GUI-0 配套发布的真实设备基准测试：
- 100 个任务 × 14 个应用
- 57% 为跨应用任务（覆盖 2-4+ 个应用）
- 细粒度子目标计分（非二值成功/失败）
- 物理设备上执行（真机+实网+真实账号）
- 应用包括抖音、小红书、微博、淘宝、高德等头部应用

## 关键结果

| Benchmark | 得分 |
|-----------|------|
| RealMobile（真机） | **72.0%** |
| AndroidWorld（模拟） | **78.9%** |

论文未在 AndroidWorld 上与其他方法做直接对比，因为 AndroidWorld 的评估环境（emulator-based）与 RealMobile 有所不同。核心对比是在真实设备和模拟环境之间的分数差距——传统的只依赖模拟器的方法会产生"benchmark illusion"（基准幻觉），在真实设备上表现远低于模拟测试。

## 范式对比

### Xiaomi-GUI-0 vs UI-TARS-2 / Mobile-Agent-v3.5

| 维度 | Xiaomi-GUI-0 | UI-TARS-2 / Mobile-Agent-v3.5 |
|------|-------------|------------------------------|
| 训练环境 | 物理设备主导 + sandbox 辅助 | 主要基于 emulator/simulator |
| 训练数据 | 真实应用异常状态全覆盖 | 成功轨迹为主 |
| RL 设计 | 三阶段渐进（SFT→Step RL→Agentic RL） | 通常单阶段 RL |
| 数据飞轮 | 错误驱动（围绕模型错误分布生产矫正数据） | 规模驱动（更多数据→更好模型） |
| 推理格式 | 结构化 CoT（五标签强制模板） | 自由文本推理 |
| 真实设备评估 | ✅ RealMobile benchmark（100 任务，14 应用） | 通常仅在模拟 benchmark 上报告 |

Xiaomi-GUI-0 的最大差异化在于**工程系统性**：不是单一技术突破，而是把"真实设备"这个原则贯彻到了基础设施、数据采集、训练管线、评估体系各个环节。

## 可复用的工程经验

1. **First-key-error 标注策略**：在级联失败的 GUI 任务中，只标注第一个关键错误。这节省了标注成本并保留了重要的因果拓扑信息。这适用于任何多步决策系统的故障分析。
2. **错误驱动飞轮 > 数据规模飞轮**：当模型已经有一定的基线能力时，围绕**模型当前在真实环境中的错误分布**生产矫正数据的收益，远大于继续增多"正确轨迹"的数量。这是一个值得在其他强化学习场景中复用的方法论。
3. **结构化 CoT 优于自由文本推理**：在可观测性和训练信号质量之间找到了一个实用的折中点——不禁止推理，但约束其格式。五标签模式使每步推理可分离审计，也更容易进行自动化奖励判断。
4. **Task-level 训练但 turn-level 更新**：Agentic RL 中用完整轨迹的 return 计算 advantage，但用固定历史窗口的 turn 级序列进行训练——这保持了梯度更新的效率，同时使优化目标对准全局行为。这个平衡对任何长序列 RL 场景都有参考价值。
5. **Device-Pull 调度优于 Push**：在物理设备集群上，设备状态随时变化（离线/风控/冷却），让设备主动拉取与其当前状态匹配的任务，可显著降低调度失败率。这是工程系统中的"防守"思维——不假设组件永远可用，而是设计系统适应组件不可用。
