# Xiaomi-Robotics-1 — 10万小时真实轨迹驱动的视觉-语言-行动基础模型

**发布日期：** 2026年7月
**来源：** [arXiv:2607.15330](https://arxiv.org/abs/2607.15330) · [Project Page](https://robotics.xiaomi.com/xiaomi-robotics-1.html)
**工程范式：** 数据规模驱动的机器人预训练——用 UMI 便携采集设备突破机器人数据瓶颈，100K+ 小时真实操作轨迹 + 两阶段训练（预训练+后训练）

## 设计哲学

机器人领域的规模化不同于大语言模型：真实机器人的遥操作数据采集成本极高、速度慢、受硬件约束，且易集中在狭窄的任务和环境范围。Xiaomi-Robotics-1 的核心矛盾是：`机器人需要大规模多样化数据才能泛化，但传统遥操作无法规模化采集`。

Xiaomi 的选择：

- **用 UMI 手持采集替代传统遥操作**：Universal Manipulation Interface (UMI) 是一种便携式采集设备，无需物理机器人本体即可在世界各地采集操作数据。这大大降低了数据采集的门槛。
- **自动标注替代人工标注**：开发了可扩展的自动标注管线，用 Qwen3.5-27B 对固定长度的轨迹片段进行场景状态转换描述，替代传统的人工语义分割和语言标注。整个 100K+ 小时的数据集在约两周内完成标注。
- **两阶段训练分离"能力"和"对齐"**：预训练阶段学泛化操作能力（用 UMI 数据），后训练阶段对齐到具体机器人本体和指令形式（用交叉本体数据）。
- **Mixture-of-Transformers (MoT)** 架构：预训练的 VLM（Qwen3-VL）负责视觉-语言编码，Diffusion Transformer (DiT) 负责动作生成，两者通过 KV cache 连接但动作相关 token 被排除在 DiT 的注意力计算之外，防止 DiT 走捷径直接复制 VLM 的输出。

## 关键架构决策

### 模型架构：Mixture-of-Transformers (MoT)

Xiaomi-Robotics-1 采用 VLM + DiT 双组件架构：

- **VLM**（预训练）：Qwen3-VL（三档规模 2.1B/4.4B/8.8B）负责处理观察图像和语言指令，并额外通过 Choice Policies 预测动作候选（K 个候选，winner-takes-all 范式）。
- **DiT**（Diffusion Transformer）：与 VLM 层数相同但隐藏尺寸更小，负责通过 flow-matching 生成 action chunk。接收 VLM 的 KV cache 和机器人本体状态作为条件。
- **动作相关 token 排除**：VLM 预测的动作 token 被排除在 DiT 的注意力计算之外，防止 DiT 直接复制而不进行有效的视觉-文本 grounding。

| 模型变体 | 总参数 | VLM 参数 | DiT 参数 |
|----------|-------|----------|---------|
| Xiaomi-Robotics-1-2B | 2.6B | 2.1B | 470M |
| Xiaomi-Robotics-1-5B | 5.1B | 4.4B | 604M |
| Xiaomi-Robotics-1-10B | 10.5B | 8.8B | 1.5B |

### 预训练 (Pre-training)

**数据**：
- 100K+ 小时真实世界操作轨迹
- 使用 UMI 手持采集设备 + 第一人称摄像头
- 覆盖家庭、商业场所、工业设施、办公室、户外等多场景
- 自动标注：Qwen3.5-27B 对固定长度轨迹片段标注"场景状态转换"描述
- 标注管线：生产-消费者架构，CPU 线程切片段 + 客户端线程发标注请求，两周内完成全量标注

**训练目标**：
- DiT 的 flow-matching loss + VLM choice policy 的回归 loss + VLM 的 next-token-prediction loss（λ=0.1）
- 视觉-语言数据与 UMI 轨迹以 1:9 比例采样
- 效率优化：同一 batch 内打包所有 VL token 到一个序列；每个 VLM 前向传播服务 4 个 flow-matching timestep

### 后训练 (Post-training)

**双重目标**：
1. 将预训练阶段学到的 UMI 夹爪操作能力迁移到机器人本体
2. 将语言条件从场景状态转换描述转换为人类给机器人的祈使指令

**数据**：
- 约 10K 小时交叉本体轨迹
  - 7,200+ 小时内部机器人数据（移动操作平台 + 双臂机器人）
  - 1,000+ 小时人工标注 UMI 数据（含时间分割 + 语言指令，用 Qwen3.5 标注）
  - 开源数据（Bridge V2, RT-1, DROID）
- 统一夹爪动作空间（relative delta end-effector poses），使不同硬件的动作表示一致
- 缺失动作维度在 loss 计算中被 mask

**训练**：使用与预训练相同的目标函数。数据采样比例：VL:开源机器人:UMI标注:内部机器人 = 0.5:0.5:0.5:8.5。

### 训练细节

- **Pre-train scaling 实验**：5B 模型在 12.5%/25%/50%/100% 约 20K 小时数据上训练。12.5% 和 25% 出现过拟合（loss 先降后升），50% 和 100% 呈现单调下降。
- **Model scaling 实验**：2B/5B/10B 三种规模在相同 20K 数据上训练。模型规模增大带来稳定提升，但幅度小于数据规模提升——说明在当前数据量下，模型容量可能已经足够，**数据量才是泛化的主要瓶颈**。

### Xiaomi-Robotics-1 vs Xiaomi-Robotics-0

Xiaomi-Robotics-1 是 Xiaomi-Robotics-0 (arXiv 2602.12684, Feb 2026) 的规模升级版：
- 预训练数据从约 20K 小时 → 100K+ 小时
- 后训练数据从有限 → 7.2K 小时内部 + 1K+ 标注 UMI + 开源
- 模型规模从单一 → 三档变体（2B/5B/10B）
- RoboCasa365 从无到 57.4% SOTA
- 新增真实机器人零样本评估

## 可复用的工程经验

1. **UMI 设备是突破机器人数据瓶颈的有效方案**——无需机器人本体的手持采集可大幅提升数据多样性和规模。100K+ 小时的数据在两周内自动标注完成，证明了整个管线的可操作性。
2. **数据规模 > 模型规模**：在 RoboCasa365 上，更大数据始终带来更好性能，而模型规模提升的效果相对温和。对于机器人基础模型，**数据采集和标注可能是比模型架构创新更值得投入的方向**。
3. **两阶段训练是有效的分离策略**：预训练学习操作能力（使用成本低的 UMI 数据），后训练对齐到具体本体和指令（使用高质量但昂贵的机器人数据）。这种分离使每种数据各尽其用。
4. **动作相关 token 排除**（不让 DiT 注意力关注 VLM 的动作预测 token）防止了捷径学习，这一设计决策被形式化为明确的系统性选择而非偶然发现。
