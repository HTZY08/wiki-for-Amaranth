# Kimi K2.5 — 多模态 Agent 智能与 Agent Swarm 并行编排

**发布日期：** 2026年2月（arXiv 2602.02276）
**来源：** https://arxiv.org/abs/2602.02276
**工程范式：** 多模态 MoE + 自组织并行 Agent 编排

## 设计哲学

Kimi K2.5 的核心设计哲学是**多模态联合优化与并行 Agent 编排的统一**。它打破了两个常见的工程假设：(1) 视觉能力应当作为语言模型的后期附加功能；(2) Agent 系统应当依赖应用层编排而非模型自身的并行决策能力。

**核心约束：** Kimi K2.5 强调文本与视觉的联合优化，让两种模态互相增强而非独立处理。在 Agent 层面，核心约束是从"顺序执行的推理链"转向"并行分解的 Agent 集群"——即通过模型自身学到的并行化策略，将线性推理时间转化为并行处理，从而突破单 Agent 的延迟天花板。

## 关键架构决策

### 1. 基础架构：万亿参数 MoE

- **基座：** Kimi-K2-Base（1.04T 总参数，32B 激活参数）
- **架构：** Mixture-of-Experts (MoE)，384 个专家，每 token 激活 8 个（稀疏度 48）
- **注意力：** MLA（Multi-head Latent Attention）
- **激活函数：** SwiGLU
- **上下文长度：** 256K tokens（通过 YaRN 插值扩展）
- **视觉编码器：** MoonViT-3D（400M 参数，基于 SigLIP-SO-400M 初始化）

### 2. 多模态联合继续预训练（~15T tokens）

在 Kimi-K2-Base 基础上，使用约 15T 混合视觉+文本 tokens 进行继续预训练。关键发现颠覆了行业惯例：

- **早期融合优于后期融合：** 实验表明，给定固定的视觉-文本 token 预算，**低视觉比例的早期融合**效果优于在训练后期大量注入视觉数据的高比例策略。这与 GPT-4V、Qwen-VL 等常见的"视觉后期接入"做法相反。
- **MoonViT-3D：** 原生分辨率视觉编码器，采用 NaViT patch packing 策略（变分辨率输入）。视频方面引入轻量 3D ViT 压缩：每 4 帧分组，通过共享编码器处理后进行时间平均池化，实现 4 倍时间压缩。图像和视频编码器完全权重共享。

### 3. Zero-Vision SFT（零视觉监督微调）

一个反直觉的创新：**仅使用文本 SFT 数据即可激活视觉推理和工具使用能力。**

- 核心观察：高质量文本 SFT 数据丰富多样，而人工标注的视觉轨迹数据质量参差不齐且覆盖有限。
- 实现方式：所有图像操作通过 IPython 编程操作代理（如像素级二值化、计数、OCR），本质上是对传统视觉工具使用的泛化。
- 实验结果：添加人工设计的视觉轨迹反而损害泛化能力。Zero-vision SFT 即可充分激活视觉能力，这是联合预训练阶段已经建立的强视觉-文本对齐的自然结果。

### 4. 联合多模态强化学习（Joint Text-Vision RL）

- **基于结果的视觉 RL：** 涵盖视觉定位与计数、图表与文档理解、视觉关键 STEM 问题三大领域。使用 F1-based reward（IoU soft matching）、归一化编辑距离、绝对差值等任务特定奖励函数。
- **视觉 RL 提升文本性能（跨模态迁移）：**
  - MMLU-Pro: 84.7% → 86.4%（+1.7）
  - GPQA-Diamond: 84.3% → 86.4%（+2.1）
  - LongBench v2: 56.7% → 58.9%（+2.2）
- **联合多模态 RL 范式：** 不按输入模态划分领域，而是按能力维度（知识、推理、编码、Agent 等）组织 RL 训练。Generative Reward Model (GRM) 跨模态优化。

### 5. Agent Swarm 并行编排（核心创新）

**PARL（Parallel-Agent Reinforcement Learning）范式**：训练一个可学习的 orchestrator，动态创建和调度专门的 frozen sub-agents。

- **解耦架构：** Orchestrator 可训练，sub-agents 冻结自中间策略检查点。避免端到端联合优化中的信用分配模糊和训练不稳定两大挑战。
- **奖励函数三组件：**
  - `r_parallel`（实例化奖励）：防止"序列坍缩"（orchestrator 默认退化为单 Agent 执行）
  - `r_finish`（完成率）：防止"虚假并行"（大量 spawn 子任务但无实际完成）
  - `r_perf`（任务级结果）：最终答案质量
  - `λ₁` 和 `λ₂` 在训练过程中渐退至零
- **关键路径约束（Critical Steps）：** 以最长并行分支的完成时间而非总步骤数作为延迟度量，激励均衡的任务分解而非单纯的并发最大化。
- **效率提升：** Agent Swarm 将推理延迟降低 **3×–4.5×**。在 WideSearch 上，Item-F1 从单 Agent 的 72.8% 提升至 79.0%（+6.3%）。
- **动态子任务创建：** Sub-agents 是运行时动态创建而非预先定义的，orchestrator 通过 PARL 学习自适应策略。可同时运行最多 100 个 sub-agents。

### 6. 训练基础设施：解耦编码器过程（DEP）

- 典型的多模态训练中，视觉编码器与文本 embedding 处于 PP pipeline 的同一 stage，导致计算负载和内存使用剧烈波动。
- DEP 将训练分为三个阶段：(1) 平衡视觉前向（所有 GPU 均分视觉数据），丢弃中间激活；(2) 主干网络训练（复用纯文本优化策略）；(3) 视觉重计算与反向传播。
- 实现 90% 的多模态训练效率（相对于纯文本训练）。

### 7. Token 高效 RL：Toggle 算法

- **问题：** 长思维链在提升推理质量的同时产生大量冗余 token。固定预算训练导致无法泛化到更高计算规模。
- **方案：** 交替两阶段优化——Phase0（预算受限）+ Phase1（标准扩展），每 `m` 轮切换一次。
- **效果：** 输出 token 减少 25–30%，性能几乎无损。冗余模式（重复验证、机械计算）显著减少。

### 8. 开源 Checkpoint 发布

- 模型权重以 Modified MIT License 发布在 HuggingFace（moonshotai/Kimi-K2.5）
- 支持 vLLM、SGLang、KTransformers 推理引擎
- 原生 INT4 量化支持

### 关键差异化分析

1. **模态集成深度：** K2.5 是极少数在整个训练管线（预训练 → SFT → RL）中坚持联合文本-视觉优化的开源模型，而非"文本模型+视觉 adapter"的后期拼装方案。
2. **Agent 编排的原生化：** 其他模型的并行 Agent 能力来自应用层框架（Claude Code Agent Teams、Codex 多线程），K2.5 将并行调度直接训练进模型权重，这是本质区别。
3. **跨模态迁移：** 视觉 RL 提升文本性能的发现（MMLU-Pro +1.7, GPQA-Diamond +2.1）在同期模型报告中未见于其他团队。
4. **Token 效率：** Toggle 算法在同类推理模型中属于首创交替预算机制，DeepSeek 和 Qwen 的类似报告尚未展示同等语义保留下的压缩率。

## 可复用的工程经验

### 1. 视觉接入时机：早期融合 + 低比例 > 后期冲刺

反直觉但实验明确的结论：给定固定视觉-文本 token 预算，早期以较低比例注入视觉数据优于后期高比例冲刺。这意味着多模态预训练应尽早开始跨模态互动，而非等到文本能力成熟后再"补课"。

### 2. Zero-Vision SFT 的可行性

联合预训练的强大对齐效果使得无视觉数据的文本 SFT 就能激活视觉推理和工具使用。这大幅简化了 SFT 数据管线的复杂度——无需手动标注大量视觉推理轨迹，降低了多模态后训练的数据门槛。

### 3. 跨模态 RL 的协同效应

视觉 RL 不会损害文本性能，反而提升文本推理能力。这意味着多模态 RL 不是零和博弈。**建议**在 RL 阶段始终保留一定比例的视觉任务，即使最终目标是纯文本推理。

### 4. PARL 奖励设计的平衡艺术

- **序列坍缩（Serial Collapse）** 是并行 Agent RL 的首要陷阱——模型天然倾向于保守的顺序执行。
- 解决策略是**两阶段奖励退火**：先用辅助奖励（实例化奖励 + 完成率奖励）引导并行探索，再渐退至纯任务奖励。
- 冻结 sub-agents 是关键工程决策：避免了多 Agent 联合训练的信用分配模糊和训练不稳定。

### 5. 关键路径作为延迟度量

用 `CriticalSteps = Σ(S_main + max_i S_sub_i)` 而非总步骤数来度量并行效率。这个简单的度量变化直接约束了**最长路径**而非**总工作量**，从根本上激励均衡的并行分解。

### 6. DEP 解耦编码器过程

多模态训练中视觉编码器的负载不均是普遍痛点。DEP 通过"前向 → 丢弃 → 重计算"三步策略解耦了视觉编码器和主干网络的并行策略，实现了 90% 的纯文本训练效率。这个设计模式可被任何 PP-based 多模态训练管线复用。

### 7. Toggle 交替预算机制

在"长的好"和"快的好"之间找到平衡——交替进行预算受限训练和标准扩展训练。关键细节：预算受限阶段**条件性**执行（仅当准确率超过阈值时），避免过早的效率-质量妥协。

### 8. 合成提示驱动并行策略学习

通过构造"顺序执行几乎不可能完成"的合成任务（如大规模文件下载、多源信息平行检索），自然地将并行分解策略塑造成 by-default 行为。提示本身不包含"请并行执行"的指令——环境压力驱动策略涌现。
